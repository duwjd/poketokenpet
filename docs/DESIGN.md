# 게임 기획

PokeTokenPet이 **무엇을 하는 게임인지**, 그리고 각 숫자가 왜 그 값인지를 적은 문서입니다.
구현 방법은 [INTERNALS.md](INTERNALS.md), 개발·빌드·배포 방법은
[DEVELOPMENT.md](DEVELOPMENT.md)에 있습니다.

## 핵심 루프

한 문장으로: **AI 코딩으로 태운 토큰이 곧 경험치입니다.**

```
Claude Code 사용  →  토큰 누적  →  알 부화(Lv.1)  →  레벨업·진화  →  Lv.100
                                                                    ↓
                                              도감 등록 + 새 알  ←  졸업
```

앱은 `~/.claude/projects/**/*.jsonl`을 20초마다 읽어 토큰을 셉니다. 그 숫자가
부화 임계값을 넘으면 알이 깨지고(Lv.1), 계속 쌓이면 레벨이 오르며 원작의 진화 조건대로
진화하고, **Lv.100이 되면 졸업**해서 도감에 남고 새 알이 옵니다. 자세한 건
[레벨과 진화](#레벨과-진화)에 있습니다.

여기에 네 개의 축이 얹힙니다:

| 축 | 하는 일 | 절 |
|---|---|---|
| **자동사냥** | 코딩을 안 하는 동안에도 조금씩 자람 | [자동사냥과 기술머신](#자동사냥과-기술머신) |
| **수집** | 졸업시킨 종이 도감에 쌓임 | [도감](#도감) · [전설과 환상](#전설과-환상--조건을-갖춰야-만난다) |
| **경제** | 토큰으로 물건을 사서 성장을 조절 | [상점과 가방](#상점과-가방--프렌들리숍-카운터) |
| **목표** | 무엇을 더 해볼지 제시 | [업적](#업적) |

**설계의 중심 제약은 하나입니다** — 사냥이든 아이템이든, *실제로 코딩해서 번 토큰*을
대체하면 안 됩니다. 앱의 전제가 "일한 만큼 자란다"이기 때문입니다. 아래 여러 절에서
반복해서 나오는 상한과 배수는 전부 이 한 줄을 지키기 위한 장치입니다.

## 원조 앱과 대조

[PokeTokenBar](https://github.com/chattymin/PokeTokenBar) (MIT, macOS 전용)가 같은 데이터를
읽습니다. 설치되어 있다면 `~/Library/Logs/PokeTokenBar.log`에 60초마다 정답이 찍히고,
`npm run validate`가 자동으로 대조합니다.

```
── 3. 원조 앱과 대조 ───────────────────────────
  원조 (2026-08-21)  : 294,817,211
  내 파서 (오늘)   : 295,995,622
  차이             : 1,178,411 (0.4%)   ✓ 일치
```

## 이 앱이 원조와 다른 점

- **Windows에서 돌아갑니다** (원조는 macOS 전용)
- **`entrypoint`별 분리** — VS Code / 터미널 / 데스크톱 사용량을 나눠서 봅니다.
  이 필드가 트랜스크립트 각 줄에 있어서 **과거 데이터까지 소급**됩니다

`entrypoint`는 **표면(surface)** 이지 계정 신원이 아닙니다. "VS Code=계정 A,
터미널=계정 B"처럼 쓰는 경우에만 계정의 대리 지표로 성립합니다. 진짜 계정 귀속은
트랜스크립트에 계정 필드가 없어서 관측 시점에 `~/.claude.json`을 스냅샷해야 하고,
**설치 이후분만** 가능합니다.

## 게임 밸런스

- **설치 기준선**: 첫 실행 시점의 누적 토큰은 기록이지 진행이 아닙니다. 이게 없으면
  기존 기록 때문에 첫 실행에 곧바로 최종 진화해 버립니다. 다만 기준선을 붙박이로 두면
  안 됩니다 — [함정 4번](INTERNALS.md#토큰을-세는-방법--함정-다섯-개) 참고
- **부화 임계값 자동 조정**: 최근 7일(활동일 기준) 평균의 15%.
  헤비 유저든 라이트 유저든 1~2시간 사용에 부화하도록 맞춰집니다
- **희귀도**: PokeAPI `capture_rate` 기준 (낮을수록 희귀). 희귀할수록 천천히 자랍니다
- **샤이니**: 1/512. 부화 시 한 번 굴리고 고정됩니다
- **집계 모드**: 기본은 캐시 읽기를 포함한 `활동량`. 캐시가 전체의 ~95%라
  `?mode=billable`로 바꾸면 성장이 훨씬 느려집니다

## 레벨과 진화

**토큰 게이지가 곧 레벨입니다.** 부화가 Lv.1, 졸업이 Lv.100이고, 그 사이 99레벨이 한 마리를
키우는 전체 토큰을 똑같이 나눠 가집니다(`levelAt`). 전체 양은 레벨이 생기기 전과 **같습니다** —
3단 진화 36배, 2단 24배, 1단 20배(× 희귀도 배수, 단위는 부화 임계값). 한 마리 키우는 데 걸리는
시간은 그대로이고, 바뀐 건 **어디서 진화하느냐**입니다. 단계가 끝날 때가 아니라 원작의
진화 레벨에서 진화합니다 — 파이리는 Lv.16에 리자드, Lv.36에 리자몽.

한 라인 안에서 길이가 다른 분기(과사삭벌레 → 애프룡 / 과미르 → 과미드라)는 가장 긴 경로로
전체 양을 잽니다. 분기가 바뀌어도 레벨이 줄지 않게 하려는 것입니다.

진행바는 **다음 레벨까지**를 보여주고, 옆에 졸업까지의 전체 비율이 붙습니다. 상태 화면에는
레벨·친밀도와 함께 **다음 진화에 무엇이 필요한지**("Lv.36", "천둥의돌", "친밀도 160 · 밤")가
나옵니다. 이상한사탕은 원작대로 **레벨 1**을 올립니다(알일 때는 부화까지 25%). 변함없는돌을
끼우면 레벨은 계속 오르지만 진화도 졸업도 하지 않습니다.

### 원작 진화 조건

`scripts/gen-species.ts`가 PokeAPI의 진화 조건을 전부 구워 `EVOLUTIONS`에 넣고,
`server/evolution.ts`가 레벨업 때와 도구를 쓸 때 확인합니다. 484단계 중 327단계는 레벨만,
82단계는 도구입니다. 조건이 여러 개면 전부 맞아야 하고, 방법이 여러 개면 하나만 맞으면 됩니다.

**분기는 조건이 정합니다.** 부화 때 한 갈래를 뽑아 두긴 하지만, 이브이는 건네받은 돌대로,
낮에 친밀도가 차면 에브이, 밤이면 블래키가 됩니다. 뽑은 갈래가 정하는 건 앱이 따로 알 수 없는
것뿐입니다 — 성별(킬리아의 엘레이드, 눈꼬마의 눈여아, 도롱충이), 성격값(개무소), 능력치
균형(배루키). 코스모움처럼 버전 한정이라 조건이 똑같은 두 갈래도 뽑은 쪽을 따릅니다.

앱에 없는 장치는 가장 가까운 것으로 옮겼습니다.

| 원작 조건 | 이 앱 |
|---|---|
| 레벨 | 그 레벨에 도달하는 레벨업 |
| 돌·사과·찻잔 등 도구 사용 | 상점에서 사서 가방에서 사용. 진화가 일어날 때만 소모 |
| 통신교환 | **연결의끈**(레전드 아르세우스의 원작 도구) 사용 |
| 도구를 지닌 통신교환·레벨업(금속코트, 예리한이빨 등) | 그 도구를 가방에서 사용(레전드 아르세우스 방식). 시간 조건은 그대로 |
| 친밀도 | 종의 기본 친밀도 + 레벨업마다 5. 피츄(70)는 Lv.19에 160 |
| 낮 · 밤 · 저녁 | 장면과 같은 시간대(낮=새벽·낮, 밤, 저녁) |
| 보름달(다투곰) | 실제 달의 위상. 보름 전후 하루의 밤 |
| 특정 장소(자포코일·리피아·글레이시아 등) | 원작 8세대부터의 돌(천둥의돌·리프의돌·얼음의돌) |
| 파티에 특정 종·타입(타만타, 판짱) | 리그 파티 |
| 비 오는 필드(미끄네일) | 가장 최근 배틀에 비가 내렸음 |
| 3DS를 거꾸로(오케이징) | 파트너 탭의 "거꾸로 들기" 스위치. 다음 레벨업 때 소모 |
| 1000걸음(빠모트·그푸리·구르데) | 조우 한 번 = 100걸음 |
| 기술 20번 사용(성원숭·노라키·침바루) · 반동 294(배쓰나이) · 피해 49(데스마스) · 한 배틀 급소 3번(파오리) · 절각참 3마리(절각참) | 파트너의 배틀 기록(`Companion.deeds`) |
| 모으령의코인 999개 | 999개 묶음을 상점에서 사서 사용 |
| 멜탄 사탕 400개(포켓몬 GO) | 조우 400번 |
| 기술을 앎(에이팜 등) · 성별 · 개체값 | 기술은 그대로, 성별·개체값은 부화 때 뽑은 갈래 |
| 여러 곳 중 한 곳(우라오스의 탑) | 족자 사용 |

상점은 진화 도구 41종을 **전부 진열**합니다. 지금 파트너의 다음 진화에 쓸 수 있는 것이
맨 위에 "지금 쓸 수 있음" 표시와 함께 오고, 나머지는 그 아래에 있습니다. 설명에는 그 도구로
진화하는 포켓몬이 나옵니다("라이츄·쥬피썬더·자포코일 등 7종이 이걸로 진화합니다").

처음에는 쓸 수 있는 것만 진열했습니다. 41줄이 벽처럼 보일까 봐서였는데, 그러면 다음
파트너를 위해 **미리 사 둘 수가 없었습니다** — 원작에서도 돌은 쓸 포켓몬이 생기기 전에 사
두는 물건입니다. 그래서 전부 진열하되, 정렬과 표시로 지금 필요한 것을 먼저 보이게 했습니다.
상점 탭의 점은 여전히 **쓸 수 있는 것**만 셉니다. 41종을 다 세면 점이 늘 켜져 아무 뜻이
없어지기 때문입니다.

레벨이 생기기 전 저장은 첫 틱에 한 번의 레벨업으로 취급해서 쌓인 레벨만큼의 진화를 바로
확인합니다. 이미 진화한 파트너가 되돌아가는 일은 없습니다.

## 자동사냥과 기술머신

코딩을 안 하는 동안에도 펫이 야생 포켓몬과 알아서 싸웁니다. **5분에 한 번** 조우하고,
조우 보상은 **시간당 부화 임계값의 5%**에 맞춰 정규화돼 있습니다 — 단 **이긴 조우만** 받습니다.
앱이 꺼져 있던 시간도 **최대 8시간까지** 소급해서 정산하니 노트북을 닫고 퇴근해도 손해가
없습니다.

**사냥은 토큰을 대체하지 못합니다.** `huntTokens`에 상한이 있습니다:

```
상한 = max(부화 임계값 × 3, 번 토큰 × 0.25)
```

토큰을 쓰는 사람에게는 상한이 사냥보다 빨리 자라서 걸리지 않고, 켜두기만 한 기계에서는
상한에 붙어 멈춥니다. 이게 없으면 아무것도 안 하는 기계가 6일에 한 마리씩 졸업시켜
앱의 전제가 뒤집힙니다. **상한에 걸려도 조우와 기술머신 드롭은 계속됩니다.**

**상한은 설정으로 끌 수 있습니다.** 설정 탭의 "사냥 상한" 토글입니다. 기본값은 적용이고,
끄면 `huntCap`이 `Infinity`를 돌려주어 클램프가 사라집니다. 끄는 것이 **환불은 아닙니다** —
지급되지 않은 조우는 애초에 기록되지 않았고, 지금 와서 소급하려면 상한이 언제부터 물었는지를
추측해야 합니다. 여기서부터 안 자를 뿐입니다.

이걸 여는 이유는, 상한이 **누적이고 절대 줄지 않기** 때문입니다. 초반에 사냥을 많이 돌린
사람은 번 토큰이 자라기 전까지 영구히 붙어 있게 되는데, 그건 "켜두기만 한 기계를 막는다"는
원래 의도와 다른 결과입니다. 무엇을 막고 싶은지는 설계의 의견이지 안전 속성이 아니고,
그 판단은 쓰는 사람 몫입니다.

**그리고 상한에 닿으면 화면이 그렇게 말합니다.** `hunt()`가 `Math.min(room(), …)`으로 잘라
조우마다 `tokens: 0`을 기록하므로, 기록 탭이 "—"로 가득 차고 진행도 바가 멈춥니다 —
설계된 동작인데 아무 설명이 없으면 **버그로 읽힙니다.** 그래서 장면 캡션이 카운트다운 대신
"사냥 진행도가 상한에 닿았다"로 바뀌고(펫은 여전히 걷고 여전히 싸우므로 표지판은 그대로
남습니다), 자동사냥 절이 상한이 왜 안 자라는지를 한 줄로 설명합니다.

**파트너 탭의 숫자는 지금 파트너 것입니다.** 부화한 뒤로 이 아이가 사냥으로 번 진행도와 만난
포켓몬 수입니다 — `huntTokens`·`huntCount`는 졸업해도 초기화되지 않는 누적값이라 그대로 쓰면
"이 아이가 한 일"이 아니라 "이 계정이 한 일"이 됩니다. `bornAt`에서 뽑아낼 수도 없습니다.
그건 `lifetimeEarned + bonusTokens + huntTokens`가 **섞인 스칼라**라 사냥 몫만 되돌릴 수 없거든요.
그래서 부화 순간에 두 카운터를 `Companion`에 스냅숏합니다. `buildState`가 `hunt()`를
`advance()`보다 먼저 돌리므로 알을 깨뜨린 그 배치까지 이미 반영돼 있고, 갓 태어난 파트너는
정확히 0에서 시작합니다.

**단 '사냥 상한'만 누적입니다.** 상한은 "지금까지 사냥이 기여한 전부"를 "지금까지 번 전부"와
재는 값이라 한 마리 몫으로 쪼갤 수가 없습니다. 그래서 그 줄만 `사냥 상한 (누적)`이라고
이름표를 달고 누적 사용량/누적 상한을 쌍으로 보여줍니다 — 위 두 줄과 다른 축이라는 걸
라벨이 말하게 두는 편이, 세 줄이 같은 척하는 것보다 낫습니다.

이미 살아 있던 파트너는 **오늘부터 0에서 셉니다.** 마지막 부화 시점의 카운터를 기록해 둔 것이
없어서 소급할 방법이 없고, 없는 숫자를 지어내느니 지금부터 정직하게 세는 편이 낫습니다 —
`trainerWins`가 같은 이유로 같은 답을 골랐습니다.

알은 싸울 수 없고, 변함없는돌을 차고 있으면 쉽니다. 둘 다 팝오버가 이유를 적어줍니다.

기술머신 말고 **메가스톤**도 여기서 나옵니다 — 만난 야생 포켓몬이 메가진화할 수 있는 종일 때만,
낮은 확률로. 아래 [특별 진화](#특별-진화--메가진화--거다이맥스--합체) 참고.

### 레벨업 기술 — 배우고, 떠올리고

기술은 두 길로 배웁니다. **기술머신**은 사냥에서 주워 가방에서 쓰고(쓰면 사라집니다), **레벨업
기술**은 원작처럼 그 레벨이 되면 배웁니다. 레벨업 기술표는 종마다 **그 종이 나오는 가장 최신
본편**(스칼렛·바이올렛 → 소드·실드 → 브릴리언트다이아몬드·샤이닝펄 → 이전 세대) 하나에서
가져옵니다. 세대마다 배우는 레벨이 달라서, 모든 세대를 합치면 "가장 낮은 레벨"이라는 어느
게임에도 없는 표가 됩니다. 기술표는 기술머신 합집합과 이 레벨업 표의 합집합으로 739개입니다.

- **부화하면 Lv.1 기술**을 압니다(원작처럼 마지막 넷). 잉어킹처럼 Lv.1 기술이 전부 변화 기술이면
  배틀의 기본 공격이 대신합니다
- **레벨업 때 빈 칸이 있으면 바로 들어갑니다.** 넷이 다 차 있으면 물어볼 사람이 없으니 들어가지
  않고, 파트너 탭 **"떠올릴 수 있는 기술"**에 쌓입니다 — 원작의 기술 떠올리기처럼 **무료**로
  아무 때나 교체합니다. 진화 기술(레벨 0)은 진화하는 순간 배웁니다
- 지나온 종의 기술도 떠올릴 수 있습니다. 리자몽도 파이리 때 배운 불꽃세례를 기억합니다
- **도감의 종은 Lv.100**이므로 리그 파티는 그 종의 레벨업 기술 전부를 무료로 씁니다.
  기술머신 전용 기술만 가방에서 소모합니다
- **야생 포켓몬은 Lv.50까지의 레벨업 기술**로 싸웁니다. 원작의 야생이 그렇습니다. 레벨업으로
  칠 게 없는 종만 기술머신 풀로 돌아갑니다. 기술머신 드롭은 여전히 기술머신 풀에서만 나옵니다

**하나 지방 관장·사천왕 기술을 원래대로 채웠습니다.** 기술표가 기술머신뿐이던 시절 빠져 있던
12칸(섀도펀치, 모래뿌리기, 속이기, 깜짝베기 ×2, 업어후리기, 태권당수, 암해머, 점프킥, 바디퍼지,
노래하기, 더블촙)을 블랙·화이트(아이리스는 블랙2·화이트2) 첫 대전 기준으로 되돌렸습니다.
태권당수와 점프킥은 최신작에서 배우는 종이 없어서 이 두 칸을 위해 표에 남겨 둡니다
(`ROSTER_ONLY`).

레벨업 기술이 들어오면서 **부가 효과가 있는 기술 약 400개**가 늘었습니다. 씨뿌리기·하품·
멸망의노래·사슬묶기·배북·비축하기·희망사항·변신·스케치·길동무·원념·매직코트·와이드가드·
패스트가드·트릭가드·킹실드 계열·아쿠아링·뿌리박기·전자부유·문어굳히기·소금절이·시럽봄·
끈적끈적네트·치유소원·회생의기도·꼬리자르기 등 **전부 원작 규칙**을 따릅니다. 속이기·
만나자마자는 나온 첫 턴에만, 기습·질풍신뢰는 상대가 공격할 때만, 비장의무기는 다른 기술을
다 쓴 뒤에만, 다크홀은 다크라이만 성공합니다. 9세대 기술 중 PokeAPI에 효과가 비어 있는
75개는 원작 설명대로 `MOVE_PATCHES`에 적었습니다. 특성을 바꾸는 기술(위액·고민씨·심플빔·
동료만들기·역할·배껴그리기)과 플러스·마이너스 전용 기술은 [특성](#특성)을 따릅니다.

도구가 있어야 하는 바꿔치기, 동료가 있어야 하는 날따름·분노가루·아로마미스트, 나무열매가 있어야
하는 트림·볼가득넣기·다과회는 원작처럼 실패합니다.

### 특성

**모든 포켓몬이 특성을 하나 갖고, 배틀에서 원작대로 작동합니다.** 도감 카드에 "특성은 배틀에
영향을 주지 않습니다"라고 적혀 있던 시절은 끝났습니다.

**누가 무엇을 갖나.** 원작처럼 개체마다 정해집니다 — 일반 특성 둘 중 하나가 반반, **숨겨진
특성은 20분의 1**입니다. 파트너의 특성은 부화 순간(`bornAt`)과 부화한 종에서 해시로 정하므로
**새 난수를 뽑지 않고**(성격·색이 롤 순서가 그대로), 레벨 도입 전 저장의 파트너도 따로 기록할
것 없이 제 특성을 갖습니다. 특성은 이름이 아니라 **칸 번호**로 따라가서 진화해도 같은 칸을
씁니다(선파워 파이리는 선파워 리자몽). 메가진화하면 그 폼의 특성이 됩니다. 졸업한 종은 도감에
칸을 남기고(숨겨진 특성으로 한 번이라도 졸업했으면 그쪽), 리그 파티는 그 특성으로 싸웁니다.
야생·트레이너 포켓몬은 배틀 시드에서 해시로 정합니다 — 배틀 난수 스트림은 한 글자도 안 바뀝니다.

**어디서 작동하나.** `server/fight.ts`가 특성이 끼어드는 자리마다 확인합니다.

졸업했는지가 나옵니다.

### 배틀 규칙 — 레벨 50, 종족값, 상태이상

**모든 배틀은 양쪽 다 레벨 50입니다.** 레벨은 성장·진화·기술 해금에만 쓰고, 배틀은 레벨 50 플랫 배틀로
가정하고 **종족값**에서 능력치를 냅니다. 개체값·노력치는 0, 성격 보정은 없습니다 — 같은 종이면
같은 능력치입니다.

```
HP     = 종족값 + 60        (껍질몬만 원작대로 1)
그 외  = 종족값 + 5
대미지 = ⌊⌊22 × 위력 × A / D⌋ / 50⌋ + 2
         × 급소(1/24, 1.5배) × 난수(0.85~1.00) × 자속(1.5배) × 상성 × 화상(물리 0.5배)
```

물리 기술은 공격/방어, 특수 기술은 특수공격/특수방어를 읽습니다. **우선도가 높은 기술이 먼저,
같으면 스피드가 빠른 쪽이 먼저** 움직입니다(동속이면 난수, 트릭룸이면 느린 쪽). 스피드에는
랭크·순풍·마비(절반)가 들어갑니다. 계산은 `server/hunt.ts`의 `battleStats`·`battleAt`이 하고,
숫자는 도감 카드가 보여주는 바로 그 표(`server/dexdata.ts`)에서 읽습니다. 날씨·필드·위력표는
`server/battlefield.ts`에 있습니다.

**상태이상은 원작(5세대 이후) 효과를 그대로 냅니다.**

| 상태 | 효과 |
|---|---|
| 화상 | 턴 끝에 최대 HP 1/16, 물리 대미지 절반 |
| 독 | 턴 끝에 1/8 |
| 맹독 | 턴 끝에 n/16, 매 턴 늘어남 |
| 마비 | 스피드 절반, 25%로 행동 불능 |
| 잠듦 | 1~3턴 행동 불능 |
| 얼음 | 행동 불능, 매 턴 20%로 녹음. 불꽃 기술에 맞으면 녹음 |
| 혼란 | 2~5턴, 1/3로 위력 40짜리 자해 |
| 헤롱헤롱 | 50%로 행동 불능 |
| 바인드 | 4~5턴 동안 1/8 |
| 악몽 | 잠든 동안 1/4 |

비휘발(화상·독·맹독·마비·잠듦·얼음)은 **한 번에 하나**이고, 불꽃은 화상·독과 강철은 독·
전기는 마비·얼음은 얼음에 걸리지 않습니다. 상태 기술도 상성을 읽어서 땅 타입에게 전기자석파는
실패합니다 — 그래서 애초에 고르지 않습니다. 지속 대미지로도 쓰러질 수 있습니다.

**능력 랭크는 원작 데이터 그대로입니다.** PokeAPI의 `movemetastatchanges`를 기술 표에 구워서,
칼춤은 자기 공격 +2, 싫은소리는 상대 방어 −2, 명상은 특공·특방 +1, 오버히트는 쓰고 나면 자기

개(공격·방어·특공·특방·스피드·명중·회피)를 따로 들고 ±6까지 오르내립니다. 급소 랭크(베어가르기류

잠자기는 원작대로 HP를 전부 채우고 2턴 잡니다. 턴 상한은 20이고, 거기까지 승부가 안 나면 이긴
사람이 없습니다 — 야생은 어딘가로 가 버리고, 트레이너는 버틴 겁니다.

**트레이너전과 리그전은 팀 대 팀 한 판입니다.** 예전에는 상대 포켓몬 한 마리마다 배틀을 따로
돌려서 날씨·설치물·내 능력 변화가 매 라운드 초기화됐습니다. 이제는 `server/fight.ts`의
`fightAt` 한 번이 전부 치르고, 쓰러지면 턴 끝에 다음 포켓몬이, 교체 기술을 쓰면 그 자리에서 교체가
일어납니다. 날씨·필드·벽·설치물은 판이 끝날 때까지 남고, 파트너의 HP·상태이상·능력 변화·대타도
계속 이어집니다. 파트너는 혼자라 교체할 대상이 없으므로 파트너에게 쓰인 울부짖기는 실패하고,
파트너가 설치물을 까는 건 상대 트레이너에게 교체할 포켓몬이 있을 때만 의미가 있어서 그때만
고릅니다. 기록은 "같은 두 마리가 마주 선 구간"인 라운드로 나뉘고, 라운드마다 누가 나와 있는지와
어떻게 끝났는지(쓰러짐·끌려나감·물러남)가 남습니다.

**화면이 전부 말합니다.** 이런 일은 모두 기록(`myEvents`·`foeEvents`·`endEvents`)에 남고,
`src/battleText.ts`가 문장으로 바꿉니다 — "비가 내리기 시작했다!", "리자몽의 공격이 크게
올랐다!", "3번 맞았다!", "모래바람이 꼬렛을 덮쳤다!", "꼬렛은 도발에 넘어가 버렸다!",
"뾰족한 바위가 갸라도스에게 박혔다!". 한 박자에 두 줄이 넘으면 페이지로 넘기고, 턴 끝에 할
말이 있으면 그 턴 뒤에 박자가 하나 더 생기고, 설치물이 새로 나온 포켓몬을 치면 등장 직후에
박자가 하나 더 생깁니다. 라운드가 끝날 때는 쓰러졌는지, 불러들였는지("낚시꾼 동현은 잉어킹을
불러들였다!"), 물러났는지를 구분해서 말합니다. 날씨·필드·트릭룸은 배틀 화면 왼쪽
위 칩에 남은 턴과 함께 떠 있습니다.

**야생전도 질 수 있습니다.** HP 바닥값과 마지막 턴 강제 마무리가 없어졌습니다. 지면 **토큰도,
기술머신도, 스톤도, 전설 아이템과 조각도** 받지 못합니다. 드롭 굴림 자체는 이겼든 졌든 똑같이
하므로 어느 조우가 무엇을 떨구는지는 승패와 무관합니다.

그 대가는 수입입니다. 조우 보상은 여전히 5%/시간에 맞춰 정규화돼 있지만, 레벨 50에서 갓
부화한 기본 단계 파트너는 야생전을 자주 집니다. 실측(야생 2000판):

```
                기술 1개   기술 8개
이상해씨           18%       34%
이상해풀           33%       53%
리자몽             54%       78%
잠만보             68%       82%
망나뇽             68%       89%
캐터피(기술 없음)    1%        1%
```

그래서 **5%/시간은 상한이지 약속이 아닙니다.** 기술 하나 든 갓 부화한 알통몬은 시간당 약
1.9%를 법니다(모든 야생전을 이기던 시절 8.1%). 진화하고 기술머신을 모을수록 원래 비율에
가까워집니다. 캐터피처럼 기계 기술을 하나도 못 배우는 종은 진화할 때까지 사냥으로 벌지
못합니다 — 원작대로라면 그게 맞는 결과입니다.

### 보이는 것 — 여행과 배틀

팝오버 펫 탭 맨 위는 정지된 초상화가 아니라 **장면**이다. 평소에는 펫이 어딘가를 걷고
(두 겹 풀이 서로 다른 속도로 흘러 시차가 생긴다), 조우가 정산되면 그 자리에서 배틀이 벌어진다.

그 "어딘가"는 고정이 아니다. **지역은 사냥이 쌓이면 바뀌고, 색은 시각에 따라 바뀐다.**
아래 "지역과 시간대" 참고.

```
야생   ! → 화면 반전 3회 → 양쪽 등장 → "앗! 야생 OO가 나타났다!"
       → 빠른 쪽부터 번갈아 → "쓰러뜨렸다!" → "진행도 +210,227"
                            또는 "눈앞이 캄캄해졌다…" → "아무것도 얻지 못했다…"

트레이너 ! → 화면 반전 3회 → 트레이너 등장 → "낚시꾼 동현이 승부를 걸어왔다!"
       → 물러나고 양쪽 등장 → "낚시꾼 동현은 잉어킹을 내보냈다!" → 배틀 → …
```

## 지역과 시간대

**여정** — 펫은 15회 조우마다 다음 장소로 넘어간다. 그냥 지형이 바뀌는 게 아니라
**포켓몬 세계관을 실제로 걷는다**: 태초마을 → 상록시티 → 상록숲 → 회색시티 → 달맞이산 →
… → 석영고원, 그다음 관동에 남은 곳들, 그러고 나서 성도의 연두마을로 넘어간다. 관동 →
성도 → 호연 → 신오 → 하나 → 칼로스 → 알로라 → 가라르 → 히스이 → 팔데아, **열 지방
728곳 · 한 바퀴 약 38일(연속 가동)** 이고, 끝나면 태초마을로 돌아온다. 끝나는 여행이면
오래 켜둔 사람이 결국 한 곳에 영영 머물게 된다.

**240곳에서 728곳이 됐다.** 오래도록 하나·가라르·히스이·팔데아가 통째로 없었고 신오는
여섯 곳뿐이었는데, 기술이 아니라 이름 때문이었다 — 아래 "지명" 절 참고. 한 다리는 그때
25조우였다. 그대로 뒀으면 한 바퀴가 연속 가동 두 달, 하루 여덟 시간이면 반년이 된다.
15로 줄여 한 바퀴를 다섯 주로 되돌리면서 한 장소에 한 시간 15분씩은 남겼다.

축이 **셋**이다. **어디를 지나는가**는 `src/journey.ts`(생성물)가, **발밑이 어떻게
생겼는가**는 `src/terrain.ts`가, **지평선에 뭐가 걸리는가**는 각 stop의 `sky`가 답한다.
예전에는 `region`이 지형을 뜻했는데 세계관 지방이 생기면서 이름이 충돌해 지형 쪽을
`terrain`으로 개명했다.

**지형과 배경을 따로 분류하는 이유가 핵심이다.** 지형 시트는 존재하는 CC0 픽셀 아트가
상한을 정한다 — 사막 타일셋도 설원 타일셋도 (쓸 만한 팔레트로는) 없다. 배경은 5세대 배틀
배경 15종이라 이미 사막도 얼음동굴도 화산도 있다. 한 축으로 묶으면 **둘 중 나쁜 쪽**에
맞춰야 하므로, 두 축이 각자 낼 수 있는 최선을 낸다:

| 장소 | 발밑(terrain) | 지평선(sky) |
|---|---|---|
| 디그다굴 | `cave` 동굴 | `dampcave` |
| 은빛산 · 석영고원 | `mountain` 산길 | `mountain` |
| 방울탑 · 포켓몬타워 | `ruins` 유적 | `earthycave` |
| 홍련섬 · 하노하노비치 | `seaside` 바닷가 | `beach` · `beachshore` |
| 하이나사막 | `desert` 사막 | `desert` |
| 벨라화산공원 | `mountain` 산길 | `volcanocave` |
| 무인발전소 | `field` 풀숲 | `thunderplains` |
| **얼음길 · 프로스트케이브** | `cave` 동굴 (설원 시트 없음) | **`icecave`** |

마지막 줄이 축을 나눈 값어치다. **쓸 만한 CC0 설원 타일셋이 없다.** 한 축이었다면 저 둘은
풀숲이나 돌길 위를 걸어야 했다 — 얼음동굴 배경 밑에 잔디가 깔린다. 지금은 발밑이 동굴
암반(원작에서도 둘 다 동굴이다)이고, 얼음이라는 사실은 지평선이 말한다.

728곳 중 **462곳**이 지평선을 받고, 나머지 266곳은 `null` — 평범한 들판은 예전처럼 단색
하늘이 더 낫고, `null`이 곧 "다운로드 실패"와 같은 화면이라 실패 경로가 따로 없다.

지형 분포는 field 238 · town 114 · cave 88 · seaside 65 · ruins 58 · mountain 40 · stonepath 32 ·
lakeside 31 · forest 30 · flowers 20 · desert 12. 분류기는 슬러그와 한글명 양쪽을
패턴으로 보므로 네 지방이 새로 들어와도 한 줄도 고치지 않았고, 안 걸리는 곳은 `field`로
떨어진다 — 그것도 실제로 있는 시트라 빈 화면이 되지 않는다.

**지명은 절반이 없다.** PokeAPI는 지방 10개의 한글명을 다 주지만, 지명은 루트를 뺀 811곳 중
**213곳만** 한글명이 있다(호연·칼로스·알로라뿐). 나머지 일곱 지방은 생성기의 표가 채우고,
그 표는 각 지명의 Bulbapedia "In other languages" 줄에서 옮겨 적었다 — 한국어판 게임이
실제로 찍는 이름이다. **출처를 확인한 것만** 넣는다. 출처에도 한글명이 없던 70곳은 소유자가 직접 채웠고, 그중
스무 곳은 다시 대조해 공식명으로 고쳤다 — 나머지 쉰 곳은 공식 한글판이 없는 곳이라 통용명을
쓰고 생성기에 `※`로 표시해 두었다(일곱섬은 3세대가 한글화되지 않아 포켓몬스터 SPECIAL
번역명 기준이다). 이제 열 지방에서 이름 없이 빠지는 곳은 없다.

**그 표가 기존 이름 여덟 개를 고쳤다.** 손으로 적어 둔 47곳을 같은 출처로 다시 뽑아 대조하니
35곳이 그대로였고, 넷은 띄어쓰기, 여덟은 **틀린 이름**이었다 — 스프라우트탑에 방울탑(그건
다른 건물이다) 이름이 붙어 있었고, 진청시티가 초옥시티로, 너도밤나무숲이 뭉게숲으로 적혀
있었다. 35곳을 그대로 재현하고 여덟 개를 고치는 출처는 손으로 확인하던 것보다 나은 출처다. 첫 초안이 New Bark Town을 무궁마을로
적었는데 그건 Cherrygrove고 New Bark는 **연두마을**이었다. 조사 중 한국어 위키백과도
보라타운을 Viridian City라고 자신 있게 적어뒀다(보라타운은 Lavender Town). 여정이 짧은 편이
틀린 지명을 띄우는 것보다 낫고, 영문 슬러그가 새는 건 더 나쁘다. 하나·가라르·히스이·팔데아와
신오 대부분은 아직 비어 있고, 생성기 주석에 TODO로 남아 있다.

**저장하지 않는다.** `hunt.count`가 이미 페이로드에 있고 오르기만 하므로 `journeyFor(count)`로
파생시킨다 — 스키마 범프도, 마이그레이션도, 둘이 어긋날 방법도 없다. 지역이 바뀌는 건
시트 URL 하나가 바뀌는 것뿐이고 CSS는 손대지 않는다. 그래서 모든 시트가 48×48에 16px
스트립 3줄(far/near/ground)이라는 **동일한 기하**를 지켜야 한다. 스크롤 키프레임이 정확히
스트립 한 폭만큼 이동하기 때문에, 폭이 다른 시트가 섞이면 매 사이클 튄다 — 생성기가 assert로
막는다.

**시간대** — 새벽(5–9) / 낮(9–17) / 황혼(17–20) / 밤(20–5). 로컬 시각 기준이고, 원작(HGSS·BW)의
구간을 따랐다. 아트는 팔레트가 구워진 픽셀 아트라 토큰으로 다시 칠할 수가 없으므로, **같은
아트에 필터를 씌운다** — 다크 모드가 이미 하던 일(`brightness(0.72) saturate(0.85)`)을 네 단계로
일반화한 것이다. 하늘(`--sky`)은 필터가 닿지 않는 배경색이라 따로 옮긴다.

여기서만 **시각이 OS 테마를 이긴다.** 오후 2시의 다크 모드 사용자는 오후를 보고 있는 것이고,
장면을 둘러싼 패널 크롬은 여전히 테마를 따른다. 시간을 갖는 건 창이 아니라 디오라마다.

필터는 `.scene`에는 절대 걸지 않는다. 스프라이트와 배틀 UI가 자식이라 같이 물들고, 필터가 걸린
요소는 absolute 자식들의 containing block이 되어 배틀 화면이 의존하는 px 오프셋이 전부 흔들린다.
그래서 `.scene-grass` / `.scene-ground`, 그리고 배틀 배경은 `::before` 레이어에만 건다.

갱신은 폴링에 얹는다. 페이로드가 이미 몇 초마다 리렌더하므로 경계는 한 폴 안에 넘어간다 —
그걸 즉시로 만들자고 타이머를 하나 더 둘 값어치는 없다.

### 전용 공간은 만나기 전까지 여정에 없다

여정이 728곳이 되면서 **시작의 방**과 **창기둥**이 평범한 정류장이 됐다. 펫이 아르세우스의
방을 한 시간 15분 서성이다 다음 칸으로 넘어간다. 3섬 항구와 같은 취급이다.

그래서 **주인을 만나기 전까지 그 방들은 route에서 빠진다.** 54곳이다 — 시작의 방·창기둥·
호수 셋·레지 3형제의 석실 아홉·팔데아 사당 넷·일륜과 월륜의 제단 같은 곳들.

**"만났다"는 이겼다가 아니다.** 기라티나에게 깨졌어도 만난 것이고, 그 방은 그만큼 실재한다.
`metLegends`가 승패를 가리기 전에 기록한다.

**펫은 앞으로 건너뛰지 않고 뒤로 물러선다.** 잠긴 방을 만나면 직전 정류장을 한 다리 더
보여준다. 인덱스는 예전과 똑같이 나아가고 *보이는 이름*만 달라지므로, 한 바퀴 길이도
지방 도달 기준도 체육관 도시도 배지함의 "회색시티까지 N조우"도 **하나도 안 움직인다.**
앞으로 건너뛰게 했다면 사람마다 여정 길이가 달라지고, 방 하나가 열릴 때마다 "지금 어디냐"의
답이 바뀐다.

#### 표는 양쪽에서 읽어서 만들었다

각 전설의 문서가 자기가 봉인된 방을 말해 주고("In Hoenn, it was sealed in the Desert
Ruins"), 각 방의 문서가 자기 주인을 말해 준다("It is the shrine in which Wo-Chien was
sealed"). **한쪽만 읽으면 거짓말을 한다** — 전설 쪽만 훑었을 때 해저유적에 토네로스가,
화염의 방에 칠색조가 붙었는데, 그 방들의 문서를 열어 보니 그런 문장이 없다. 아이템 위치
언급이 걸린 것이었다.

**주인을 말해 주지 않는 방은 넣지 않았다.** 언노운의 석실들(이라님 석실·옥포그리 유적·
알프의 유적·신수유적), 칼로스의 다섯 방, 해저유적, 그리고 고시의 석실 — 마지막 것은 레지의
석실을 여는 열쇠지 방이 아니다.

바위산의 유적과 빙산의 유적은 신오와 가라르 양쪽에 같은 이름으로 있고 둘 다 같은 레지가
봉인된 곳이라, 한 줄이 두 정류장을 함께 잠근다. 이름으로 키를 잡아서 공짜로 얻은 것이다.

#### 전용 배경은 찾아봤고 없다

**PokeAPI 스프라이트 저장소**에는 badges·items·pokemon·types 넷뿐이라 장소 그림이 없다.
**쇼다운 `fx/`** 에는 `bg-*.png`가 36개인데, 15개가 이미 쓰는 5세대 풍경화이고, 8개는 대회
배너(spl·scl·npa·wcop)이며, 나머지 13개(`gen1`~`gen4`와 변종)는 **전투 화면을 통째로 그린
합성물**이다. HP 플레이트와 메시지 박스가 그림에 박혀 있어서, 깔면 `gen-ui.ts`가 그리는
전투 UI 안에 두 번째 전투 UI가 들어앉는다. 취향이 아니라 종류가 다르다.

CC0도 답이 아니다 — `server/movefx.ts`가 기술 이펙트에 대해 이미 같은 결론을 적어 뒀다.

**대신 조사하다 진짜 문제를 찾았다.** 그 방들 중 일곱 곳이 배경 없이 `field`로 그려지고
있었다. 아르세우스의 방이 풀밭이었다. 새 리소스 없이 선반의 열다섯 장으로 고쳤다 —
제단·기둥·시작의 방은 산 위이므로 `mountain`, 배꼽바위는 `beach`, 송별의샘은 `river`.
그리고 **`deepsea`가 처음으로 쓰인다.** `server/biome.ts`가 "실재하고 닿을 수 있는데 아직
아무것도 안 가리킨다"고 적어 둔 그 배경이고, 거품이 떠 있는 어두운 해저 동굴이라
**바다 동굴**(가이오가)에 정확히 맞는다.

## 상태 화면

펫 탭이 원작 요약 화면 역할을 한다. 탭은 늘리지 않았다 — 420px 패널에 6개가 이미 빡빡하다.

```
[장면]
우리레오 ✏️              ← 연필을 누르면 인라인 편집, Enter 확정 / Esc 취소
```

## 도감

떠나보낸 포켓몬이 **스프라이트와 함께** 카드 격자로 쌓인다. 이로치는 이로치 스프라이트로,
테두리도 강조된다.

**진화체를 졸업시키면 지나온 형태가 전부 등록된다.** 리자몽을 키웠다는 것은 파이리를
키웠다는 뜻이니까. `Companion.pathIds`가 부화 때 확정된 경로 전체라
`pathIds.slice(0, stageIndex + 1)`이면 끝난다. 닉네임은 **실제로 떠난 형태에만** 붙는다 —
앞 단계는 "지나갔다"는 기록이지 그 이름으로 떠난 개체가 아니다.

졸업과 알 구매 두 경로가 `retireInto()` 하나를 공유한다. 예전에는 각자 복사본을 갖고 있었고,
그게 두 경로가 어긋나는 방법이다.

옛 저장본은 `migrate`에서 한 번 소급 등록된다. 분기 라인에서도 안전한데,
**541개 라인 전수에서 선행 단계가 모호한 종이 0개**이기 때문이다 — 라플레시아와 아르코는
둘 다 뚜벅쵸 → 냄새꼬를 거치고, 뷰티플라이와 독케일은 실쿤/카스쿤에서 갈리지만 서로의
경로에 나타나지 않는다.

**세대는 데이터를 굽지 않는다.** 9세대 전부 연속 id 구간임을 PokeAPI로 확인했으므로

**도감 색인은 페이로드가 아니다.** 미수집 칸을 보여주려면 1025종의 이름·등급·세대·타입이

`/api/dex`(브라우저) · `pet:dexIndex`(Electron)로 빼서 토글을 처음 켤 때 한 번만 받는다.
미수집 칸은 스프라이트를 받지 않으므로 토글을 켜도 다운로드가 늘지 않는다.

### 상세 화면

카드를 누르면 **그 자리에서 격자가 엔트리 화면으로 바뀐다.** 원작이 하는 일이 그거다 —
책장에서 한 권을 고르고 B로 돌아온다. 그리고 420px 팝오버에 정보가 다 들어가는 방법이
그것뿐이다: 이 패널은 이미 떠 있는 창이라, 모달을 띄우면 창 안의 창이 되고 스크림이 덮을
"바깥"이 없다. 앱에 `position: fixed`는 여전히 `.flash` 하나뿐이다.

가방의 기술머신 슬롯 선택기가 이미 같은 일을 작은 규모로 한다 — 목록을 제자리에서 선택기로
바꾼다. 이건 그걸 화면 크기로 한 것이지 새 장치가 아니다.

**머리 부분은 격자가 들고 있던 것으로 즉시 그린다.** 열어 둔 카드를 id 쌍이 아니라 **행 통째로**
들고 있기 때문이다 — 번호·이름·그림·이로치·타입이 곧 엔트리 화면의 머리다. 네트워크를 기다리는
것은 그 아래 절들뿐이라 돌릴 스피너가 없다.

**미수집 칸은 누를 수 없다.** `mine`이 정의상 비어 있고, 스프라이트를 받지 않는다는 위의 약속을
깨지 않으려면 그림 없는 화면을 열게 되기 때문이다. 원작도 등록되지 않은 번호는 열어주지 않는다.

**초점은 키로 되돌린다.** 상세가 열린 동안 격자는 언마운트되므로, 들어갈 때 잡아둔 노드는
돌아왔을 때 detached다 — detached 노드의 `.focus()`는 **아무 일도 조용히 일어나지 않는다.**
카드마다 `data-key`를 달고 키로 다시 찾으면, 덤으로 그 카드가 화면 안으로 스크롤된다.

**상세도 페이로드가 아니다.** 색인과 같은 이유이면서 반대 방향이다: 색인은 정적이라 한 시간
캐시하지만, 상세는 절반이 플레이어 자신의 기록이라 `no-store`다. 졸업이 한 시간 뒤에 반영되면
고장으로 읽힌다. `/api/dex/:id`(브라우저) · `pet:dexEntry`(Electron)로 **누른 종 하나만** 받는다.

라우트 순서가 조용한 함정이었다. 색인이 `startsWith('/api/dex')`인데 **`/api/dex/25`도 이 조건을
만족한다** — 순서를 뒤집으면 모든 상세 요청이 **아무 에러 없이** 116KB짜리 색인을 돌려받는다.
상세를 앞에 두고, 색인 조건은 정확 일치로 좁혔다. 순서 하나가 정확성을 떠받치지 않도록.
테스트 목에도 같은 함정이 있어서 같이 고쳤다 — 안 고쳤으면 새 테스트가 **틀린 이유로 통과했다.**

#### 굽지 않아도 나오는 것들

절반은 이미 저장소 안에 있었다. **방어 상성**이 특히 그렇다 — `effectiveness`를 공격 타입 쪽으로

**폼이 없는 종은 줄 자체가 없습니다**와 같은 규칙이다.

**진화 라인은 경로가 아니라 단계로 접는다.** `lineOf(133).paths`는 **여덟 개**다. 경로마다 한 줄씩
그리면 420px에 첫 칸이 전부 이브이인 여덟 줄이 된다. 단계마다 한 칸이 원작이 트리를 그리는

**폼은 `formsFrom`이 아니라 `f.base === speciesId`로 찾는다.** `formsFrom(800)`은
울트라네크로즈마를 빠뜨린다 — 이미 합체한 네크로즈마에서만 도달하므로 `from`이
`[10155, 10156]`이라 800에서 안 잡힌다. `formsFrom`은 "지금 이 모습에서 어디로"라는
**배틀의 질문**이고, 도감은 "이 종에 무엇이 있나"를 묻는다.

#### 도감 설명이 없는 127종

`#899` 이상은 PokeAPI에 **한국어 행이 아예 없다.** 요청이 실패한 게 아니라 번역이 없다.

집안 규칙(한글이 없으면 throw)의 기존 대응은 셋이었다 — 성격은 **throw**, 메가 이름은 **합성**,
여행지는 **생략**. 여기엔 셋 다 안 맞는다: #900도 도감에 있고 카드도 받는다.
그래서 네 번째 답이다 — **없는 대로 두고, 화면이 설명 상자를 아예 그리지 않는다.**
빈 상자도 "설명 없음"도 아니다.

생성기는 개수가 아니라 **경계**를 못박는다. `KO_FLAVOR_THROUGH = 898`. 127이라는 숫자는 오늘의
사실이고, "898까지 전부 있고 그 위로는 없다"가 주장이다 — 이렇게 써야 요청 한 덩어리가 조용히
빈손으로 돌아왔을 때 경계가 끌려 내려가고 생성이 멈춘다. 위쪽이 채워지는 건 좋은 소식이라
로그만 남긴다. `NO_MACHINE_MOVES`와 같은 본능이다.

특성은 반대다 — **이름은 284개 전부 한글이 있어서 하나라도 없으면 throw**하고, 설명만
248/284라 없는 줄은 이름으로 끝난다.

#### 종족값을 넣은 대가

**넣었고, 이제 배틀이 그대로 씁니다.** 종족값 막대 아래에
`원작 수치입니다. 이 앱의 배틀은 양쪽 모두 레벨 50, 개체값 없이 이 종족값으로 능력치를 계산합니다.`가
붙습니다. 처음 넣을 때는 반대 문장("배틀은 종족값을 읽지 않고…")이었고, 배틀이 레벨 50
능력치로 바뀌면서 뒤집혔습니다.

**테스트가 출처를 하나로 묶습니다** — `server/hunt.ts`는 `dexdata.ts`의 `statsOf`를 import해야
하고, `game.ts`·`state.ts`는 하면 안 됩니다. 도감 카드에 보이는 숫자와 배틀이 쓰는 숫자가
같은 표에서만 나오게 하려는 것입니다.

막대 분모는 **255가 아니라 180**이다. 255에 닿는 종이 거의 없어서 255로 나누면 여섯 막대가
전부 절반도 안 차고, 그러면 종끼리 비교가 안 된다 — 막대가 하는 유일한 일이 그건데.

#### 조판은 파트너 탭에서 빌려온다

`.portrait` · `.bars.info` · `.types` · `.chain`을 그대로 쓴다. 두 화면이 갈라지지 않게 하는 게
재사용의 목적이다. **종족값 막대에는 새 CSS가 한 줄도 필요 없었다** — `.bars li`가 이미
라벨·막대·숫자 3열이고, 토큰 탭의 `어디서 썼나`가 쓰는 마크업 그대로다.

새로 쓴 건 셋뿐이다. `.dex .card`는 상자를 칸에서 **카드로 옮긴다** — 누르는 것이 곧 상자여야
한다(`.items .rowbtn`이 이미 정리한 논쟁). `.dexart`는 카드의 48px 박스의 정확히 두 배다.
`.bars.matchups`는 배수 라벨 열이다.

**도감 설명 상자는 `.uiwin`을 입되 `.saywin`은 아니다.** 점원의 상자가 92px 고정인 이유는 그
아래에 누를 목록이 붙어 있어서인데, 여기는 아래에 누를 게 하나도 없고 상자가 열릴 때 한 번
쓰이고 상태가 바뀌지 않는다. 반면 비용은 진짜다 — 92px는 약 3.6줄이라 네 줄짜리 설명은
**마지막 문장을 잃는다.** 아무도 없어진 걸 알 수 없는 그 문장을. 그래서 같은 숫자를
천장이 아니라 **바닥**(`min-height`)으로 쓴다.

## 체육관과 배지 — 여정에 목적지가 생긴다

여정은 오래 배경이었습니다. 15조우마다 728곳을 걸어 관동에서 팔데아까지 35일에 한 바퀴를
도는데, 회색시티를 지나든 석영고원을 지나든 바뀌는 건 발밑 타일과 지평선뿐이었습니다.
관동 8체육관은 **걸어서 도착할 목적지**를 처음 만듭니다.

### 관장은 자기 도시에만 서 있습니다

규칙 하나입니다 — **펫이 서 있는 도시의 관장이, 아직 이기지 않았으면** 그 다리의 leg offset
2·7·12에 승부를 걸어옵니다. 회색시티에서는 웅, 블루시티에서는 이슬이고, 그 사이 길에서는
아무도 서 있지 않습니다. **배지 순서 제한은 없습니다** — 웅에게 져도 블루시티에서 이슬에게
도전할 수 있습니다.

예전에는 "자격이 되고 아직 안 이긴 관장 중 가장 앞선 사람이, 도시가 현재 정류장 이하면"
서 있었습니다. 그래서 배지가 0개면 회색시티를 지난 뒤로 **관동 어느 도시를 지나도 웅이
나왔습니다.** 도시와 관장이 따로 놀았던 거고, 순서 제한이 그걸 강제했습니다. 순서 제한을
없애면 따라올 이유도 없어집니다.

**예외는 원작이 잠가 둔 체육관 하나뿐입니다.** 비주기(`lateLock`)는 관동의 다른 일곱 배지를
모두 모아야 열리고, 열린 뒤로는 자기 도시(상록시티, 정류장 1)부터 **펫을 따라옵니다** —
그렇지 않으면 일곱 번째 배지를 따고 한 바퀴를 더 돌아야 합니다.

**놓치면 한 바퀴입니다.** 도시 하나에 머무는 다리 하나에서 세 번이 기회이고, 지거나
지나치면 다음 방문은 한 바퀴 뒤입니다. 순서가 자유로워서 한 관장에게 막혀도 나머지 지방은
그대로 열려 있으니, 한 번 지는 값이 지방 전체를 잠그지는 않습니다.

**배지 번호와 만나는 순서는 다릅니다.** 노랑시티(정류장 13)가 연분홍시티(14)보다 먼저라 초련을
독수보다 먼저 만나고, 배지 번호는 원작 그대로 6번과 5번입니다. `GymRow.order`는 이제 관문이
아니라 배지함과 사다리를 **길 순서로 늘어놓는** 열입니다.

### 뽑기를 한 번도 하지 않습니다

팀이 표에 박혀 있어서 `gymAt`은 draw가 없습니다. `trainerAt`이 네 번째 솔트를 써야 했던 이유
— 조우 스트림을 밀면 과거 조우가 전부 달라진다 — 가 여기서는 **구조적으로 해결**됩니다.
새 RNG 솔트가 필요 없고, `test/gyms.test.ts`가 2만 조우로 그걸 지킵니다.

### 여덟 번 다 질 수 있습니다

팀은 원작 그대로 자르지 않았습니다. 웅 2마리부터 비주기 5마리까지입니다. 파트너 한 마리가
레벨 50 팀 전체를 회복 없이 상대하므로, 원작 능력치 그대로(grit 1.0)면 관동 관장 대부분이
**승률 3~16%** 입니다. 그래서 **`grit`으로 조율합니다.** grit은 상대의 **스피드를 뺀 모든
능력치**에 곱합니다 — 누가 먼저 움직이는지와 어떤 상성이 좋은지는 원작 그대로 두고, 얼마나
세게 때리고 얼마나 버티는지만 움직입니다.

grit은 한 마리당 강함이라 **팀이 큰 관장일수록 grit이 낮습니다.** "1차 통과"는 그 시점에
실제로 들고 있을 기술머신 수(`TM_DROP_CHANCE` 0.04 × 조우)를 굴린 것에 Lv.50까지의
레벨업 기술을 더해, 그중 위력 상위 4개를 배치한 값입니다(특성은 개체마다 정해진 대로). 최종 진화 파트너 10종 평균, 관장당 900판:

```
관장      팀 grit   만나는 조우   1차 통과   맨몸
웅        2 1.12        47         62%       0%
이슬      2 0.95        77         61%       9%
마티스    3 0.80        92         62%      30%
민화      3 0.77       167         61%      15%
초련      4 0.58       197         62%      33%
독수      4 0.72       212         61%       3%
강연      4 0.64       242         63%      12%
비주기    5 0.51       247         62%       0%
```

68곳 전부를 같은 방법으로 **62%를 향해 이분 탐색**했습니다. 날씨·랭크·선공이 들어온 뒤,
팀 대 팀 한 판이 된 뒤, 그리고 **레벨업 기술·특성·부가 효과가 전부 들어온 뒤** 한 번씩 더
쟀습니다. 마지막 측정에서 55~63%입니다. 레벨업 기술이 파트너에게 제 타입의 강한 기술을
쥐여 줘서 예전 grit 그대로면 중앙값이 80%까지 올라갔기 때문에, 대부분의 관장 grit이 올랐습니다.
예전엔 멜리사·나누·모야모·라임이 고스트·악 타입 때문에 목표 아래에서 평평해졌는데, 레벨업
기술이 들어온 뒤로는 파트너들이 칠 기술을 갖게 되어 그 평평한 구간이 사라졌습니다. 테스트의
하한 35%·상한 85%는 그대로입니다.

**맨몸은 대체로 훨씬 낮습니다**(관동 평균 약 13%, 비주기 0%). 마티스처럼 맨몸과 1차 통과가
비슷한 관장은, 그 시점 가방이 기술머신 서너 개라 맨몸과 크게 다르지 않아서입니다.

### 배지 부상은 그 관장의 기술머신입니다

**적록이 아니라 파이어레드·리프그린 목록을 씁니다.** 적록의 참기·사이코웨이브·땅가르기는
`power: 0`이라 `FIXED_POWER`로 떨어지고, 땅가르기는 명중 30이라 70%를 빗나갑니다. 전투가
쓸 수 없는 기술을 상으로 주는 건 리메이크 목록을 고르는 것보다 나쁜 불충실입니다.

| 배지 | 기술머신 | 위력 |
|---|---|---|
| 회색 | 암석봉인 | 60 |
| 블루 | 물의파동 | 60 |
| 오렌지 | 전격파 | 60 |
| 무지개 | 기가드레인 | 75 |
| 핑크 | 맹독 | 상태 |
| 골드 | 명상 | 상태 |
| 진홍색 | 불대문자 | 110 |
| 그린 | 지진 | 100 |

목록 자체가 사다리입니다. **이기기 가장 어려운 배지가 다음 싸움을 가장 크게 바꿉니다** —
져서 못 받은 기술머신이 다음 도전을 어렵게 하고, 이겨서 받은 게 다음을 쉽게 합니다. 원작의
설계이고, 이게 패배를 나선이 아니라 자가 치유로 만듭니다.

### 보상과 상한

관장 승리는 `6 × 마릿수 × 2`입니다 — 웅 24배, 비주기 60배. 예전 식은 `3 × 마릿수 × grit × 2`
였는데, grit이 이제 "이 싸움의 값"이 아니라 관장마다 다른 조율 다이얼이라(고스트 체육관은
낮아야 합니다) 보상에서 뗐습니다. 6은 예전 열이 마리당 평균으로 주던 값이라 로스터 전체의
보상 총량은 그대로입니다. **이상한사탕은 여기서도 안
줍니다** — `bonusTokens`로 들어가 `huntCap`을 우회하고, `server/trainer.ts`가 같은 이유로
이미 거절합니다.

**갓 설치한 저장은 관동을 도는 동안 `huntCap`에 닿습니다.** 하한이 3 HT인데 배지가 붙은 관동
통과가 3.15~5.0 HT입니다. 무지개시티 언저리에서 배지 페이아웃이 0으로 잘리는데, 숫자를 바꿀
이유는 아니고 **캠페인이 상한에 면역이라는 걸 적어 둘 이유**입니다 — 배지도, 부상 기술머신도,
아이템 굴림도, 업적 상금도 전부 `huntCap` 바깥입니다.

### 승부는 물어본 뒤에 합니다

관장 승부는 `hunt()`가 배치 정산 안에서 결론을 냈습니다. 앱이 닫혀 있는 동안에도 정산되니까,
**배지가 걸린 단 하나의 승부가 아무도 볼 수 없는 승부였습니다.** 얼마나 못 보는지 세어 보면
이렇습니다 — 한 번에 최대 96조우가 정산되고, 로그는 20개만 남고, 장면은 `huntLog[0]` 하나만
재생하고, 그마저 첫 payload에서는 무장만 합니다. 조우가 최신이어야 하고, 패널이 파트너 탭에
열려 있어야 하고, 폴링이 보고 있는 순간에 떨어져야 합니다. 셋이 겹치는 일은 드뭅니다.

그래서 **관장과 리그는 물어봅니다.** 카드에 도전과 나중에가 있고, 도전을 누르면 **그 자리에서**
싸웁니다. 다음 조우를 기다리지 않는 이유는 그게 최대 5분이고, 5분 뒤에 벌어지는 일은 "볼 수
있다"가 아니기 때문입니다.

**정산 루프를 기다리게 만들 수는 없었습니다.** `huntCount`는 한 방향 연속 커서라 "아직 정산 안
된 조우"라는 상태가 없고, `hunt()`는 5분이 지나야 할 일이 생깁니다. 그래서 루프는 **싸우지
않기만** 하고, 승부는 액션 쪽에서 벌어집니다.

**제안은 저장하지 않고 유도합니다.** 누가 서 있는지, 어느 배지가 걸렸는지는 모두
`(huntCount, badges, leagues)`의 순수 함수입니다. 저장하면 사본이 어긋나고, 어긋나지 않게
유지하려면 갱신 코드가 필요합니다 — 그게 `forcedNext`의 모양이고, 그건 만료도 철회도 없어서
커서가 지나가면 기능 전체가 영구히 막힙니다. 그래서 저장하는 것은 **사용자의 답**뿐입니다.

**수락은 조우 하나를 씁니다.** 장식이 아니라 재생의 조건입니다. 장면과 펫 창은 둘 다
`huntLog[0].seq`를 지난번 재생한 번호와 비교하므로, 지나간 번호를 찍은 항목은 조용히
건너뛰어집니다. 다음 번호를 쓰면 항상 최신이 되고, 기존 재생 경로가 한 줄도 안 바뀝니다.

**한 다리에 세 번까지.** 자동 사냥이 한 다리에 관장에게 갖는 기회와 같은 수입니다. 없으면
보려고 고른 것이 이길 때까지 재시도하는 것이 되고, 모든 체육관은 질 수 있어야 합니다 —
`grit` 열이 그 위에서 측정됩니다.

**재대결은 묻지 않습니다.** 배지가 걸려 있지 않고, 지방을 다 넘기면 한 바퀴에 수십 번을 묻게
됩니다. 그리고 이긴 관장과의 스파링은 지방을 다 쓸어담은 뒤 `gymWins`를 움직이는 유일한
것이라 — 도장깨기 업적이 재는 바로 그것이라 — 막으면 그 줄이 영구히 도달 불가가 됩니다.

**결과는 장면이 말합니다.** 도전을 누르면 승부는 그 자리에서 결정되지만, 예전에는 그 응답
("회색배지를 받았습니다!")을 토스트로 **곧바로** 띄웠습니다. 장면은 그다음 payload가 와야
시작하니, 사용자는 결과를 먼저 보고 배틀을 나중에 봤습니다. 지금은 이렇게 흐릅니다:

1. 도전 → 서버는 **밀린 조우부터 정산**하고(그래야 이 승부가 `huntLog[0]`으로 남습니다) 싸운
   뒤, 결과 없이 "관장 웅에게 승부를 걸었습니다!"만 돌려줍니다.
2. 패널은 그 응답을 토스트로 띄우지 않고, 도전 카드를 **숨깁니다** — 이기면 카드가 사라지고
   지면 "기회 2번 남음"이 되는 차이도 결과를 말해 버리기 때문입니다.
3. 장면이 배틀을 재생하는 동안 진화·업적·새 도전 토스트는 **보류**됩니다. 배지를 딴 진행도로
   진화하면 "진화!"가 배틀보다 먼저 뜰 수 있었습니다.
4. 장면이 끝나면(`onPlaying(false)`) 보류된 토스트가 한꺼번에 뜹니다. 20초 안에 장면이
   시작되지 않으면 보류를 풉니다.

장면이 재생하는 배틀은 서버가 다시 계산한 것인데, 정산과 재생 사이에 `advance`가 파트너를
진화시킬 수 있습니다. 능력치가 종족값에서 나오니 진화한 종으로 다시 계산하면 **다른 승부**가
됩니다. 그래서 파트너가 싸운 모든 조우에 `mine`(종과 기술)을 기록하고, 재생은 그 기록으로
합니다.

**알리는 쪽이 절반입니다.** 이 앱은 조우를 알린 적이 없었습니다. 그래서 제안이 생기면 토스트가
뜨고, 파트너 탭에 점이 붙고, 데스크톱 펫에 `!`가 **계속** 붙어 있고, 트레이 툴팁이 이름을
말합니다. 아무도 못 보는 카드는 안 묻는 것과 같습니다.

### 배지함은 업적 탭에 있습니다

탭은 안 늘렸습니다 — 420px 패널에 일곱 개가 이미 빡빡합니다. 도감 그리드를 그대로 빌려
4칸 2줄로 놓았고, 못 딴 칸은 도감의 `.unseen`(파선 + 45%)에 회색조를 더합니다. **색이
"땄다"와 "아직"의 전부**라 그게 빠지는 게 맞습니다.

칸마다 한 줄이 상태를 말합니다 — 땄으면 배지 이름과 부상 기술머신, 아직이면 도시와
"62조우", 상록시티면 "배지 7개 필요". **기다림을 읽을거리로 만드는 자리**이고, 알 게이지와
업적 게이지가 이미 하는 일입니다.

#### 지방과 업적은 쌓지 않고 고릅니다

관동 하나일 때는 배지함 아래에 업적 목록을 이어 붙여도 됐습니다. 아홉 지방이 되고 업적이
77줄 열 칸이 되고 나니 **한쪽을 보려면 다른 쪽을 지나쳐 스크롤해야** 했습니다. 배지함이
한 화면, 업적 목록이 일곱 화면입니다.

그래서 탭 위쪽에 화면 전환을 두고, 한 번에 한쪽만 그립니다. 상태는 하나입니다 —
`awardCat`에 `'region'`이 들어가면 그게 지방 화면이고, 업적 쪽 필터(`a.cat === awardCat`)는
아무것도 안 맞아서 목록이 **구조적으로** 빕니다.

탭은 **지방으로 열립니다.** 업적 목록은 첫 소제목이 나오기도 전에 화면을 다 쓰고, 지방
화면은 한 화면이고, 펫이 걷는 동안 바뀌는 쪽은 지방입니다.

**요약 줄도 화면을 따라갑니다.** 위쪽 숫자가 지방 화면에서는 "12개 / 68개 배지 · 명예의
전당 1 / 9"를, 업적 화면에서는 "23개 / 77개 달성"을 말합니다. 머리말이 몸통과 다른 것을
말하면 읽는 사람이 둘 다 안 믿게 됩니다.

**탭의 점도 옮겼습니다.** 업적이 하나 달성되면 탭에 점이 붙는데, 지금까지는 탭을 여는 순간
꺼졌습니다. 이제 탭을 열어도 업적 목록은 안 보이므로, **업적 화면으로 들어갈 때** 꺼집니다.

#### 칩을 21개 늘어놓았다가 2개로 줄였습니다

첫 판은 화면 전환과 분야 필터를 **한 칩 줄에** 넣었습니다. `지방` 다음에 `전체`, 그다음
분야 열 칸. 420px에서 세 줄로 접혔고, 그 아래 지방 칩 아홉 개가 또 두 줄이었습니다.
**칩 21개.** 사용자가 "어지럽다"고 한 것이 이것이고, 맞는 말이었습니다.

원인은 한 줄이 두 가지 일을 한 것입니다. `지방`은 **모드**이고 나머지 열한 개는
**필터**입니다. 데이터로는 한 변수에 담는 것이 맞았지만, 컨트롤로는 아니었습니다.

레퍼런스를 찾아보니 전부 같은 말을 합니다. 애플 HIG는 세그먼티드 컨트롤을 다섯에서 일곱
개로 보고 그보다 많으면 "hard to parse"라고 합니다. 머티리얼 3은 칩이 두 줄을 넘기면
"each chip harder to scan"이라며 가로 스크롤이나 메뉴로 넘기라고 합니다. eBay는 "Do use a
single row of chips". 좁은 화면 가이드들은 부차적 필터를 접으라고 합니다.

가로 스크롤은 이 앱에 없습니다. 패널에 `overflow-x` 스트립이 한 곳도 없고, 데스크톱
팝오버에서 가로로 숨긴 것은 발견되지 않습니다. 남는 답 셋을 다 썼습니다.

**모드는 전환 줄로.** `.chips shopchips` 버튼 둘(`지방` / `업적`). 가방·도감·상점이 "지금
어느 판을 보고 있나"에 쓰는 그 줄 그대로입니다. 한 줄이고, 절대 접히지 않고, 분야나 지방이
늘어도 그대로입니다.

**필터는 접어서.** 도감이 타입 칩 18개를 `필터` 링크 뒤에 접어 둔 그 관용구 그대로,
분야 칩 열한 개가 `분야` 링크 뒤로 갑니다. 접힌 라벨이 고른 분야를 괄호로 답니다 —
`분야 (도감)`. 도감은 개수를 다는데 여기는 하나만 고르는 자리라 `1`은 아무 말도 안 합니다.

**목록은 목록으로.** 지방 칩 아홉 개가 아홉 줄이 됩니다. 아래를 보십시오.

#### 지방 칩이 지방 목록이 됐습니다

한 지방씩 보는 배지함에는 "아홉 지방을 어디까지 했나"가 나올 자리가 없었습니다.
`clearedAt`(그 지방 명예의 전당에 오른 시각)은 리그가 지방별이 된 날부터 페이로드에 있었고
**읽는 코드가 한 줄도 없었습니다.**

처음에는 칩에 붙였습니다. 안 간 지방은 이름만, 도는 중이면 `4/8`, 제패했으면 `★`. 칩이
작아서 별이 숫자를 **대신해야** 했고, 두 줄로 접혔고, 아홉을 나란히 비교할 수 없었습니다.

```
관동  ████████  8/8 ★
성도  ████░░░░  4/8
호연  ░░░░░░░░  0/8
```

줄이 되니 세 가지가 한꺼번에 좋아집니다. **게이지가 붙어** 아홉을 세로로 비교할 수 있고,
**별이 숫자 옆에 서고**(칩에서는 `8/8 ★`가 안 들어갔습니다), 별이 **액센트 색을 씁니다** —
칩에서는 선택된 칩이 액센트로 꽉 차 있어서 그 안의 별이 색을 못 썼고 투명도 65%로 물러나
있어야 했습니다.

기록 탭의 토큰 막대(`.bars`)를 그대로 입습니다. 프레임까지 포함해서요 — 그 클래스의 주석이
"프레임이 없으면 색 바탕 위에 얹혀서 미완성으로 읽힌다"고 적어 둔 것이 아홉 지방에도 그대로
맞습니다. 줄만 촘촘하게 합니다: 12px 대신 10px, 여백은 `--s1`. 한 줄 19px, 아홉 줄에
프레임까지 193px입니다.

**고른 줄은 액센트로 채우지 않습니다.** 표면 틴트(`var(--track)`)와 굵은 글씨입니다.
`.items li.row:hover`가 이미 정한 답이고, `.items button:not(.rowbtn)`이 존재하는 이유가
"374px짜리 줄을 액센트로 칠하지 마라"입니다. 칩은 작으니까 채울 수 있었던 것입니다.

**줄 전체가 누를 곳입니다.** `.items .rowbtn`의 주석이 적어 둔 그대로 — 원작은 줄을
고르게 하지, 줄 끝의 컨트롤을 고르게 하지 않습니다.

### 포켓몬리그 — 도감이 처음으로 무언가를 합니다

도감은 지금껏 아무것도 하지 않았습니다. 졸업한 포켓몬의 기록이고, 채워지고, 그걸 읽는 코드가
한 줄도 없었습니다. **리그 파티가 그걸 읽는 첫 번째 것**입니다 — 실제로 키운 여섯 마리를
가방에서 무장시켜 석영고원에 데려갑니다.

**파트너는 이 일에서 빠집니다.** 사냥도 체육관도 지금처럼 파트너 한 마리가 합니다. 한 번에
한 마리를 키우는 게 이 앱의 모양이고, 파티가 사냥까지 하면 조용히 다른 게임이 됩니다.

**상대는 적록 원작 그대로 26마리입니다.** 사천왕이 5마리씩, 챔피언 그린이 6마리. 6마리씩인
판본은 레츠고 재대결뿐인데 거기엔 알로라 고지·알로라 딱구리·메가리자몽X가 섞여 있고 이 앱에는
리전폼 데이터가 한 줄도 없습니다. **진짜 26마리가 지어낸 30마리보다 낫습니다.**

**한 사천왕이 한 조우**입니다. 다섯 조우, 25분. 한 조우가 5~6라운드라 연출이 트레이너전과
같은 길이이고, 26라운드를 한 조우에 넣으면 2분이 넘어 팝오버에서 볼 수 없습니다. **HP는
조우를 넘어 이어지고 중간 회복은 없습니다.**

**상대는 내 여섯 중 하나가 쓰러진다고 사라지지 않습니다.** 그 자리에 계속 서 있고 다음 바가
들어옵니다 — 이게 여섯 바가 큰 바 하나보다 나은 이유이고, 처음 짤 때 이걸 빠뜨려서
"상대를 못 쓰러뜨렸는데 이긴 것으로 세는" 버그가 났습니다. 고치고 나니 난이도가 크게 올라
grit을 다시 재서 붙였습니다.

#### 기술머신은 이제 곁들이는 것입니다

**도감의 종은 Lv.100 졸업생이라 레벨업 기술 전부를 무료로 씁니다.** 그래서 리그 파티를 무장시키는
주재료는 기술머신이 아니라 그 종이 스스로 배우는 기술이고, 가방은 그 종이 레벨로는 못 배우는 것을
더해 줄 뿐입니다. 레벨업 기술이 들어오기 전에는 "기술머신 8개로는 최종체 6마리가 17%"처럼
가방 크기가 승률을 갈랐는데, 이제 가방 크기에 따른 차이는 측정 오차 수준입니다. 대신 **무장했느냐가
전부입니다.** 파티에 넣은 포켓몬은 기술 없이 들어오고(`setMember`는 `moves: []`로 시작), 아무것도
배치하지 않은 여섯은 관동 리그를 한 번도 넘지 못합니다.

테스트 하네스는 "현명한 플레이어"를 흉내 내어 가방과 레벨업 기술 중 **위력 × 명중 × 자속 보정**이
높은 4개를 고르고, 충전 턴·반동·역린 계열·자기 능력 하락·첫 턴 전용 기술은 깎아서 봅니다. 위력만
보고 고르면 가방이 커질수록 믿을 만한 자속 기술이 오버히트나 솔라빔에 밀려나 **큰 가방이 더 약하게
재지는** 하네스 착시가 났습니다.

**파티 구성이 크게 작용합니다.** 같은 관동 리그에서 "최종체 6마리"(리자몽·거북왕·이상해꽃·잠만보·
후딘·망나뇽)가 약 25~30%를 넘는 동안 "좋은 6마리"(갸라도스·팬텀·루카리오·한카리아스·자포코일·
망나뇽)는 거의 매번 넘깁니다. 누구를 데려가느냐가 가장 큰 변수입니다.

#### 기술머신은 배치하면 사라집니다

파트너에게 가르치는 것과 똑같습니다. 도감 엔트리가 이미 기록하고 있는 기술은 공짜고 —
그 종이 배운 적이 있으니까 — 가방에서 꺼내는 건 소비됩니다. 파티에서 빼도 **돌아오지
않습니다.** 되돌릴 수 있으면 6 × 4 = 24칸이 결정이 아니라 당번표가 됩니다.

그래서 도감이 졸업할 때 기술을 적기 시작합니다(`DexEntry.moves`). **합집합**이고 덮어쓰지
않습니다 — 도감은 개체가 아니라 수집의 기록이라 "이 종이 배운 적 있는 기술"이 정직한 읽기고,
줄어들 수가 없습니다. 기존 엔트리는 전부 비어 있는데, 그건 어디에도 기록이 없어서 지어낼 수
없기 때문입니다.

#### 지면 도전이 끝납니다

사천왕 셋을 꺾고 목호에게 지면 그 셋도 날아갑니다. 다음 시작 슬롯에서 파티가 만HP로
처음부터 섭니다. 원작은 여기서 "처음부터"인데 그건 15분짜리 재도전을 전제한 규칙이고, 여기서
한 바퀴는 21~62일입니다. **도전은 처음부터 다시 하되 시작 슬롯을 한 다리에 셋 줍니다** —
지는 건 흔하고, 한 달을 잃는 건 드물어야 합니다.

대부분의 도전이 실패로 끝나므로 **어디까지 갔는지를 남깁니다**(`leagueBest`). 실패가 아무것도
남기지 않으면 화면이 할 말이 없습니다.

#### 파티는 도감 탭 안에서 짭니다

새 탭을 만들지 않았습니다. 고를 후보가 전부 도감 그리드에 있으니 **도감이 아닌 화면에서
도감을 고르는 건 틀린 화면**입니다. 도감 · 전설 목록 옆에 파티 칩이 하나 늘고, 그 모드에서는
같은 카드가 다른 일을 합니다 — 상세 화면을 여는 대신 파티에 넣습니다. 파티에 있는 카드는
이로치 카드가 쓰는 그 강조 테두리를 답니다.

### 이름은 지어내지 않았습니다

적록·파이어레드·하트골드는 한국어 정식 발매 이전이라, 관동 8체육관이 전부 한국어로 들어
있는 첫 정식 게임은 레츠고 피카츄·이브이(2018)입니다. 배지 여덟 개와 관장 여덟 명, 팀
스물여섯 마리를 전부 출처와 대조했고 **첫 추측 중 셋이 틀렸습니다** — 그레이배지가 아니라
**회색배지**, 레인보우배지가 아니라 **무지개배지**, 그리고 강연의 것은 영어로 Volcano지만
일본어가 クリムゾン이라 **진홍색배지**입니다.

## 아홉 지방 — 한 지방이 표 한 덩어리가 됩니다

관동 하나로 시작한 캠페인이 아홉 지방이 됐습니다. 체육관 68곳, 사다리 47줄입니다.

**코드는 한 줄도 안 늘었습니다.** `server/gymdata.ts`가 표만 들고 `server/gyms.ts`가
논리만 드는 구조로 먼저 갈라 뒀고, 지방 하나가 순수한 데이터 편집이 되도록 만든 것이
그 갈라 둔 값입니다. 여덟 지방을 넣는 동안 `gyms.ts`에서 바뀐 것은 새 불변식 검사 하나뿐입니다.

### 도전 순서는 원작이 아니라 길입니다

`GymRow`가 `badge`와 `order`를 따로 드는 이유가 관동에서는 두 칸(초련·독수)이었는데,
아홉 지방에서는 **거의 모든 지방이 어긋납니다.** 신오가 가장 심해서 여덟 중 다섯이
다릅니다 — 생성된 길이 운하·들판·물가를 일찍 지나고 연고·장막·선단을 한참 뒤에 지나거든요.
가라르는 원작 5번 포플러가 첫 상대고, 호연은 원작 5번 종길이 첫 상대입니다.

`badge`는 원작 번호 그대로 남습니다. 저장 키이자 스프라이트 파일명이라 바꿀 수 없고,
바꿀 이유도 없습니다.

### 배지 번호는 지방마다 1~8이 아닙니다

하나와 가라르는 관장이 버전마다 갈리는 자리가 있어 **고유 배지가 열 개씩**입니다.
블랙 기준 하나는 33 34 35 37 38 39 40 41이고 소드 기준 가라르는 51 52 53 54 56 57 59 60입니다.
36·42와 55·58은 상류 목록에 있지만 이 표가 쓰지 않습니다. 지방별 1~8 인덱스로는
두 지방을 표현할 수 없고, 이게 전역 번호를 쓰는 이유입니다.

알로라는 배지가 아예 없습니다. 대시련이 Z크리스탈을 주거든요. 78~81을 **저장 키로만**
쓰고, `ensureBadgeSprite`가 77 초과에 null을 돌려줘서 못 딴 칸과 같은 빈 슬롯이 그려집니다.
지어내지 않는다는 규칙이 여기서는 "그리지 않는다"로 나타납니다.

### 리그가 늘 자기 지방에 있는 것은 아닙니다

성도의 포켓몬리그는 석영고원입니다. 닮은 건물이 아니라 관동 사천왕이 앉아 있는 바로 그
고원이고, `RegionRow`에 `leagueIn`이 `ko`와 따로 있는 이유가 이겁니다. 한 정류장에 사다리
둘이 서고 `leagueAt`이 둘 중 아직 안 깬 쪽을 고릅니다.

대가는 긴 걸음입니다. 검은먹시티가 정류장 75이고 고원이 19이라, 여덟 번째 배지와 사다리가
거의 한 바퀴 떨어져 있습니다. **배지함이 8 / 8을 한참 띄워 놓고 기다립니다.** 죽은 시간은
아닙니다 — 그동안 다른 지방의 체육관을 돌거든요.

가라르에는 사천왕이 아예 없습니다. 슛시티의 토너먼트이고 일곱 라운드입니다 —
마리·호브·비트에 관장 셋, 그리고 단델. `leagueKind`가 챔피언컵을 말하고 `LEAGUE_REWARD`가
길이로 나누므로 라운드당 상금은 저절로 맞습니다.

### 상대가 실제로 배운 기술을 씁니다

명명된 트레이너도 야생 포켓몬과 같은 풀에서 뽑았습니다 — 그 종이 머신으로 배울 수 있는
전부에, 자속과 고위력 보정을 얹은 가중 추첨. "방금 뭘 만났나"에는 맞는 규칙인데 리그에는
틀립니다. **타입 상성이 평균으로 뭉개져서 어떤 파티를 데려가든 비슷해집니다.**

하나 사천왕부터 표에 실제 기술을 적습니다(`teamMoves`). 같은 grit에서 표 대신 생성 풀로
돌리면 네 파티의 클리어율이 **최대 28%p씩 움직입니다.** 가방 크기보다 어떤 포켓몬을
데려가느냐가 중요해졌다는 뜻입니다.

**적을 수 없는 칸은 비웁니다.** `server/moves.ts`는 "머신으로 배울 수 있는 기술의 합집합"이라
야습·점프킥·더블촙 같은 레벨업 전용 기술이 존재하지 않습니다. 비슷한 기술로 바꿔 넣으면
표가 자기가 주장하는 것을 더 이상 말하지 않게 되므로, 칸을 버립니다.

### grit은 지방마다 다시 잽니다

관동 열을 베껴 오면 안 됩니다. 관장을 만나는 시점이 지방마다 달라서 그때 들고 있는
기술머신 수가 두 자리에서 네 자리까지 벌어지거든요.

```
관동 웅        조우    47   머신   2
호연 종길      조우 1,457   머신  58
신오 강석      조우 2,537   머신 101
하나 덴트      조우 3,909   머신 150
칼로스 비올라   조우 5,087   머신 203
팔데아 단풍     조우 9,722   머신 389
```

68곳 전부를 **그 지방의 실제 첫 조우 지점 기준으로** 62%를 향해 이분 탐색했고, 41~65%에
들어왔습니다. `test/gyms.test.ts`가 68곳을 매번 다시 잽니다 — 관동 여덟만 재던 테스트를
전 지방 스윕으로 넓힌 것이고, 이 테스트가 없으면 베껴온 열이 전부 90% 위로 올라갑니다.

사다리도 같습니다. 지방마다 사다리 전체에 한 배수를 곱해 파티 네 종의 평균 완주율을 약 40%에
맞췄고, 날씨·랭크·선공이 들어온 뒤, 팀 대 팀 한 판이 된 뒤, 레벨업 기술·특성이 들어온 뒤 한 번씩
더 맞췄습니다. 마지막에는 평균보다 **가장 약한 파티가 5% 위, 가장 강한 파티가 99% 아래**에 드는
배수를 골랐습니다 — 레벨업 기술로 파티 간 차이가 커져서, 평균만 맞추면 한쪽 끝이 밖으로 나갑니다.
관동은 "최종체 6마리"가 20~60%에 들도록 맞춥니다.
가라르 챔피언컵은 일곱 라운드 34마리라 여전히 로스터에서 가장 낮은 열이고, 여기서 어려움은
개별 라운드가 아니라 길이입니다.

### 이름은 한 장씩 대조했습니다

관동 여덟에서 첫 추측 셋이 틀렸던 그 문제가 아홉 지방에서는 훨씬 큽니다. 이름은 20초마다
도는 앱의 메시지 박스에 찍히니까요.

**모아 놓은 페이지는 못 씁니다.** 아홉 지방의 사천왕을 한 번에 준다는 페이지를 받아 봤더니
관동 챔피언을 목호라고 하고, 칼로스 챔피언을 디안시(포켓몬입니다)라고 하고, 한국어 이름
가운데에 가타카나를 섞어 놨습니다. 버리고 **트레이너 한 명당 한 페이지씩** 받았습니다.

그렇게 해서 잡힌 것들입니다.

- 신오 관장 셋이 한 칸씩 밀려 있었습니다. 자두를 전진 자리에, 맥실러를 자두 자리에.
  신오 관장은 전부 식물 이름이고 스모모가 자두라는 게 고쳐진 열이 맞다는 증거입니다.
- 알로라 아칼라의 섬퀸은 **라이치**입니다. 올리비아는 영어 이름이고요.
- 알로라 사천왕은 카히리가 아니라 **카일리**입니다.
- 성도 담청·진청은 근사한 동형이의어라 출처마다 반대로 말합니다. 정류장 96번이
  **담청등대**이고 아픈 전룡이 있는 등대는 진청이 아니라 담청 것이라, 길이 답을 줬습니다.

### 표가 지어낸 칸은 딱 하나입니다

알로라의 `prize`입니다. 대시련은 Z크리스탈을 주는데 이 앱에 Z크리스탈이 없어서, 그 타입에
맞는 머신을 대신 줍니다 — 파이팅Z는 깨뜨리다, 록Z는 스톤샤워. 나머지 67곳의 `prize`는
원작이 실제로 주는 기술머신입니다. 그래서 이 한 칸만 주석에 "골랐다"고 적혀 있습니다.

스타터에 따라 갈리는 자리도 셋 있습니다 — 가라르의 호브와 단델, 알로라의 쿠쿠이박사.
이 앱에는 스타터가 없으니 하나로 고정하고 어느 쪽인지 적었습니다. 관동의 그린이 이미 그렇게
돼 있습니다.

## 전설과 환상 — 조건을 갖춰야 만난다

전설 71종 + 환상 23종, **94종은 그냥 나오지 않습니다.** 조건을 갖춰야 야생에 나타나고,
만나면 **질 수 있는 배틀**이 벌어지고, 이기면 **그 포켓몬의 알**이 남습니다.

```
조건 달성 → 야생 조우 가능 → 배틀에서 승리 → 알 획득 → 알을 품어 키움 → 도감 등록
                    ↑
          전용 도구를 쓰면 다음 조우를 확정 예약
```

**도감 규칙은 안 바뀝니다.** 잡았다고 등록되지 않습니다. 알을 품어 키우고 졸업시켜야
들어갑니다 — 도감의 뜻("떠나보낸 포켓몬")을 지키려고 일부러 이렇게 했고, 전설도 예외가
아닙니다.

### `rarityOfSpecies`는 전설 분류기가 아니었습니다

먼저 고쳐야 했던 것입니다. capture_rate 규칙은 양쪽으로 틀립니다:

```
전설인데 안 걸림   뮤 45 · 세레비 45 · 쉐이미 45 · 코스모그 45 → 귀함
                  네크로즈마 255 · 테라파고스 255 → 흔함
전설 아닌데 걸림   메타몽 35 · 에어아머 25 · 메탕 3 · 패러독스 16종 → 전설
```

그래서 `scripts/gen-legends.ts`가 PokeAPI의 **`is_legendary` / `is_mythical`**을 실제로
가져옵니다. 같은 생성기가 전용 도구 38종의 한글명도 가져오고, 아이콘이 있는지 **HEAD로 직접
확인**합니다 — 스프라이트 저장소는 7세대쯤에서 얇아져서 녹슨검·가면들은 아이콘이 없습니다.
27/38에 아이콘이 있고, 나머지는 다이맥스밴드처럼 글리프를 그립니다.

### 조우 스트림은 한 글자도 안 건드렸습니다

`encounterAt`은 `(k, speciesId, threshold)`에 순수해야 합니다. 두 가지가 거기 매달려 있습니다:
두 프로세스가 같은 구간을 재생해 같은 바이트를 내는 멱등성, 그리고 패널이 옛 로그를 다시 그리는
재생. 드로우 하나만 늘어도 앱이 만든 **모든 조우가 다시 굴려집니다.**

그래서 게이트는 `encounterAt`의 **출력에** 얹습니다 — `stoneAt`이 사는 그 자리입니다.

```ts
const open = openLegends(state);            // 루프 밖에서 한 번
...
const locked = !!legendOf(rolled) && !open.has(rolled);
const wildId = locked ? substituteAt(seq) : rolled;   // 여섯 번째 솔트
```

`substituteAt`은 **전설이 없는 라인에서만** 뽑으므로 재시도 루프가 필요 없습니다. 결과는
`HuntEntry.wildId`에 기록되므로 재생은 계산이 아니라 기록을 읽습니다. 그 김에 `state.ts`가
옛 로그의 등급을 `encounterAt`으로 다시 굴리던 것도 저장된 종에서 읽게 고쳤습니다 — 치환이
과거 로그를 거짓말로 만들 수 없게.

**루트 트레이너는 전설을 안 들고 다닙니다.** 등산가가 아르세우스를 꺼내면 게이트가 한 줄로
무의미해집니다. `rollSpecies`의 `exclude`로 전설 라인을 빼는데, 이건 **드로우를 하나도 더
쓰지 않습니다** — 풀만 좁아지고 뽑기 횟수는 그대로입니다.

### 세 등급, 세 갈래 길

| 등급 | 종수 | 조건 |
|---|---|---|
| 준전설 | 43 | 달성 조건만. 삼신조·레지 3종·카푸 4종처럼 **그룹이 조건을 공유**합니다 |
| 박스 전설 | 28 | 대부분 전용 도구를 **들고 있어야** 열립니다 |
| 환상 | 23 | 가장 무겁습니다. 도감 400~600종 + 전설 N종 등록 |

전용 도구는 38종, 획득 경로가 **일부러 셋으로 갈립니다**:

```
drop   18종  조건을 먼저 채우면 사냥에서 떨어지기 시작 (2.5% ≈ 3시간)
award   7종  업적 보상 (키스톤·부적이 이미 그 자리에 있으니 규칙이 하나로 유지됩니다)
shards 11종  조각이 떨어지고 12개를 모아 합성 (6% ≈ 17시간)
```

**도구가 없는 행도 있습니다.** 원작에 전용 도구가 없는 종에 억지로 붙이면 — 쐐기돌에 갇힌
뮤츠 같은 것 — 원작에 대한 거짓말이 됩니다. 그런 종은 조건만으로 열되, 혼자 설 만큼 무겁게
잡았습니다.

측정치: 조건이 닫혀 있으면 20,000 조우에서 **한 마리도** 안 나옵니다. 조건을 채운 뒤에는 전설
등급 3% 안에서 뽑히니 여전히 귀합니다. 전용 도구를 쓰면 기다림을 건너뛰고 **다음 조우를 확정
예약**합니다.

### 예약은 절대 인덱스로 못박습니다

```ts
forcedNext: { seq: state.huntCount, speciesId }
```

"다음 조우"는 두 writer가 합의할 수 있는 사실이 아닙니다. `hunt()`는 커서 구간을 재생하고,
어느 조우가 예약된 것인지 둘이 같은 답을 내야 합니다 — 절대 인덱스는 그 답이 되고 "다음"은
안 됩니다.

**도구는 이길 때가 아니라 쓸 때 소모됩니다.** 지면 손해가 있어야 배틀이 긴장을 갖습니다.
다만 조건 자체는 남으므로, 돌아가는 길은 도구를 다시 구하는 것이지 전부 다시가 아닙니다.

### 배틀과 알

트레이너전과 같은 구조입니다 — **질 수 있고**, 등급에 따라 grit이 붙습니다(준전설 0.86 ·
박스 0.86 · 환상 1.11). 강한 기술 4개(대폭발·파괴광선처럼 대가가 큰 것은 빼고)를 든 최종 진화
파트너 기준 승률은 준전설 약 60% · 박스 약 35% · 환상 약 30%입니다. 가장 어려운 아르세우스도
스무 번에 한 번은 이깁니다. 이기면
`legendEggs[speciesId]`가 오르고, 가방 '전설' 주머니에서 품으면 `forcedSpecies`가 서서
그 종이 확정으로 부화합니다 — `forcedRarity`·`shinyCharmActive`와 **완전히 같은 수명**입니다.

**전설은 원작에서 만날 때의 기술 4개를 그대로 들고 나옵니다**(`server/legendmoves.ts`). 예전에는
야생처럼 "Lv50까지 배운 공격기 전부"에서 뽑아서, 히드런이 마그마스톰(Lv72) 없이 메탈클로를
휘둘렀습니다. 지금 표는 종마다 **고정 심볼로 싸울 수 있는 가장 최근 본가 게임**의 조우 기술이고,
출처 게임과 레벨을 행마다 적었습니다. 그 4개에 전용기가 없으면 겹치는 기술 하나를 전용기로
바꾸고 그 사실도 적습니다 — 에어로블라스트 없는 루기아는 루기아를 만난 것이 아닙니다. 만날 수
없고 받기만 하는 종(지라치·코스모그 등)은 받을 때의 레벨업 기술을, 진화로만 얻는 종(실버디·
우라오스 등)은 원작 레벨업 규칙대로 마지막 4개를 씁니다. 배틀 레벨은 여전히 50이고, 표의 레벨은
기술의 출처일 뿐입니다. `test/legend-moves.test.ts`가 94종 모두 행이 있는지, 전용기를 들었는지
지킵니다.

**배틀은 화면에서도 재생됩니다.** 정산과 재생이 같은 `legendBattleAt`을 씁니다. 전에는 전설
기록에 재생이 아예 실리지 않아, 장면이 턴 없이 바로 쓰러지는 연출로 넘어갔습니다 — 진 싸움에서도
전설이 쓰러졌습니다. 기술표가 생기기 전에 정산된 기록은 지금 재생하면 결과가 달라질 수 있어서,
재생 결과가 저장된 승패와 다르면 재생을 싣지 않고 결과만 보여 줍니다.

부화 분기는 강제 종이 있어도 **주사위는 그대로 굴립니다.** 건너뛰면 그 뒤의 샤이니·성격
뽑기가 전부 밀리기 때문입니다.

### 화면

조건을 보는 길은 **두 개**이고 둘 다 도감 탭 안입니다. 420px 한 줄에 여덟 번째 탭은
안 들어가고, 전설도 결국 모으는 화면이라 도감 뒤가 제자리입니다.

**격자의 `?` 칸이 첫 번째 길입니다.** 아직 못 만난 전설 94종은 `미수집 포함` 토글과 무관하게
항상 격자에 있습니다 — 볼 수 없으면 목표가 아니고, 목표로 만드는 것이 이 기능의 전부입니다.
누르면 도감 상세 화면의 한 갈래로 조건이 열립니다(등급·세대, 게이지 또는 `조우 가능`, 전용
도구와 그것을 얻는 길, 그리고 알 설명). 이름은 끝까지 `???`입니다 — 무엇을 위한 조건인지는
만나면 알게 됩니다.

미수집 칸이 원래 안 눌리는 이유는 코드에 적혀 있습니다 — *"`mine`은 정의상 비어 있고, 그 칸의
상세 화면은 비어 있거나 '다운로드 없음'이라는 약속을 어긴다."* **잠긴 전설은 정확히 그
예외입니다**: 할 말이 있고(조건은 이미 페이로드의 `legends.gates`에 다 있습니다), 스프라이트를
받을 필요도 없습니다.

**격자에서는 수집한 칸이 먼저, 잠긴 칸이 뒤입니다.** 번호순으로 한데 섞으면 9종짜리 도감이
94개의 `?` 아래로 묻힙니다(첫 실물이 6번째 줄). `미수집 포함`을 켠 화면은 어차피 1025칸이
번호순이라 그 갈래는 그대로 둡니다.

**두 번째 길은 94행 목록**입니다. `[도감] [전설 목록]` 칩 한 줄로 꺼내는데, 가방의 주머니 칩과
같은 어휘입니다. 예전에는 헤더 구석의 밑줄 링크였고 바로 옆 `필터`와 한 덩어리로 읽혀서
아무도 못 찾았습니다. 칩 이름을 `전설`로 줄이면 **도감 필터의 등급 칩 `전설`과 부딪칩니다.**
94행은 **세대별로 묶고** 헤딩이 `N / M`을 말합니다 — 업적 보드와 같은 방식입니다.

가방에는 '전설' 주머니가 생겨 전용 도구 · 조각 · 알 셋을 만나는 순서대로 놓습니다. 비어 있을
때의 안내가 "조건을 채우면"이라고 말하면서 조건을 볼 길이 없었으므로, 그 문장에서 목록으로
가는 링크가 나갑니다. 그리고 가방 탭의 점(`bagCount`)은 `inventory`만 세고 있어서 **첫 금강옥이
떨어져도 안 켜졌습니다** — 전용 도구 · 알 · 합성 가능한 조각을 함께 셉니다.

### 새 필드 다섯 개

`legendItems` · `shards` · `legendEggs` · `forcedSpecies` · `forcedNext`. 전부 optional이라
스키마 번호는 그대로지만, **`migrate`에 이름을 적어야 합니다** — 그 함수는 spread가 아니라
allow-list라서, 안 적으면 20초마다 지워지고 열어둔 게이트가 조용히 다시 잠깁니다.

전용 도구는 `ItemId` 유니온에 넣지 **않았습니다.** 그 유니온은 `shop.ts`와 `game.ts`에 손으로
두 번 적혀 있어서 38개를 더하면 함정이 됩니다. 메가스톤이 폼 id로 키를 잡듯 슬러그로 키를
잡고, 사는 선반이 아니라 확인하는 수집품으로 둡니다.

## 업적

아홉 분야 50개. 달성하면 **소지금**과, 어떤 것은 **아이템**이 들어옵니다.

```
성장    임계값 10 · 100 · 1000배                        🔁 250배마다
여행    성도·호연·신오·하나·칼로스·알로라·가라르·히스이·팔데아, 세계일주  🔁 1,000조우마다
도감    10 · 50 · 150 · 500 · 완성, 아홉 세대            🔁 25종마다
희귀    전설 1 · 10종, 이로치 1 · 3 · 10종, 합체 등록, 숨겨진 특성
트레이너  1 · 10 · 50 · 100승                            🔁 25승마다
배틀    기술 네 칸, 기술머신 30 · 60종 보유
수집    메가스톤 1 · 3 · 10 · 30종, 기술머신 1 · 50 · 200개  🔁 100개마다
육성    졸업 1 · 10 · 50 · 100마리, 이름을 지어줬다, Lv.50,  🔁 10마리마다
        도구로 진화 1 · 10회
상점    첫 구매, 임계값 10 · 100 · 500배 소비              🔁 150배 소비마다
```

**새 카운터는 하나도 안 늘렸습니다.** 쉰 개가 전부 이미 저장돼 있던 값에서 나옵니다 —
`spentTokens`, `dex`의 세대·등급·이로치·별명, `active.moves.length`, 보유 기술머신 종류 수.

레벨·특성·진화 도구가 들어오면서 넷을 더했습니다. `raise-level-50`(Lv.50 — 졸업생이 있으면
이미 지난 것으로 칩니다)과 `raise-hidden-ability`(숨겨진 특성으로 졸업)는 저장된 값에서 나오지만,
**도구로 진화한 횟수만은 새 카운터 `itemEvolutions`**가 셉니다. 진화한 뒤의 종만 보고는 돌로
진화했는지 레벨로 진화했는지 알 수 없어서입니다. 그 전의 진화는 기록이 없으니 0부터 셉니다.

### 🔁 반복 업적

여섯 개는 **끝나지 않습니다.** "25승마다", "1,000조우마다" 식으로 계속 반복되고 달성 횟수가
쌓입니다. 사다리 꼭대기를 본 뒤에도 그 분야에 볼 것이 남습니다.

**상점 사다리는 값을 올린 만큼 위로 늘렸습니다.** 10배·100배는 옛 가격에서 "상점 전체를 다섯
번"이었지만 이제는 전설의 알 하나쯤이라 초반 이정표가 됐고, 그 위에 `shop-500`과 반복
`shop-repeat`을 **더했습니다** — 옛 계단의 번호를 고쳐 달지 않은 이유는, 이미 `shop-10`을
달성해 둔 저장본이 가리킬 곳을 잃기 때문입니다. 표에 없는 id를 가리키는 달성 기록은 번
것을 조용히 잃는 것입니다.

**상한을 두지 않았습니다.** 보상이 지갑행이라 성장을 못 건드리고, 간격이 실제 진행(사냥·졸업·
도감)에 묶여 있어 놀고 있는 기계가 캘 수 있는 것이 아닙니다. 다만 **전부 그 분야 일회성
꼭대기보다 쌉니다** — 반복이 유한한 것보다 더 주면 사다리가 무의미해집니다. 테스트가 그걸
지킵니다.

계단 수는 `floor(have / step)`을 **매번 새로 계산**합니다. `+= 1`이 아니라서 두 번 돌려도,
두 프로세스가 같이 돌려도 두 번 지급되지 않습니다 — `settleAchievements`의 멱등성이 여기에도
그대로 적용됩니다. 앱을 껐던 동안 세 계단을 넘었으면 한 번에 세 번 치릅니다. 오프라인 사냥
백로그가 정산되는 방식과 같습니다.

상태는 `repeats`(id → 지급 횟수)에 따로 둡니다. `achievements`(id → 달성 시각)와 한 칸에
넣지 않은 이유는, 일회성의 뜻이 "언제 열렸나"이고 반복의 뜻은 "몇 번 받았나"라서입니다.
**`migrate`에 이름을 적는 것은 여기서도 필수**입니다.

### 화면 — 분야로 묶어서 봅니다

'전체'일 때는 **분야별로 묶고 헤딩이 `3 / 5`를 말합니다.** 상점의 선반과 똑같은 방식입니다 —
행이 아니라 분야 목록을 필터하고, 칩으로 하나를 고르면 헤딩이 사라집니다. 숫자를 칩에 넣으면
칩 열 개가 세 줄이 되므로 헤딩이 가져갑니다.

**「달성 숨기기」**는 도감의 필터 토글과 같은 자리, 같은 `.linky`입니다. **반복 업적은 숨기지
않습니다** — 끝난 적이 없으니까요. 같은 이유로 반복 행은 흐려지지도 않습니다. 잠긴 것도
끝난 것도 아니라 **언제나 다음 계단으로 가는 중**입니다.

게이지 비율(`ratio`)은 **서버가 계산합니다.** 반복 행의 막대는 전체가 아니라 계단 안에서의
진행도라, 렌더러가 `have / need`로 다시 계산하면 87승이 다음 목표 100 대비 87%로 보입니다 —
실제로는 75에서 100까지 중 48%입니다. 숫자와 막대가 어긋날 수 없게 한 곳에서 냅니다.

**보상은 지갑으로만 갑니다.** `awardTokens`는 `lifetimeOf`에 들어가지 않습니다 — 거기 넣으면
도감을 채우는 것으로 포켓몬이 부화합니다. `bonusTokens`(이상한사탕이 쓰는 칸)도 안 됩니다.
그건 `huntCap`이 재는 대상 밖이라, 공짜로 거기 넣으면 사냥 상한을 통째로 우회합니다 —
`server/trainer.ts`가 트레이너 보상에서 이상한사탕을 뺀 것과 같은 이유입니다.
금액은 상점 가격과 같이 **부화 임계값의 배수**라 헤비 유저든 라이트 유저든 체감이 같습니다.

### 키스톤·다이맥스밴드·반짝반짝부적은 이제 팔지 않습니다

셋 다 **업적 보상으로 옮겼습니다.** 원작에서도 반짝반짝부적은 도감을 채운 대가이고 키스톤은
사람이 주는 물건이지, 돈으로 사는 물건이 아니었습니다. 그래서 반짝반짝부적은 도감 네 계단에
걸려 있고(부화 때 소비되는 일회용이라 한 번으로는 모자랍니다), 키스톤은 **메가스톤 3종**에
붙어 있습니다 — 짝이 될 돌이 하나도 없을 때 주는 키스톤은 빈 물건이니까요.

**상품 목록에서 행을 지우지는 않았습니다.** 가방이 이름·설명·아이콘을 `state.shop.products`에서
찾기 때문에(`product()`·`itemIcon()`), 지우면 이미 가진 사람의 가방에 **이름 없는 칸**이
남습니다. 대신 `award` 플래그를 달아 선반에 안 오르고 `buy()`가 거절합니다. 거절 문구도
"토큰이 부족합니다"가 아니라 "파는 물건이 아닙니다"입니다 — 값을 더 모으면 살 수 있다는
거짓말을 하지 않으려고 지갑 검사보다 **먼저** 봅니다.

### 소급 달성

첫 실행에 이미 넘긴 것이 전부 열리고 보상도 들어옵니다. 따로 짠 코드가 아니라, 판정이
"델타"가 아니라 **지금 상태와 임계값의 비교**라서 저절로 그렇게 됩니다. 그리고 그 비교 방식이
`settleAchievements`를 **멱등**하게 만듭니다 — `electron:dev`에서 Vite와 Electron이 같은
`state.json`에 각자 파이프라인을 돌리는데, 안전이 "둘이 같은 바이트를 계산한다"에만 기대고
있기 때문에 이건 선택이 아니라 요구사항입니다.

**트레이너 승수만 0부터 셉니다.** 승패는 롤링 20칸 로그에만 있었고(약 100분), 재현도 안
됩니다 — `trainerBattleAt`은 그때의 기술과 폼을 받는데 그 둘이 기록돼 있지 않습니다.
화면이 그 사실을 그대로 적습니다.

### 새 필드는 `migrate`에 반드시 적습니다

`achievements` · `awardTokens` · `trainerWins` · `tmsFound` 넷은 전부 optional이라 스키마 번호를
올리지 않지만, **`server/store.ts`의 `migrate`에 이름을 적어야 합니다.** 그 함수는 spread가
아니라 **allow-list**라서, 적지 않은 필드는 다음 로드에서 버려집니다. 업적 표가 20초마다
비워지면 **매 틱마다 보상을 다시 지급**합니다. (개발 중에 실제로 봤습니다 — 새 필드를 모르는
이전 빌드가 아직 떠 있는 채로 새 코드가 상태를 쓰자, 이전 빌드가 종료하면서 넷을 전부
지웠습니다.)

`tmsFound`는 지금 든 기술머신 수를 **바닥값**으로 깔고 시작합니다. `tms`는 배우면 줄어들어
기록이 못 되기 때문인데, 이건 `retiredCount`가 `departedCount(dex)`로 바닥을 까는 것과 같은
수법입니다.

### 업적은 시스템과 함께 갑니다

**id는 영구 키이고 분야는 표현입니다.** 행은 자유롭게 다시 묶어도 되고 실제로 그렇게 했습니다 —
`raise-shiny`·`raise-fusion`은 희귀로 옮겼지만 **id는 그대로**입니다. id를 바꾸면 그걸로 달성해
둔 기록이 조용히 사라집니다.

**시스템을 더하거나 바꾸면 이 표도 같이 고칩니다.** 새 기능이 들어왔는데 업적판이 그대로면
업적판은 그 순간부터 거짓말을 시작합니다. 새 기능이 durable 카운터를 만들었으면 `ACHIEVEMENTS`에
행을 더하거나, 안 더하는 이유를 적습니다. 임계값을 바꿔도 **이미 달성한 것은 회수되지
않습니다** — `state.achievements`는 id로 키를 잡고, 이미 있는 id는 건너뜁니다.

`test/achievements.test.ts`가 기계로 지킬 수 있는 만큼을 지킵니다: 분야마다 최소 하나,
사다리는 오름차순, 상점에서 뺀 셋은 반드시 어떤 업적이 준다(이게 없으면 키스톤을 영영 못 얻는
빌드가 나갑니다), 그리고 두 번 돌려도 보상이 두 번 들어오지 않는다.

## 상점과 가방 — 프렌들리숍 카운터

지갑 = **번 토큰 − 쓴 토큰**. 성장과는 분리되어 있어 **아이템을 사도 진화가 되돌아가지 않습니다.**
가격은 부화 임계값(HT)에 비례하므로 헤비 유저든 라이트 유저든 체감이 같습니다.

**HT를 날로 읽는 법.** `hatchThreshold = 최근 7일 일평균 × 0.15`이므로 (`game.ts:675`)
**코딩 하루 = 6.67 HT**입니다. 이 환산이 없으면 `80×`가 얼마나 비싼 건지 아무도 모릅니다:
전설의 알 80 HT는 **열이틀치 코딩**이고, 흔한 알 5 HT는 **네 시간**입니다.

지갑에 들어오는 것은 딱 둘입니다 — `lifetimeEarned`와 업적 보상(`awardTokens`). **사냥과
이상한사탕은 진행도만 올리고 지갑은 건드리지 않습니다.** 그래서 수입은 6.67 HT/일에 업적
일회성 365.5 HT(≈ 55일치를 한 뭉치로)와 반복 업적 ~1.5 HT/일이 얹히는 모양입니다.

상점 탭은 **카운터**입니다. 선반 앞에 점원이 서 있고, 배틀 화면과 같은 9-slice 메시지 상자로
말을 겁니다. 나머지 화면이 전부 원작의 언어로 말하는데 상점만 설정 화면처럼 생겼던 것을 고쳤습니다.

```
┌ 선반 · 점원 · 카운터 상판 ────┐   ← CSS로 그림, 점원만 런타임 스프라이트
│                소지금 2.47B │   ← 카운터 안에 얹음
└─────────────────────────────┘
╔═════════════════════════════╗
║ 전설의 알               2.14B ║   ← 가리키면 점원이 설명한다
║ "전설"이 보장된 알. …          ║
╚═════════════════════════════╝
[전체][알][성장][진화]
 ▶ 🥚 전설의 알           2.14B     ← 한 항목에 한 줄
```

**설명은 목록 위, 움직이지 않는 자리에 있습니다.** 4·5세대 가방과 구매 화면은 DS 윗화면에
설명·소지금을 두고 아랫화면에 목록을 둡니다 — 설명은 가만히 있고 목록이 그 아래에서 움직입니다.
처음에는 반대로 만들었다가(설명을 화면 하단에 붙임) 목록 위에 얹혀 떠다니는 것처럼 보여서
원작 쪽으로 고쳤습니다. 그 김에 **설명창과 점원 대사창을 하나로 합쳤습니다**: 창 하나에 상태
넷 — 인사, 가리킨 물건, 질문, 감사 인사. 상점에서 실제로 일어나는 일이기도 합니다.

**가리키는 것은 공짜입니다.** 호버와 포커스가 설명을 띄우고(원작에서 커서를 옮기는 것과 같음),
클릭이 질문으로 넘어갑니다. 포커스도 거는 이유는 키보드로도 설명을 읽을 수 있어야 하기 때문입니다.

**창은 상태가 바뀌어도 높이가 변하지 않습니다.** 가장 큰 상태에 맞춘 고정 높이입니다 — 늘어나면
바로 아래 목록이 통째로 밀려서, 누르려던 줄이 커서 밑에서 도망갑니다.

**한 번에 사지지 않습니다.** 줄을 고르면 점원이 값을 부르고 되묻습니다 — 원작의 절차 그대로인데,
여기서는 그게 연출만이 아닙니다. **알을 사면 지금 파트너가 도감으로 떠나는데** 그동안 클릭 한 번에
경고 없이 그렇게 됐습니다. 이제 알을 고르면 파트너 이름이 확인 대사에 들어갑니다:

```
전설의 알 2.14B입니다.
지금 코코리는 도감으로 떠납니다. 괜찮으시겠습니까?   [예] [아니오]
```

구매 결과도 화면 위 토스트가 아니라 **점원의 상자**에 들어갑니다. 3초 뒤 인사로 돌아갑니다.

**점원은 Showdown의 트레이너 스프라이트**(`waitress`, 80×80, 789바이트)입니다. 여기 쓰려고
들여온 `ensureNpcSprite`를 지금은 **트레이너 배틀의 등장 컷도 같이 씁니다**. 배틀 배경·기술
이펙트와 **같은 호스트에서 런타임에 받아 캐시**하며, 다른 자산과 똑같이 **커밋하지 않습니다** —
직접 그리거나 CC0여야 한다는 규칙은 저장소에 담기는 픽셀에 대한 것입니다. 못 받아오면 점원만
없고 카운터·대사·가격은 그대로입니다(`test/ui/tabs.test.tsx`가 그걸 지킵니다).

참고로 BW의 `clerk`는 상점 점원이 아니라 **회사원 트레이너 클래스**입니다. 실제로 카운터 사람처럼
읽히는 건 `waitress`와 `waiter`뿐이라 넷을 받아 눈으로 보고 골랐습니다.

**마트 내부 배경은 받지 않고 그립니다.** Showdown에는 실내 배경이 없습니다(`bg-indoor`·
`bg-pokecenter`·`bg-building` 전부 404). 벽·선반·상판은 그라디언트 몇 줄이라 받아올 것도,
실패할 것도 없습니다. 그리고 그 밝은 카운터가 **다크 모드에서 대사 상자가 놓일 바닥**이 되어
줍니다 — 배틀 화면이 쓰는 것과 같은 해법입니다.

**한 항목에 한 줄입니다.** 원작이 그러듯 아이콘이 왼쪽, 숫자가 오른쪽입니다. 처음에는 가격을
이름 밑에 쌓아서 한 줄이 60px이었는데, 그러면 상품 열 개가 화면 대부분이었습니다.

**커서 자리는 항상 비워둡니다.** 원작이 그러듯 `▶` 칸을 상시 확보합니다. 선택할 때만 자리를
만들면 선택이 옮겨갈 때마다 모든 줄이 옆으로 흔들립니다.

**가리킨 줄은 은은한 면으로만 표시합니다.** 행 전체를 버튼으로 만들면서 `배우기`·`사용` 같은
**알약 버튼**의 채우기 스타일이 행에도 걸린 적이 있습니다 — 60×28 알약을 위해 그린 색이
400×44 행에 칠해지니 바가 물든 것처럼 보였습니다. 지금은 알약 규칙이 `:not(.rowbtn)`으로
좁혀져 있고, `test/panel-css.test.ts`가 그 형태가 돌아오지 못하게 붙잡습니다.

가방도 같은 창을 같은 자리에 씁니다 — 점원만 없습니다(원작에서도 가방은 혼자 여는 화면입니다).

그리고 **주머니로 나눕니다** — 도구 · 중요한 물건 · 기술머신 · 메가스톤. 5세대 가방이
주머니(Case) 다섯 개로 나뉘는 그 구조이고, 여기서는 그게 실제 문제를 풉니다: 기술머신 14개에
도구와 스톤까지 한 칼럼에 쌓이면 가방 하나가 화면 여섯 장이었습니다. 지금은 한 장에 들어갑니다 —
다만 **기술머신 주머니만은 그 약속을 한 번 깼다가 되찾았습니다.** 모으다 보면 한 주머니 안에서
다시 길어지기 때문인데, 거기는 쪽으로 넘깁니다(`### 기술머신` 참고).

### 빈 설명창이 지금 걸린 효과를 말합니다

설명창에는 상태가 셋 있습니다. 무언가를 가리키면 그 이름과 설명, 아무것도 안 가리켰는데
**지금 걸려 있는 효과가 있으면 그 효과**, 둘 다 아니면 `고르면 여기에 설명이 나옵니다.`입니다.

가운데 것이 이번에 생겼습니다. 그전까지 `진화 정지 중` · `다음 부화 샤이니 확률 8배` 같은 줄은
**아이템 목록 맨 아래 회색 한 줄**에 있었습니다 — 화면에서 가장 눈에 안 띄는 자리인데, 내용은
*지금 이 순간 규칙이 다르게 돌고 있다*는 사실입니다. 그동안 화면에서 가장 큰 요소(92px 창)는
누가 마우스를 올려주기를 기다리며 비어 있었습니다. 둘을 바꿨습니다.

**그 김에 버그 하나가 딸려 나갔습니다.** 옛 줄은 조각 셋에 구분자를 각각 붙여 이어서,
마지막 조각이 없으면 `다음 부화 샤이니 확률 8배 · `처럼 **가운데점으로 끝났습니다.**
`filter(Boolean).join(' · ')`이면 그 실패 방식 자체가 없습니다.

### 중요한 물건은 주머니가 따로입니다

키스톤과 다이맥스밴드는 **갖고 있는 것 자체가 효과**라 누를 것이 없습니다(바로 아래
`### 키스톤과 다이맥스밴드는 패시브다` 참고). 그런데 이상한사탕·변함없는돌과 한 목록에 있으면서
혼자 버튼 대신 `보유 중` 배지를 달고 있었습니다 — 한 목록에 성격이 두 가지였다는 뜻입니다.

원작에 이미 이름이 있어서 그대로 씁니다. 이제 **도구 주머니에는 누를 것만** 있고,
**중요한 물건 주머니에는 누를 것이 하나도 없습니다.** 가리키면 설명은 나옵니다 —
이 주머니를 여는 유일한 이유가 그것입니다.

### 자동사냥·사냥 상한은 설정 탭으로 갔습니다

둘은 **아이템이 아니라 설정**입니다. 전에는 그 사실을 인정하면서도 가방 주머니 밖 맨 아래에
뒀는데, 이 앱이 실제로 따르는 규칙은 따로 있습니다 — **컨트롤은 그 주제가 있는 곳에 둔다.**
기술 4칸이 파트너 탭에 있는 이유(`## 상태 화면`)도, 배틀 모습 토글이 설정이 아니라 파트너에
있는 이유(`### 배틀 모습 표시 토글`)도 그겁니다. 사냥의 주제는 가방이 아닙니다.

**설정 탭 맨 위에, `PetSettings` 바깥에 둡니다.** 생김새가 같아서 합치고 싶어지지만 두 줄은
`/api/shop` → `state.json`으로 가고 **웹 빌드에서도 동작**하는 반면, 데스크탑 펫 설정 여섯 줄은
`prefs.json`으로 가고 **Electron에서만** 그려집니다. 안에 넣으면 브라우저에서 통째로 사라집니다.
`server/game.ts`의 `setShowBattleForm` 주석이 왜 `huntEnabled`가 Prefs가 아니라 GameState에
사는지를 이미 적어뒀습니다 — `buildState`는 Prefs를 못 보고, 웹 빌드에는 Prefs가 없습니다.

설명을 제자리에 두는 구분은 그대로입니다: 설정은 제자리에서 설명하고, 아이템 설명은 찾아보는
것입니다. 이제 **설정은 전부 설정 탭에서** 그렇게 합니다.

상점은 **알 · 성장 · 진화** 세 선반으로 나뉘고, 위쪽 칩으로 하나만 볼 수 있습니다.
5세대 프렌들리숍이 계산대 둘로 **공통 상품과 지역 한정 상품**을 나눠 파는 것과 같은 구조입니다.
칩은 도감 필터가 이미 쓰는 언어이고, 다만 **접히지 않습니다**: 10줄뿐인데 클릭 한 번을 더
요구할 이유가 없습니다.

| 선반 | 상품 | 가격 | 하루치 | 효과 |
|---|---|---|---|---|
| 성장 | 이상한사탕 | **요구량의 0.3×** | 아래 절 | 지금 단계 진행도 +25% |
| 진화 | 변함없는돌 | 8× | 1.2일 | 진화·졸업 정지 (토글, 해제는 무료) |
| 진화 | DNA쐐기 | 35× | 5.2일 | 도감에 있는 상대와 합체 (분리는 무료) |
| 알 | 흔한 알 | 5× | 0.75일 | 보장 없음 — 그냥 새로 시작 |
| 알 | 조금 귀한 알 | 12× | 1.8일 | "조금 귀함" 이상 보장 |
| 알 | 귀한 알 | 25× | 3.7일 | "귀함" 이상 보장 |
| 알 | 전설의 알 | 80× | 12일 | "전설" 보장 |
| — | 반짝반짝부적 · 키스톤 · 다이맥스밴드 | **안 팜** | — | 업적 보상 (위 절) |

알을 사면 지금 포켓몬은 도감에 등록되고 떠납니다.

### 값이 여덟 배가 된 이유

**돈이 뜻을 잃었기 때문입니다.** 옛 값으로는 사는 물건 일곱 개를 전부 하나씩 사도 22.2 HT,
**사흘 반치**였습니다. 그런데 업적 하나만 해도 일회성 365.5 HT를 줍니다 — **상점 전체를
열여섯 번** 살 돈입니다. 실제 저장본에서 지갑에 24억(92 HT)이 잠들었고, 가방에는 아무
쓸모도 없는 변함없는돌이 열다섯 개 쌓였습니다.

새 값으로 전부 하나씩은 **165 HT ≈ 25일치**입니다. 지갑이 다시 "무엇을 살까"를 묻습니다.

**알 사다리는 원래 원칙으로 돌아갔습니다.** 이 문서가 줄곧 *"자연 확률(60/25/12/3)에 대략
반비례"*라고 적어놨는데 실제 비율은 1 : 1.9 : 3.75 : 12.5로 어긋나 있었습니다. 5 / 12 / 25 / 80은
**1 : 2.4 : 5 : 16**으로, 진짜 역수(1 : 2.4 : 5 : 20)에 훨씬 가깝습니다.

**메가스톤은 팔지 않습니다** — 사냥으로만 나옵니다. 아래 "특별 진화" 절 참고.

### 한 개만 파는 물건 — `PASSIVE`가 아니라 `UNIQUE`

키스톤·다이맥스밴드는 이제 아예 안 팔지만(업적 보상), **변함없는돌은 팔되 하나만 팝니다.**
`consumeItem`을 보면 그 돌은 **켤 때도 끌 때도 개수를 줄이지 않습니다** — 하나 가지면
영구히 토글이고 두 개째는 정확히 아무 일도 안 합니다. 1.5×일 때는 조용한 낭비였지만 8×는
하루치를 버리는 함정이라, 값을 올리는 변경이 곧 이걸 고쳐야 하는 이유가 됐습니다.

그래서 집합을 둘로 갈랐습니다. `PASSIVE`는 **가방에 누를 것이 없는** 물건이고(키스톤·
다이맥스밴드), `UNIQUE`는 **상점이 두 개째를 안 파는** 물건입니다(`PASSIVE` + 변함없는돌).
변함없는돌은 토글이라 가방 버튼이 있어야 하므로, 둘을 한 집합으로 뭉치면 그 버튼이
조용히 사라집니다. 테스트가 그 구분을 지킵니다.

이미 가지고 있으면 그 줄이 가격 대신 **보유중**을 띄우고 점원이 "이미 가지고 계십니다"라고
답합니다. 판단은 서버가 합니다(`UNIQUE` · `owns`) — 화면이 규칙을 다시 유도하면 두 벌이
되고, 그러면 상점이 `buy`가 거절할 물건을 파는 날이 옵니다. 페이로드의 `owned`도 같은
집합을 봐야 하고, 그게 이 주석이 경고하던 바로 그 어긋남입니다.

**알은 네 등급이 다 있고, 보장은 "정확히"가 아니라 "바닥"입니다.** 산 등급보다 잘 나온
굴림은 그대로 둡니다 — 귀한 알에서 전설이 나올 수 있습니다. 그래서 바닥이 `common`인
흔한 알은 아무것도 보장하지 않고, 그 사실이 곧 그 상품의 정체입니다: 등급을 사는 게 아니라
**교체를 사는** 가장 싼 방법이고, 흔한 포켓몬일수록 성장 배율이 낮아(`RARITY_MULT` 1.0)
가장 빨리 자랍니다.

가격은 자연 확률(60/25/12/3)에 대략 반비례합니다. 사다리는 `RARITY_ORDER` 하나에서 나오고
`Rarity` 유니온 자체가 그 배열에서 파생되므로, 등급을 추가하면 보장 비교가 자동으로 따라옵니다.
`test/shop.test.ts`가 "등급마다 알이 정확히 하나", "비쌀수록 바닥이 낮아지지 않음",
"어떤 알도 바닥 아래로는 절대 안 나옴"을 지킵니다.
이상한사탕이 주는 진행도는 지갑에 들어가지 않으므로 **사탕으로 사탕을 살 수는 없습니다.**

### 이상한사탕은 자기가 주는 만큼 받는다

**가격표에서 유일하게 임계값의 배수가 아닌 줄입니다.** 사탕의 효과는 처음부터
`지금 단계 요구량의 25%`였는데(`shop.ts`가 그래야 하는 이유까지 적어뒀습니다 — 고정 배수는
전설이나 늦은 단계에서 광고한 25%가 아니라 1.7%를 주게 됩니다) **값만 임계값 고정**이었습니다.
요구량은 `4×`에서 `100×`까지 움직이므로, 같은 버튼의 수익률이 이렇게 갈렸습니다:

| 언제 사느냐 | 낸 값 | 받은 진행도 | 배율 |
|---|---|---|---|
| 알 단계 | 0.4 HT | 0.25 HT | **0.6배** — 살 이유가 없음 |
| 흔함 · 1단계 | 0.4 HT | 3 HT | 7.5배 |
| 전설 · 졸업 직전 | 0.4 HT | 25 HT | **62.5배** |

62.5배짜리 버튼은 가격이 아니라 구멍입니다. 24억이면 사탕 230개, 진행도 920억 — 게임을
통째로 건너뜁니다.

그래서 **값의 기준을 효과와 같은 것으로 맞췄습니다.** `Listing.basis`가 `'candy'`이면
`priceOf`가 임계값 대신 `candyGrant(state)` — 지금 사탕 하나가 주는 양 — 를 씁니다. 레벨이
생긴 뒤로 그 양은 **이 파트너의 레벨 하나**(졸업까지 전체 양의 1/99)이고, 알일 때는 부화까지의
25%입니다:

```
값   = 1.2 × candyGrant(state)
효과 = candyGrant(state)          ← 레벨 +1, 알이면 부화 25%
```

어느 상황에 사도 **0.83배**입니다 — 시간을 앞당기는 값으로 20%를 얹어 내는 것이고, 그래서
"돈을 진행도로 바꾸는 것이 최적"인 상태가 생기지 않습니다. 테스트가 *어떤 등급·어떤 단계에서도
받는 것이 낸 것보다 적다*를 전수로 지킵니다.

**표시 가격이 파트너에 따라 움직입니다.** 이건 버그가 아니라 그 물건의 정체입니다 —
페이로드가 20초마다 다시 오므로 자동으로 따라가고, 알 단계에는 `candyGrant`가
임계값의 25%를 돌려주므로 자연스럽게 이어집니다. `priceOf`가 `hatchThreshold` 대신 `state`를
받게 된 이유가 이것 하나입니다.

## 특별 진화 — 메가진화 · 거다이맥스 · 합체

진화에 **두 번째 축**이 생겼습니다. 첫 번째 축은 `stageIndex`가 `pathIds`를 따라 걷는 것이고,
그건 1~1025 기본 종을 절대 벗어나지 않습니다. 폼은 그 옆에 나란히 놓입니다 — **그려지는 것과
불리는 것만** 바꾸고, 도감·희귀도·학습기·진화 라인이 보는 종은 그대로 둡니다.

`server/forms.ts`가 그 테이블입니다(`npm run gen:forms`로 생성, 직접 수정 금지).
**메가 100 · 거다이맥스 34 · 합체 6**, 총 140개.

| | 지속 | 조건 | 저장 |
|---|---|---|---|
| **합체** | 영구 (분리 가능) | 도감에 파트너 + DNA쐐기 | `Companion.formId` |
| **메가진화** | 배틀 한 번 | 키스톤 소지 + 그 종의 메가스톤(사냥) | 저장 안 함 |
| **거다이맥스** | 배틀 3턴 | 다이맥스밴드 소지 | 저장 안 함 |

### 키스톤과 다이맥스밴드는 패시브다

처음에는 변함없는돌을 따라 **착용 토글**로 만들었는데 그게 틀렸습니다. 변함없는돌은 실제로 껐다
켜는 물건이고, 이 둘은 그냥 **가지고 있는** 팔찌와 밴드입니다. 지금은 소지 여부가 조건 전부이고,
가방에서 누를 것이 없습니다 — 눌러도 아무 상태도 안 바뀌는 버튼이 있는 것보다, 버튼을 두지 않고
`보유 중`이라고 적는 편이 정직합니다. 개수(`×1`)도 안 붙입니다: 장신구는 스택이 아닙니다.

그래서 `GameState.keyStone`·`dynamaxBand` 두 필드가 사라졌습니다. 마이그레이션은 필요 없습니다 —
토글은 물건을 가진 사람만 켤 수 있었고 소지는 `inventory`에 남아 있습니다.

**그 대신 우선순위가 뒤집혔습니다.** 둘 다 패시브면 하나를 벗어서 다른 쪽을 고를 수 없으므로,
지는 쪽은 영영 못 보게 됩니다. 둘 다 되는 종은 실측 **4종**입니다(이상해꽃·리자몽·거북왕·팬텀).
그래서 **스톤이 있으면 메가, 없으면 거다이맥스**로 정했습니다. 거다이맥스는 한 번 사면 끝이고
메가는 **그 종의 스톤이 풀숲에서 나와야** 하니, 공들인 쪽이 이깁니다. 그 4종도 스톤을 줍기
전까지는 거다이맥스를 그대로 봅니다.

### 무엇이 모자란지 화면이 말한다

파트너 탭의 "배틀에서" 줄은 조건이 **전부** 충족됐을 때만 나타났습니다 — 도움이 될 수 있는 유일한
순간에 아무 말도 안 했다는 뜻입니다. 지금은 그 종에 폼이 있으면 항상 뜨고, 안 되는 이유를 댑니다:

```
배틀에서   메가저리더프                        ← 준비됨
배틀에서   메가저리더프 · 저리더프나이트 필요      ← 스톤이 없다
배틀에서   메가저리더프 · 키스톤 필요             ← 아이템이 없다
배틀에서   메가저리더프 · 변함없는돌을 빼면 가능    ← 막혀 있다
```

폼이 없는 종은 줄 자체가 없습니다. 천 종에 "없음"을 적는 것은 정보가 아닙니다.

### 스프라이트는 한 줄도 안 고쳤습니다

폼의 PokeAPI **pokemon id가 곧 스프라이트 id**이기 때문입니다. `ensureSprite`는 원래 아무 숫자나
받고, `id <= BW_MAX_ID ? 0 : 1`이 폼 id를 자동으로 Showdown 계층부터 시작시킵니다.
메가이상해꽃(10033)은 앞·뒤·샤이니·뒤샤이니가 전부 있고, 거다이맥스(10195)는 Showdown 뒷모습이
없지만 **기존 폴백이 정적 PNG로 떨어집니다** — 원래 하던 동작 그대로입니다.

### 전투 보정을 지어내지 않았습니다

폼은 **자기 종족값으로** 싸웁니다. `scripts/gen-forms.ts`가 PokeAPI에서 폼마다 여섯 종족값을
받아 `Form.stats`에 굽고, `formOpts`가 그걸 배틀에 넘깁니다.

- **메가는 종족값 자체가 다릅니다** — 메가리자몽X는 공격 130, 특수공격 130으로 원래
  리자몽(84/109)과 배분이 다르고, 타입도 불꽃/드래곤입니다. 예전엔 합계 비율(약 1.19)을
  대미지에 곱했는데, 이제는 실제 배분으로 계산합니다. 야생 조우 토큰은 그 비율을 그대로 받습니다.
- **합체(블랙큐레무 등)도 자기 종족값**으로 싸웁니다. 합체는 배틀 변신이 아니라 이 포켓몬이
  이제 그 모습이라는 뜻입니다.
- **거다이맥스는 종족값이 base와 완전히 같습니다** (525→525). 원작에서 다이맥스는 능력치가
  아니라 **HP 2배**이므로, "**3턴 동안 받는 피해 절반**"이 같은 산수입니다. 이제 야생전도 질 수
  있어서 거다이맥스는 야생에서도 승률을 올립니다.

### 메가스톤은 사냥으로 줍습니다

**만난 야생 포켓몬이 메가진화할 수 있는 종이면, 낮은 확률로 그 종의 메가스톤을 떨굽니다.**
가중치 표가 없습니다 — 희소성이 데이터에서 저절로 나옵니다. 메가는 대부분 최종진화체인데
`encounterAt`이 제곱 굴림으로 미진화체 쪽으로 기울어 있어서, **조우의 약 5%만** 메가 가능한
종입니다. 실측하면 스톤 1개당 약 82조우 = **6.8시간** 사냥입니다(`test/stone.test.ts`).

스톤은 **기술머신처럼 파트너보다 오래 삽니다**. 상한(`huntCap`) 바깥이라 진행도가 상한에
붙어도 계속 모입니다.

`stoneAt`은 **다섯 번째 솔트**를 씁니다. `encounterAt`의 스트림에 draw를 하나만 끼워도
지금까지의 모든 조우가 다시 써지기 때문입니다 — `trainerAt`이 같은 문제를 같은 방법으로 풉니다.

### 합체는 도감이 박스입니다

파트너는 한 마리뿐이라 "둘 다 가지고 있어야 한다"를 옮길 데가 없습니다. 이 앱에서 소유의 유일한
의미는 **키워봤다**이고, 그게 정확히 도감이 기록하는 것입니다. 그래서 지금 파트너가 큐레무이고
도감에 제크로무가 있으면 합체할 수 있습니다.

| base | partner | → |
|---|---|---|
| 큐레무 | 제크로무 / 레시라무 | 블랙큐레무 / 화이트큐레무 |
| 네크로즈마 | 솔가레오 / 루나아라 | 황혼의 갈기 / 새벽의 날개 |
| 버드렉스 | 블리자포스 / 레이스포스 | 백마 탄 모습 / 흑마 탄 모습 |

**파트너를 도감에서 지우지 않습니다.** 도감은 무엇을 키웠는지의 기록이고, 아이템 값을 역사에서
받아내면 그 약속이 깨집니다. 대신 분리가 무료입니다.

**울트라네크로즈마는 합체가 아니라 2단계입니다.** 먼저 솔가레오/루나아라와 합체(영구)하고,
그 다음 배틀에서 울트라버스트(일시)입니다. `Form.from`이 배열인 이유가 이것 하나이고
(`[10155, 10156]`), 이게 원작 규칙을 그대로 옮깁니다. 스톤도 없습니다 — 스톤은 그걸 쓰는 야생
포켓몬이 떨구는데 합체한 네크로즈마는 풀숲에 나오지 않고, 여기까지 온 것 자체가 이미 대가입니다.

합체하면 **타입도 폼을 따릅니다** — 배틀의 타입 상성까지. 패널에는 프시케/강철로 보이는데
싸울 때는 그냥 프시케이면 그건 타입표가 하는 거짓말입니다.

### 도감에는 base 종으로 등록되고, 카드만 떠난 모습을 보여준다

합체한 채로 졸업하면 도감 항목은 **큐레무**로 들어가고, 카드의 **그림과 이름만** 블랙큐레무가
됩니다. 등급·세대·타입 필터·수집률은 전부 base 종 기준입니다 — `generationOf`·`rarityOfSpecies`·
`preEvolutionsOf`·`dexTotal`이 하나같이 1..1025를 전제하고, 그 전제를 깨는 것이 이 설계에서
가장 비싼 일입니다. 닉네임이 "실제로 떠난 형태에만" 붙는 기존 규칙과 같은 생각입니다.

**메가·거다이맥스는 도감에 안 남습니다.** 배틀 한정이라 어디에도 저장되지 않습니다. 도감에
폼으로 남을 수 있는 것은 합체뿐입니다.

**여기 버그가 하나 있었습니다.** `record()`가 `(종, 이로치)`로만 중복을 걸러서, **평범한 큐레무를
먼저 졸업시킨 적이 있으면** 나중에 블랙큐레무로 졸업해도 이미 있다고 보고 빠져나갔습니다 —
`formId`도 닉네임도 **저장조차 안 됐습니다.** 어느 쪽을 먼저 키웠는지가 세이브에 남는 내용을
바꾸는, 가장 조용한 종류의 버그입니다. 지금은 이미 있는 항목이라도 새로 온 쪽에 정보가 더 많으면
채워 넣습니다(덮어쓰지는 않습니다 — 먼저 떠난 개체가 이름을 지킵니다).

그리고 페이로드가 그 `formId`를 **실제로 읽습니다.** 저장은 되는데 아무도 안 읽어서 카드에는
평범한 큐레무가 뜨던 기간이 있었습니다.

### 한글 이름이 없는 49종

메가 97종 중 **49종은 PokeAPI에 한글명이 없습니다**(id 10278 이상, Legends Z-A 신규).
메가스톤 아이콘도 전부 404이고, 거다이맥스는 34종 전부 한글명이 없습니다.

다만 이름 규칙이 **예외 0건으로 규칙적**입니다 — 기존 48종이 전부 `메가`+한글종명(+X/Y/Z),
메가스톤 47개가 전부 한글종명+`나이트`. 그래서 생성기가 **공식 이름이 있으면 쓰고 없으면 합성**합니다.
한 종에 메가가 둘 이상이면 수식어를 붙이는데, 그 한글도 대개 PokeAPI가 다른 폼에 이미 갖고
있습니다(`로우한 모습`, `500년 전의 색` 등 85개). 어써러셔 셋만 어디에도 없어 손으로 적었습니다.

**한글명이 겹치면 생성이 throw합니다.** 수식어를 몰라 조용히 빠뜨리는 것이 유일한 실패 방식인데,
그러면 같은 이름 두 개가 나오므로 충돌 검사 하나가 그걸 전부 잡습니다.

스프라이트는 대응이 필요 없습니다 — 97종 전부 정적 PNG가 있어서 폴백 체인이 그대로 씁니다.
신규 일부가 애니메이션 대신 정지 이미지인데, #650 이상 종에 이미 하던 것과 같은 성질입니다.

**한글 도감 설명이 없는 127종은 답이 다릅니다.** 메가 이름은 규칙이 예외 0건이라 합성할 수
있었지만, 도감 설명은 지어낼 수 없습니다. 그래서 **없는 대로 두고 화면이 상자를 안 그립니다** —
자세한 건 `## 도감`의 `### 상세 화면`에 있습니다.

### 배틀 모습 표시 토글

메가는 5분에 한 번 도는 배틀에서 10초 나타났다 사라집니다. 그런데 이 앱에서 실제로 보는 것은
**떠 있는 펫**입니다. 그래서 파트너 탭에 토글이 하나 있습니다 — 켜면 떠 있는 펫과 패널이 그
모습으로 보입니다. **순수 장식이고 규칙은 아무것도 안 읽습니다**(성격이 이미 같은 자리에 있습니다).
배틀이 정산될 때는 `battleFormOf`를 다시, 정직하게 봅니다.

### 저장 형식

`Companion.formId`, `GameState.stones` / `keyStone` / `dynamaxBand` / `showBattleForm`,
`HuntEntry.stoneId` / `form` — **전부 선택 필드라 `schemaVersion`은 4 그대로**입니다.

다만 `migrate()`는 **화이트리스트**입니다. 필드를 하나씩 적어서 새 객체를 만들기 때문에,
거기 안 적힌 것은 다음 로드에 조용히 사라집니다. 실제로 그랬습니다 — 당시 착용 토글이던 키스톤이 20초마다
스스로 벗겨지고 스톤 수집이 비워졌는데 화면에는 아무 설명이 없었습니다.
`test/shop.test.ts`가 이제 **전부 채운 세이브를 왕복시켜 필드가 하나도 안 없어지는지** 봅니다.
다음에 추가될 필드까지 잡는 모양입니다.
