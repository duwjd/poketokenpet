# PokeTokenPet

AI 코딩으로 태운 토큰만큼 자라는 포켓몬. Windows / macOS 양쪽에서 돌아갑니다.

`~/.claude/projects/**/*.jsonl`을 읽어 토큰을 세고, 알이 부화해 진화하고, 최종 단계에
도달하면 도감에 등록된 뒤 새 알이 나옵니다.

> ⚠️ **비공식 팬 프로젝트입니다.** 닌텐도 / 크리처스 / 게임프리크 / 주식회사 포켓몬 /
> Anthropic 과 제휴 관계가 없습니다. 포켓몬은 그들의 상표이며, **이 저장소와 배포본에는
> 포켓몬 이미지가 하나도 들어 있지 않습니다** — 스프라이트는 실행 중에 사용자 기기가
> 직접 받아 로컬에만 캐시합니다. 코드는 MIT. 전문은 [NOTICE.md](NOTICE.md).
>

## 받아서 쓰기

빌드된 앱은 [Releases](../../releases)에 있습니다. 개발자가 아니어도 됩니다.

| 내 컴퓨터 | 받을 파일 | 안내 |
|---|---|---|
| Mac (M1~M4) | `...-arm64-mac.dmg` | [docs/MACOS.md](docs/MACOS.md) |
| Mac (Intel) | `...-x64-mac.dmg` | [docs/MACOS.md](docs/MACOS.md) |
| Windows | `...-x64-win.zip` | [docs/WINDOWS.md](docs/WINDOWS.md) |
| Windows (ARM) | `...-arm64-win.zip` | [docs/WINDOWS.md](docs/WINDOWS.md) |

**서명하지 않은 빌드입니다.** 첫 실행에서 macOS는 "손상되었습니다", Windows는
SmartScreen 창을 띄웁니다. 넘어가는 방법은 위 두 문서에 한 단계씩 적어뒀습니다.
찜찜하면 아래처럼 직접 빌드하는 쪽이 확실합니다 — 직접 빌드한 앱에는 격리 딱지가
붙지 않아 경고 자체가 안 뜹니다.

**Claude Code를 쓴 적이 있어야** 셀 토큰이 있습니다. 앱은 `~/.claude/projects/`의
토큰 수만 읽고, 대화 내용은 파싱하지 않으며, 아무것도 외부로 보내지 않습니다
([NOTICE.md 4절](NOTICE.md#4-privacy)).

## 실행

**데스크톱 앱** (메뉴바/트레이 + 항상 위에 뜨는 펫):

```bash
npm install
npm run electron:dev     # 개발
npm run app:pack         # release/ 에 앱 생성 (설치본 없이 바로 실행)
npm run app:dist         # dmg / zip 배포본
```

**브라우저**로 쓰고 싶다면 `npm run dev` 후 http://localhost:5173.
Chrome/Edge의 "페이지를 앱으로 설치"로 독립 창도 됩니다.

| 명령 | 설명 |
|---|---|
| `npm run electron:dev` | 데스크톱 앱 (Vite HMR + Electron) |
| `npm run app:pack` | 패키징 (서명 없음, 로컬 실행용) |
| `npm run app:dist` | 배포본 — dmg/zip (mac x64+arm64) · portable zip (win x64+arm64) |
| `npm run dev` | 브라우저 버전 |
| `npm run validate` | **파서를 실측 데이터와 대조.** 숫자가 의심스러우면 제일 먼저 |
| `npm test` | Vitest |
| `npm run gen:species` | PokeAPI에서 진화 데이터 재생성 |
| `npm run gen:moves` | PokeAPI에서 기술머신·종 데이터 재생성 |
| `npm run gen:grass` | CC0 타일셋에서 풀숲 시트 재생성 |

## 데스크톱 앱

### 트레이 / 메뉴바
- **macOS** — 메뉴바에 아이콘 + 오늘 토큰(`355.2M`). 아이콘은 순수 검정+알파
  템플릿이라 다크모드에서 자동 반전됩니다. Dock 아이콘은 없습니다(`LSUIElement`)
- **Windows** — 트레이에 아이콘. **Windows에는 트레이 텍스트가 없어서** 숫자는
  툴팁으로 갑니다. 자동 반전도 없어 라이트/다크 `.ico`를 각각 넣고
  `nativeTheme`으로 전환합니다 (16·20·24·32·48·64·128·256 프레임)

트레이를 클릭하면 팝오버가 뜹니다. 트레이 위치를 기준으로 열되 화면 작업영역 안으로
가둡니다 — **Windows 작업표시줄은 어느 가장자리에나 있을 수 있어서** 위/아래를 가정하지 않습니다.

### 항상 위에 뜨는 펫

| 조작 | 동작 |
|---|---|
| 드래그 | 위치 이동 (자동 저장) |
| 마우스 휠 | 크기 조절 |
| 더블클릭 | 팝오버 열기 |
| 호버 | 이름·진행률·오늘 토큰 표시 |

크기는 64 / 96 / 128 / 160 / 200 / 256px 중에서 고릅니다. 트레이 메뉴와 팝오버 설정에서도
바꿀 수 있고, **가운데를 기준으로** 커지고 작아져 화면을 가로지르지 않습니다.

**왜 창 테두리를 끌어서 크기를 못 바꾸나** — Windows에서 `transparent: true`와
`resizable: true`를 함께 쓰면 투명도가 깨집니다. 그래서 창은 고정 크기로 두고 크기를
프로그램이 바꿉니다. 드래그도 `-webkit-app-region: drag` 대신 IPC로 좌표를 넘깁니다.
그 속성이 `setIgnoreMouseEvents`와 같이 있으면 Windows에서 오작동하기 때문입니다.

**클릭 통과**를 켜면 펫이 마우스를 아예 받지 않아 뒤쪽 창을 그대로 클릭할 수 있습니다.
꺼져 있을 때는 커서가 스프라이트 위에 있을 때만 마우스를 받습니다.

**한 번들, 두 창 — 그래서 CSS도 한 벌입니다.** `main.tsx`가 `#pet` 해시로 갈라 같은 번들을
두 창에 씁니다. Vite는 import된 CSS를 전부 한 파일로 합치므로, 떠 있는 펫 창을 위한
`html, body, #root { background: transparent }`가 **팝오버에도 걸려** 패널의
`background: var(--bg)`를 덮고 있었습니다. 라이트 모드에서는 `--bg`가 흰색과 거의 같아
아무도 몰랐고, 다크 모드에서는 **패널 전체가 흰 바탕에 흰 글씨**가 됐습니다.
지금은 `main.tsx`가 `<html data-window="pet">`을 달고 그 규칙이 거기에만 걸립니다.

상태는 `~/.poketokenpet/state.json`, 설정은 `prefs.json`,
스프라이트 캐시는 `~/.poketokenpet/sprites/` — **양 OS 모두 이 폴더 하나**입니다
(App Support / `%APPDATA%` 분기를 피하려고 홈 dotfolder를 씁니다).

패키징된 앱에는 개발 서버가 없어서 스프라이트는 `petsprite://` 커스텀 스킴으로
캐시 폴더에서 직접 서빙합니다. 시작 시 메인 프로세스가 렌더러와 같은 경로로 한 번
실제 fetch 해보고 결과를 로그에 남깁니다:

```
[poketokenpet]
  tray          ok · title="355.2M"
  pet           128x128 @ 1344,740 · visible=true · onTop=true · clickThrough=false
  sprite fetch  ok 667-w.gif (32576B)
  companion     레오꼬 1/2 · 51%
```

## 토큰을 세는 방법 — 함정 다섯 개

이 다섯 가지를 틀리면 숫자가 조용히 어긋납니다. `npm run validate`가 전부 검사합니다.

**1. `message.id`로 중복 제거하되 마지막 줄을 채택**

Claude Code는 API 응답 1건당 1줄이 아니라 **content block 1개당 1줄**을 쓰고, 각 줄에
같은 `usage`를 통째로 복사합니다. 한 응답이 최대 27줄까지 나옵니다.
중간 줄의 `output_tokens`는 자리표시자(`5, 5, 5, … , 2289`)라서 **마지막 줄만 진짜 값**입니다.

> 그냥 합산하면 **2.2배 과대집계**됩니다.

**2. 날짜는 로컬 시간으로 버킷팅**

타임스탬프는 UTC입니다. UTC 날짜로 묶으면 KST 기준 **약 30% 틀립니다.**

**3. `subagents/*.jsonl`도 포함**

전체 assistant 턴의 **절반 가까이**가 서브에이전트 파일에 있습니다. 빼면 반토막.
메인과 서브에이전트는 `message.id`가 겹치지 않으므로 중복 걱정은 없습니다.

**4. 누적 토큰은 줄어들 수 있다**

Claude Code는 `cleanupPeriodDays`(기본 30일)가 지난 트랜스크립트를 지웁니다. 프로젝트
폴더를 통째로 지워도 그만큼 사라집니다. 그래서 **전체 합계는 단조증가가 아닙니다.**

`진행량 = 현재합계 − 고정기준선`으로 계산하면 정리가 한 번 돌아간 순간 합계가 기준선
아래로 떨어지고, 지워진 만큼을 다시 벌 때까지 게이지가 **영구히 0에 멈춥니다.**
트레이 숫자는 기준선을 안 보고 오늘치만 세니까 멀쩡해 보여서 알아채기도 어렵습니다.

그래서 기준선을 빼는 대신 **폴링 간의 증가분만 누적**합니다 (`accrue()`).
합계가 줄면 그 폴은 0을 더하고 기준점만 새로 잡으니, 바로 다음 토큰부터 다시 셉니다.

**5. 쓰이는 중인 파일의 잘린 마지막 줄**

전량 재스캔은 20초마다 1.2 GB를 다시 읽었습니다 — 코어의 약 16%를, 앱이 떠 있는 내내.
그런데 24시간 안에 바뀐 파일은 184개 중 8개뿐이고, 무엇이 바뀌었는지 알아내는 데는
`readdir` + `stat` 23밀리초면 됩니다. 그래서 파일마다 커서를 듭니다
(`경로 / 크기 / mtime / inode / 바이트오프셋 / 지문 / 기여한 id 집합`).

여기서 **`offset`의 정의가 전부**입니다: "소비됐고 **개행으로 끝난**" 바이트입니다.
아직 쓰이는 중인 마지막 줄은 이월하지 않고 다음 틱에 자기 시작점부터 다시 읽습니다.
그래서 `parseLine`은 미완성 줄을 아예 보지 않습니다 — 방어가 아니라 구조로 없앤 것.

그리고 오프셋은 **바이트**여야 합니다. `readline`은 문자열을 주고 문자열에서는 바이트
오프셋을 복원할 수 없습니다: `Buffer.byteLength(line) + 1`은 CRLF 줄마다 1바이트씩
틀리고(`crlfDelay`가 `\r`을 삼킴), 표본 60개 중 56개에 multibyte가 있으니 문자 길이는
확정적으로 어긋납니다. 그리고 `readline`은 완전한 줄과 잘린 줄을 구별해 주지 않습니다.

무효화 판단 (mtime은 **동등 비교만** — 크기가 1차 신호이고, `>` 비교가 없어서 NTP 점프나
VM 스냅샷에 면역입니다):

| 관찰 | 처리 |
|---|---|
| 커서 없음 | 전량 |
| inode 바뀜 / 크기 줄어듦 | 버리고 전량 |
| 크기 같고 mtime 같음 | 건너뜀 (약 96%) |
| 크기 같고 mtime 다름 | 버리고 전량 (제자리 재작성) |
| 크기 늘어남 | `offset`에서 재개, 지문 확인 |
| 지문 불일치 | 버리고 전량 (한 틱 안에 잘리고 더 길게 재작성) |
| 목록에서 사라짐 | 기여한 id를 걷어냄 → 함정 4번 |

30분마다 전량으로 재조정합니다(0.1% duty cycle). 증분 쪽 실수를 "영구"에서
"길어야 30분"으로 묶는 안전망입니다. 되돌리려면 `~/.poketokenpet/full-scan` 파일을
만들면 됩니다 — GUI 앱은 셸 환경변수를 못 보니까요.

[PokeTokenBar](https://github.com/chattymin/PokeTokenBar) (MIT, macOS 전용)가 같은 데이터를
읽습니다. 설치되어 있다면 `~/Library/Logs/PokeTokenBar.log`에 60초마다 정답이 찍히고,
`npm run validate`가 자동으로 대조합니다.

## 이 앱이 원조와 다른 점

- **Windows에서 돌아갑니다** (원조는 macOS 전용)
- **`entrypoint`별 분리** — VS Code / 터미널 / 데스크톱 사용량을 나눠서 봅니다.
  이 필드가 트랜스크립트 각 줄에 있어서 **과거 데이터까지 소급**됩니다

`entrypoint`는 **표면(surface)** 이지 계정 신원이 아닙니다. "VS Code=계정 A,
터미널=계정 B"처럼 쓰는 경우에만 계정의 대리 지표로 성립합니다. 진짜 계정 귀속은
트랜스크립트에 계정 필드가 없어서 관측 시점에 `~/.claude.json`을 스냅샷해야 하고,
**설치 이후분만** 가능합니다.

## 게임 밸런스

- **설치 기준선**: 첫 실행 시점의 누적 토큰은 기록이지 진행이 아닙니다. 이게 없으면
  기존 기록 때문에 첫 실행에 곧바로 최종 진화해 버립니다. 다만 기준선을 붙박이로 두면
  안 됩니다 — [함정 4번](#토큰을-세는-방법--함정-네-개) 참고
- **부화 임계값 자동 조정**: 최근 7일(활동일 기준) 평균의 15%.
  헤비 유저든 라이트 유저든 1~2시간 사용에 부화하도록 맞춰집니다
- **희귀도**: PokeAPI `capture_rate` 기준 (낮을수록 희귀). 희귀할수록 천천히 자랍니다
- **샤이니**: 1/512. 부화 시 한 번 굴리고 고정됩니다
- **집계 모드**: 기본은 캐시 읽기를 포함한 `활동량`. 캐시가 전체의 ~95%라
  `?mode=billable`로 바꾸면 성장이 훨씬 느려집니다

## 자동사냥과 기술머신

코딩을 안 하는 동안에도 펫이 야생 포켓몬과 알아서 싸웁니다. **5분에 한 번** 조우하고,
기본기만 든 채로 **시간당 부화 임계값의 6%**를 법니다. 앱이 꺼져 있던 시간도 **최대 8시간까지**
소급해서 정산하니 노트북을 닫고 퇴근해도 손해가 없습니다.

**사냥은 토큰을 대체하지 못합니다.** `huntTokens`에 상한이 있습니다:

```
상한 = max(부화 임계값 × 3, 번 토큰 × 0.25)
```

토큰을 쓰는 사람에게는 상한이 사냥보다 빨리 자라서 걸리지 않고, 켜두기만 한 기계에서는
상한에 붙어 멈춥니다. 이게 없으면 아무것도 안 하는 기계가 6일에 한 마리씩 졸업시켜
앱의 전제가 뒤집힙니다. **상한에 걸려도 조우와 기술머신 드롭은 계속됩니다.**

**상한은 설정으로 끌 수 있습니다.** 설정 탭의 "사냥 상한" 토글입니다. 기본값은 적용이고,
끄면 `huntCap`이 `Infinity`를 돌려주어 클램프가 사라집니다. 끄는 것이 **환불은 아닙니다** —
지급되지 않은 조우는 애초에 기록되지 않았고, 지금 와서 소급하려면 상한이 언제부터 물었는지를
추측해야 합니다. 여기서부터 안 자를 뿐입니다.

이걸 여는 이유는, 상한이 **누적이고 절대 줄지 않기** 때문입니다. 초반에 사냥을 많이 돌린
사람은 번 토큰이 자라기 전까지 영구히 붙어 있게 되는데, 그건 "켜두기만 한 기계를 막는다"는
원래 의도와 다른 결과입니다. 무엇을 막고 싶은지는 설계의 의견이지 안전 속성이 아니고,
그 판단은 쓰는 사람 몫입니다.

**그리고 상한에 닿으면 화면이 그렇게 말합니다.** `hunt()`가 `Math.min(room(), …)`으로 잘라
조우마다 `tokens: 0`을 기록하므로, 기록 탭이 "—"로 가득 차고 진행도 바가 멈춥니다 —
설계된 동작인데 아무 설명이 없으면 **버그로 읽힙니다.** 그래서 장면 캡션이 카운트다운 대신
"사냥 진행도가 상한에 닿았다"로 바뀌고(펫은 여전히 걷고 여전히 싸우므로 표지판은 그대로
남습니다), 자동사냥 절이 상한이 왜 안 자라는지를 한 줄로 설명합니다.

**파트너 탭의 숫자는 지금 파트너 것입니다.** 부화한 뒤로 이 아이가 사냥으로 번 진행도와 만난
포켓몬 수입니다 — `huntTokens`·`huntCount`는 졸업해도 초기화되지 않는 누적값이라 그대로 쓰면
"이 아이가 한 일"이 아니라 "이 계정이 한 일"이 됩니다. `bornAt`에서 뽑아낼 수도 없습니다.
그건 `lifetimeEarned + bonusTokens + huntTokens`가 **섞인 스칼라**라 사냥 몫만 되돌릴 수 없거든요.
그래서 부화 순간에 두 카운터를 `Companion`에 스냅숏합니다. `buildState`가 `hunt()`를
`advance()`보다 먼저 돌리므로 알을 깨뜨린 그 배치까지 이미 반영돼 있고, 갓 태어난 파트너는
정확히 0에서 시작합니다.

**단 '사냥 상한'만 누적입니다.** 상한은 "지금까지 사냥이 기여한 전부"를 "지금까지 번 전부"와
재는 값이라 한 마리 몫으로 쪼갤 수가 없습니다. 그래서 그 줄만 `사냥 상한 (누적)`이라고
이름표를 달고 누적 사용량/누적 상한을 쌍으로 보여줍니다 — 위 두 줄과 다른 축이라는 걸
라벨이 말하게 두는 편이, 세 줄이 같은 척하는 것보다 낫습니다.

이미 살아 있던 파트너는 **오늘부터 0에서 셉니다.** 마지막 부화 시점의 카운터를 기록해 둔 것이
없어서 소급할 방법이 없고, 없는 숫자를 지어내느니 지금부터 정직하게 세는 편이 낫습니다 —
`trainerWins`가 같은 이유로 같은 답을 골랐습니다.

알은 싸울 수 없고, 변함없는돌을 차고 있으면 쉽니다. 둘 다 팝오버가 이유를 적어줍니다.

기술머신 말고 **메가스톤**도 여기서 나옵니다 — 만난 야생 포켓몬이 메가진화할 수 있는 종일 때만,
낮은 확률로. 아래 [특별 진화](#특별-진화--메가진화--거다이맥스--합체) 참고.

### 보이는 것 — 여행과 배틀

팝오버 펫 탭 맨 위는 정지된 초상화가 아니라 **장면**이다. 평소에는 펫이 어딘가를 걷고
(두 겹 풀이 서로 다른 속도로 흘러 시차가 생긴다), 조우가 정산되면 그 자리에서 배틀이 벌어진다.

그 "어딘가"는 고정이 아니다. **지역은 사냥이 쌓이면 바뀌고, 색은 시각에 따라 바뀐다.**
아래 "지역과 시간대" 참고.

```
야생   ! → 화면 반전 3회 → 양쪽 등장 → "앗! 야생 OO가 나타났다!"
       → 2~5턴의 실제 배틀 → "쓰러뜨렸다!" → "진행도 +210,227"

트레이너 ! → 화면 반전 3회 → 트레이너 등장 → "낚시꾼 동현이 승부를 걸어왔다!"
       → 물러나고 양쪽 등장 → "낚시꾼 동현은 잉어킹을 내보냈다!" → 배틀 → …
```

### 지금 어디인지는 표지판이 말합니다

원작이 새 지역에 들어설 때 왼쪽 위로 밀어 넣는 그 명패입니다. 지방이 작게 위에, 지역명이
아래에, 왼쪽에는 기둥처럼 액센트 막대가 섭니다. 아래 캡션은 이제 **카운트다운만** 맡습니다 —
장소는 표지판의 일이고, 캡션이 `관동 · 태초마을을 지나는 중 · 다음 조우까지 3분`처럼 셋을
한 줄에 이어 붙이던 것이 원래 무리였습니다.

**에셋은 받아올 수 없어서 그렸습니다.** Showdown에는 배경과 기술 이펙트뿐이고(141개 전수
확인) 표지판류는 없습니다. 다른 곳에 있는 것은 전부 Game Freak 자산의 립이라
`scripts/gen-ui.ts`가 세워둔 규칙에 걸립니다. 그래서 `ui-window`·`ui-plate`를 그린 그
파이프라인에 `ui-sign.png`(16×16, 120바이트)를 한 장 더 그렸습니다. 원작의 둥근 모서리는
재현하지 않습니다 — 픽셀 격자에 둥근 모서리는 없고, `test/panel-css.test.ts`가 시트 전체에서
`border-radius`를 금지합니다. 대신 "표지판"이라고 말하는 디테일 하나, **왼쪽 기둥**을 남겼습니다.
그 막대는 **왼쪽 slice 안에** 들어가야 합니다. border-image는 가운데를 늘리므로, slice 밖으로
나간 막대는 명패 전체에 번집니다.

**도착 애니메이션에 상태 기계가 없습니다.** 엘리먼트에 `key={지방/지역}`을 주면 끝입니다 —
키가 바뀌면 React가 새 엘리먼트를 넣고, 새로 삽입된 엘리먼트의 CSS 애니메이션은 0부터 돕니다.
`.scene-mine.entering`이 쓰는 것과 같은 수법이고, `journey.test.ts`가 "연속한 두 정거장은
절대 같은 곳이 아니다"를 보장하므로 키가 바뀌면 항상 진짜 새 장소입니다.

**그리고 다크 모드에서 배틀 글자가 안 보이던 걸 같이 고쳤습니다.** `.scene`과 마트 카운터는
어느 시각에도 밝은 그림이라 밝은 9-slice 틀을 유지하는데, 그 위 글자가 `var(--ink)`를 쓰고
있었습니다. `--ink`는 다크 모드에서 밝은 색으로 뒤집히므로 **흰 명패 위에 흰 글씨**였습니다.
틀을 되돌리는 규칙은 처음부터 옳았고 그 옆의 색만 조용히 틀렸던 것이라, 뒤집히지 않는
`--ink-lit`을 만들어 셋 다 그걸 쓰게 했습니다.

**한 교환은 두 박자다** — 내 기술, 그다음 상대의 기술. 턴 수에 따라 7~13초.
아무 곳이나 클릭하면 바로 풀숲으로 돌아간다.
`prefers-reduced-motion`이면 연출을 건너뛰고 결과만 말한다.

**"승부를 걸어왔다!"는 배틀당 한 번이고, 그 문장은 자기 박자를 갖는다.** 예전에는 첫
내보내기와 `intro`를 나눠 쓰느라 **사람이 왔다는 문장이 포켓몬 그림 위에 떴다.** 게다가
트레이너가 다음 포켓몬을 꺼낼 때 상태 기계가 `send`에서 `enter`로 되돌아가는데 메시지
분기가 라운드를 안 보고 페이즈만 봐서, 팀원마다 도전 대사가 1.7초씩 다시 나왔다 — 방금
"갸라도스를 내보냈다!"라고 말해놓고서. 지금은 `meet` 박자가 그 문장과 트레이너 그림을
가져가고, **모든 라운드가 똑같이 "내보냈다!"** 를 쓴다. 원작 순서 그대로이고 분기 조건도
하나 줄었다.

**건너뛰는 박자는 이제 술어 하나로 판정한다.** `meet`(트레이너가 없거나 두 번째
포켓몬부터)와 `form`(변신할 게 없거나 두 번째 포켓몬부터) 둘 다 "어떤 배틀에만 있는
박자"다. 예전에는 `form` 하나만 ORDER 워크 직전에 한 칸 앞을 내다보는 특수 케이스로
처리했는데, 바로 앞에 건너뛸 박자가 하나 더 생기면 두 칸을 내다봐야 한다. 술어 + 전진
루프로 바꿔서 셋째 박자가 생겨도 술어에 한 줄만 는다. (`formKind`가 라운드가 아니라
인카운터 단위라 두 번째 포켓몬이 "거다이맥스했다!"를 다시 재생하던 문제도 여기서 같이
막힌다.)

**배틀은 실제로 HP가 닳는다.** `battleAt(seq, rarity, moves, foeSpeciesId, opts)`가
순수 함수로 턴을 만든다:

- 데미지는 **기술의 위력**에 지터(±15%)와 12% 확률의 급소(×1.5)를 얹은 값
- **상대도 자기 기술로 답한다.** 예전에는 이름 없는 "반격" 숫자 하나였다. 지금은
  기술머신 학습셋에서 **그 종이 실제로 배울 수 있는 공격 기술**만 뽑고, 자기 타입을
  세 배 가중한다(STAB 채택률 약 58%). 학습셋이 빈 13종은 몸통박치기로 떨어진다
- **양쪽 다 뽑기 전에 상성표를 본다.** 상성은 오랫동안 데미지에만 적용됐다 — 고르는 데는
  안 쓰여서, 땅 기술을 아는 파트너가 비행 타입에게 그걸 네 번에 한 번씩 영원히 던졌고
  화면은 그때마다 "효과가 없는 것 같다…"라고 말했다. 이제 상성 배수가 **뽑힐 가중치**가
  된다(내 쪽 `MATCHUP_WEIGHT`, 상대 쪽 `FOE_MATCHUP_WEIGHT`).
  갸라도스를 만나면 번개가 77%, 지진이 0.8%다
- **규칙이 아니라 기울기다.** 무효도 가중치가 0이 아니라 0.05다. 항상 최적을 고르면
  `battleAt` 주석이 기록한 그 실패로 돌아간다 — 기술을 돌려쓰던 시절 2000번의 인카운터가
  서로 다른 시퀀스를 두 개밖에 못 만들었고 각본처럼 읽혔다. 바닥값 덕에
  "효과가 없는 것 같다…"도 여전히 게임이 할 수 있는 말로 남는다(약 1%)
- **변화 기술은 이 논쟁에서 빠진다.** 어차피 데미지가 0이고 `statusOutcome`은 타입을
  읽지 않으므로 중립 가중치를 그대로 받는다. 덕분에 나쁜 매치업에서는 공격 기술만
  가중치를 잃어서, 때릴 수단이 없는 파트너가 눈에 띄게 셋업을 한다
- **타입 상성이 양방향으로 문다.** 상대 기술의 상성이 내 타입에 걸린다 — 피카츄의
  번개는 꼬마돌에게 무효고, 꼬마돌의 대지의힘은 피카츄에게 굉장하다.
  무효는 진짜 0이라 "효과가 없는 것 같다"와 바가 어긋나지 않는다
- 반격의 기준점은 여전히 `counterHit`이다. 기술 위력은 ±35%만 흔들고 상성은 온전히 문
  뒤 2.5배로 자른다. 위력 축의 가중 평균은 상성표를 보게 한 뒤에도 **0.981 그대로**다 —
  거기는 손대지 않았다. 다만 상대가 안 통하는 기술을 그만 쓰면서 `foeMult` 전체 평균이
  **0.99에서 1.06으로**, 한 대당 30.9에서 33.4 HP로 올랐다. 의도한 대가이고 실측했다.
  이 축을 조이고 싶으면 `FOE_MATCHUP_WEIGHT`의 위쪽 절반을 완화한다 — `foeMult`나
  `FOE_MULT_MAX`가 아니다. `test/hunt.test.ts`의 봉투 테스트가 그 밴드를 붙들고 있다.
  상대의 데미지 수치는 화면에 안 나오므로 위력 축을 압축해도 읽을 게 줄지 않는다
- 내 HP도 닳지만 바닥값(18%)이 있다 — 사냥은 지는 법이 없는 메커니즘이라,
  바는 "전설이 라타보다 아팠다"를 보여주는 용도다
- **상대 추첨은 별도 RNG 스트림**에서 뽑는다. 루프의 draw가 조건부라 같은 스트림에서
  하나만 더 뽑아도 지금까지의 모든 배틀이 다시 굴러간다.
  `test/hunt.test.ts`의 `GOLDEN` 표가 내 쪽 절반이 안 움직였음을 붙들고 있다
- **상성표를 보게 하면서도 draw는 하나도 안 늘렸다.** 균등 뽑기가 가중 뽑기로 바뀌었을 뿐
  굴림 횟수와 위치가 같다. 그리고 가중치 표에는 **중립(1) 항목이 일부러 없다** — 중립은
  리터럴 1로 떨어지고, 가중치가 전부 1이면 뺄셈 루프가 `Math.floor(roll * n)`을 정확히
  재현한다. 그래서 상성이 할 말이 없는 `GOLDEN` 6행 중 4행은 바이트 단위로 그대로고,
  실제 매치업이 있는 2행만 의도적으로 다시 기록했다

**상태이상은 이름·HP 패널에 배지로 남는다.** 메시지 박스는 한 번 말하고 지나가지만 상태는
계속 걸려 있다 — 특히 독은 매 턴 HP가 깎이는데 왜 깎이는지가 화면에 없었다. 3세대 이후
원작이 하는 그대로, **HP 바 행 끝에 색 배경 + 흰 글자 배지**를 붙인다. 색은 원작 팔레트다
(독 `#A4009A` · 화상 `#EE5533` · 마비 `#9AA400` · 얼음 `#009AA4` · 잠듦 `#AA77AA`).

**비휘발성 상태만 배지가 붙는다.** 혼란·옭아매기·기술봉인은 원작도 패널에 아이콘을 주지
않는다("Volatile status conditions are not indicated by an icon") — 메시지 박스에만 나온다.
실측 12,454건의 배지 중 휘발성은 0건이다. 색만으로 정보를 주지 않도록 플레이트의
`aria-label`에도 상태가 들어간다.

**상태 기술은 데미지가 0이고 대신 효과를 남긴다.** 예전에는 위력이 없다는 이유로 35를
때렸다 — 전기자석파가 상대를 두들기는 게 그래서였다. 지금은 PokeAPI의 `movemeta`에서
가져온 상태 컬럼(`ailment` · `ailmentChance` · `category`)을 읽는다:

| 무엇이 | 어떻게 |
|---|---|
| 독 · 화상 · 악몽 · 조이기 | 남은 배틀 내내 매 턴 상대 최대 HP의 1/16을 긁는다 |
| 마비 · 혼란 · 얼음 그 외 | 상대의 반격이 절반으로, 0.25배까지 누적 |
| 자신 강화(`net-good-stats`) | 내 공격 ×1.2 누적, ×1.8 상한 |
| 회복(`heal`) | 최대 HP의 25% 회복 |

- **공격 기술도 부가 상태이상을 건다** — 기술머신 340개 중 44개가 확률을 갖고 있다.
  화염방사는 10%로 화상을 입힌다. 양방향이라 상대의 폭발펀치가 나를 혼란에 빠뜨린다
- **이미 걸린 상태를 다시 걸려 하지 않는다.** 원작에서도 실패하는 수인데, 예전에는 맹독을
  다섯 턴 내리 던지고 다섯 번 다 실패했다. 지금은 **추첨 전에 그 기술을 후보에서 뺀다** —
  실측 13,811턴에서 낭비된 턴 0회. 후보가 전부 빠지면 그때만 "하지만 실패했다!"가 나온다
- **긁는 데미지는 절대 쓰러뜨리지 않는다** (1에서 멈춘다). 마지막 턴의 `foeHpAfter === 0`이
  "내 스윙이 눕혔다"를 계속 뜻해야 최소 턴 보장과 마무리 규칙이 유지된다
- **상태이상이 턴을 건너뛰게 하지는 않는다.** 턴 수는 모든 길이 불변식이 딛고 선 것이라
  (상대 풀이 내 평균 스윙에 맞춰 잡힌다), 마비가 행동을 날리면 전기 타입을 만날 때마다
  배틀이 조용히 길어지고 튜닝은 그걸 모른다
- 마지막 턴에 상태 기술이 뽑히면 **몸통박치기로 대체**한다 — 상태 기술은 아무도 못 눕힌다
- 상대 HP는 **내 기술 위력에 비례해 스케일된다.** 고정 풀이면 좋은 기술 구성이 흔한
  포켓몬을 한 방에 눕혀서, 애초에 이 배틀을 다시 만든 이유("한 번 툭 때리면 끝")로
  되돌아간다. 희귀도가 길이를 늘린다: 흔함 ×0.75, 전설 ×1.3
- 그래서 **상대 HP의 절대값은 의미가 없다** — 그래서 숫자를 안 보여주고 바만 보여준다.
  원작도 야생 포켓몬의 HP 수치는 안 보여준다
- 보상은 배틀이 정하지 않는다(`encounterAt`이 정한다). 둘은 같은 기술 구성을 읽으므로
  이야기가 어긋나지 않는다: **강한 구성은 더 빨리 이기고 더 많이 번다**
- `encounterAt`과 **다른 시드 솔트**를 쓴다. 스트림을 공유하면 배틀을 조회하는 것이
  "어떤 포켓몬을 만났는가"를 바꿔버려서, 설계 전체가 기대는 재생 성질이 깨진다

- 내 포켓몬은 **뒷모습**, 상대는 앞모습 — 원작과 같다. PokeAPI에 앞모습과 동일한 3단 체인으로
  뒷모습이 있다 (`animated/back/` #1-649 → `showdown/back/` 전 세대 → `back/*.png`)
- 풀은 **진짜 픽셀 아트**다. 아래 "풀숲은 어디서 왔나" 참고
- **발판은 배경을 들어올린 것이지 배경 위에 얹은 도형이 아니다.** 아래 참고

#### 발판은 배경에 없다

원작에서 발판은 원근이 들어간 **원형 디스크**이고, 4세대부터는 배경과 분리되어 밟고 선 지형
타일이 정한다. 우리가 쓰는 젠5 배경 13장에는 그게 **없다** — 흙·풀·바위 텍스처뿐이고,
업스트림에 따로 받아올 base 에셋도 없다. 직접 그려야 한다.

오랫동안 `.scene-pad` 주석은 "elliptical platforms"라고 써 있었지만 규칙에는 `border-radius`가
한 줄도 없어서 실제로는 **각진 사각형 두 개**였다. 그리고 넣을 수도 없다 —
`test/panel-css.test.ts`가 이 스타일시트에서 `border-radius`를 금지한다. 우회할 일도 아니다:
26px 높이의 안티에일리어스 곡선은 픽셀 아트 위에서 흐릿한 얼룩이 된다. 원작 발판도 래스터다.

그래서 **계단 타원 `clip-path`** 하나(`--pad-shape`)를 두 발판이 나눠 쓴다. 높이를 13행으로
잘라 각 행의 반폭을 타원식에서 뽑았고, 좌표가 손으로 편집되다 어긋나면 테스트가 잡는다.

더 큰 변화는 채움 쪽이다. 예전에는 불투명한 `#87a163` 한 색이라 **용암굴에서도 초원에서도
얼음굴에서도 똑같은 초록 타원**이었고, 정확히 그렇게 보였다 — 배경 위에 붙인 UI 도형. 지금은
반투명 밝기 워시 + 아래쪽 어두운 측벽이라, 13장 배경이 각자의 흙과 모래와 용암을 발판 안으로
비춘다. 시간대 필터도 공짜로 따라온다 — `.scene-battle::before`가 이미 아래에 먹여둔 것을
통과해서 보는 것이라, 한밤중에도 정오처럼 밝던 예전 발판과 다르다. `--pad`는 20% 틴트로
남아 둘을 묶는다.
- **8시간 소급으로 96건이 한 번에 정산되면 최신 1건만 연출**하고 나머지는 한 줄로 요약한다.
  전부 연출하면 11분이 걸린다
- 첫 페이로드에서는 연출하지 않는다. 로그는 항상 있으므로, 안 막으면 실행할 때마다 지난
  배틀이 재생된다

떠 있는 데스크톱 펫은 포켓몬만 보여준다. 조우하면 "! 야생 OO"가 잠깐 뜬다. 예전에는 발밑에
풀숲을 깔았지만 투명 창에서 빈 풀숲이 바탕화면 클릭을 잡아먹어서 걷어냈다 — 그래서 시간대
색조도 여기에는 없다. 칠할 배경이 없다. 그때 쓰던 여백 계산은 `pixelFit.ts`에 남아 있다.

### 지역과 시간대

**여정** — 펫은 25회 조우마다 다음 장소로 넘어간다. 그냥 지형이 바뀌는 게 아니라
**포켓몬 세계관을 실제로 걷는다**: 태초마을 → 상록시티 → 상록숲 → 회색시티 → 달맞이산 →
… → 석영고원을 지나면 성도의 연두마을로 넘어가고, 관동 → 성도 → 호연 → 신오 → 칼로스 →
알로라 순으로 이어진다. **240곳 · 한 바퀴 약 21일**이고, 끝나면 태초마을로 돌아온다.
끝나는 여행이면 오래 켜둔 사람이 결국 한 곳에 영영 머물게 된다.

축이 **셋**이다. **어디를 지나는가**는 `src/journey.ts`(생성물)가, **발밑이 어떻게
생겼는가**는 `src/terrain.ts`가, **지평선에 뭐가 걸리는가**는 각 stop의 `sky`가 답한다.
예전에는 `region`이 지형을 뜻했는데 세계관 지방이 생기면서 이름이 충돌해 지형 쪽을
`terrain`으로 개명했다.

**지형과 배경을 따로 분류하는 이유가 핵심이다.** 지형 시트는 존재하는 CC0 픽셀 아트가
상한을 정한다 — 사막 타일셋도 설원 타일셋도 (쓸 만한 팔레트로는) 없다. 배경은 5세대 배틀
배경 15종이라 이미 사막도 얼음동굴도 화산도 있다. 한 축으로 묶으면 **둘 중 나쁜 쪽**에
맞춰야 하므로, 두 축이 각자 낼 수 있는 최선을 낸다:

| 장소 | 발밑(terrain) | 지평선(sky) |
|---|---|---|
| 디그다굴 | `cave` 동굴 | `dampcave` |
| 은빛산 · 석영고원 | `mountain` 산길 | `mountain` |
| 방울탑 · 포켓몬타워 | `ruins` 유적 | `earthycave` |
| 홍련섬 · 하노하노비치 | `seaside` 바닷가 | `beach` · `beachshore` |
| 하이나사막 | `desert` 사막 | `desert` |
| 벨라화산공원 | `mountain` 산길 | `volcanocave` |
| 무인발전소 | `field` 풀숲 | `thunderplains` |
| **얼음길 · 프로스트케이브** | `cave` 동굴 (설원 시트 없음) | **`icecave`** |

마지막 줄이 축을 나눈 값어치다. **쓸 만한 CC0 설원 타일셋이 없다.** 한 축이었다면 저 둘은
풀숲이나 돌길 위를 걸어야 했다 — 얼음동굴 배경 밑에 잔디가 깔린다. 지금은 발밑이 동굴
암반(원작에서도 둘 다 동굴이다)이고, 얼음이라는 사실은 지평선이 말한다.

240곳 중 **173곳**이 지평선을 받고, 나머지 67곳은 `null` — 평범한 들판은 예전처럼 단색
하늘이 더 낫고, `null`이 곧 "다운로드 실패"와 같은 화면이라 실패 경로가 따로 없다.

지형 분포는 town 62 · field 56 · **cave 29** · **seaside 22** · **ruins 20** · **mountain 14** ·
stonepath 13 · forest 9 · flowers 9 · lakeside 4 · **desert 2**. 굵은 것이 새로 생긴 시트고
합쳐서 **87곳**이다. 예전에는 동굴·산·유적·탑 62곳이 전부 `stonepath`(풀 난 자갈길)
하나였고, 바다·섬 19곳이 `lakeside`(풀밭 연못)였다.

**지명은 절반이 없다.** PokeAPI는 지방 10개의 한글명을 다 주지만, 지명은 루트를 뺀 811곳 중
**213곳만** 한글명이 있다(호연·칼로스·알로라뿐). 나머지는 생성기에 손으로 적고 **출처를
확인한 것만** 넣는다 — 확인 안 된 이름은 버린다. 첫 초안이 New Bark Town을 무궁마을로
적었는데 그건 Cherrygrove고 New Bark는 **연두마을**이었다. 조사 중 한국어 위키백과도
보라타운을 Viridian City라고 자신 있게 적어뒀다(보라타운은 Lavender Town). 여정이 짧은 편이
틀린 지명을 띄우는 것보다 낫고, 영문 슬러그가 새는 건 더 나쁘다. 하나·가라르·히스이·팔데아와
신오 대부분은 아직 비어 있고, 생성기 주석에 TODO로 남아 있다.

**저장하지 않는다.** `hunt.count`가 이미 페이로드에 있고 오르기만 하므로 `journeyFor(count)`로
파생시킨다 — 스키마 범프도, 마이그레이션도, 둘이 어긋날 방법도 없다. 지역이 바뀌는 건
시트 URL 하나가 바뀌는 것뿐이고 CSS는 손대지 않는다. 그래서 모든 시트가 48×48에 16px
스트립 3줄(far/near/ground)이라는 **동일한 기하**를 지켜야 한다. 스크롤 키프레임이 정확히
스트립 한 폭만큼 이동하기 때문에, 폭이 다른 시트가 섞이면 매 사이클 튄다 — 생성기가 assert로
막는다.

**시간대** — 새벽(5–9) / 낮(9–17) / 황혼(17–20) / 밤(20–5). 로컬 시각 기준이고, 원작(HGSS·BW)의
구간을 따랐다. 아트는 팔레트가 구워진 픽셀 아트라 토큰으로 다시 칠할 수가 없으므로, **같은
아트에 필터를 씌운다** — 다크 모드가 이미 하던 일(`brightness(0.72) saturate(0.85)`)을 네 단계로
일반화한 것이다. 하늘(`--sky`)은 필터가 닿지 않는 배경색이라 따로 옮긴다.

여기서만 **시각이 OS 테마를 이긴다.** 오후 2시의 다크 모드 사용자는 오후를 보고 있는 것이고,
장면을 둘러싼 패널 크롬은 여전히 테마를 따른다. 시간을 갖는 건 창이 아니라 디오라마다.

필터는 `.scene`에는 절대 걸지 않는다. 스프라이트와 배틀 UI가 자식이라 같이 물들고, 필터가 걸린
요소는 absolute 자식들의 containing block이 되어 배틀 화면이 의존하는 px 오프셋이 전부 흔들린다.
그래서 `.scene-grass` / `.scene-ground`, 그리고 배틀 배경은 `::before` 레이어에만 건다.

갱신은 폴링에 얹는다. 페이로드가 이미 몇 초마다 리렌더하므로 경계는 한 폴 안에 넘어간다 —
그걸 즉시로 만들자고 타이머를 하나 더 둘 값어치는 없다.

[Overworld - Grass Biome](https://opengameart.org/content/overworld-grass-biome) — 저자 **Beast**,
라이선스 **CC0**. `scripts/gen-grass.ts`가 여기서 지역마다 세 조각을 잘라
`src/scenes/{지역}.png`(각 48×48, 1KB 남짓)로 합성한다.

**이건 커밋한다.** `server/sprites.ts`의 규칙("닌텐도 자산이므로 런타임에 받고 절대 커밋·재배포
하지 않는다")과 반대로 가는 이유는, 이게 원작자가 퍼블릭 도메인으로 내놓은 오리지널 픽셀
아트이기 때문이다. CC0는 출처 표기 의무도 ShareAlike도 없다. 의무는 없지만 출처는 생성기
주석에 남긴다 — 커밋된 바이너리가 어디서 왔는지 나중에 검증할 수 있어야 한다.

검색해서 나온 것 대부분은 못 쓴다. DeviantArt·Pinterest에 있는 것은 닌텐도 리핑본이고, 품질이
가장 좋았던 것들은 **CC-BY-SA 3.0**이라 ShareAlike가 MIT 저장소에 얽힌다.

**어느 타일을 왜 골랐나** — 타일셋을 전수 조사해 가로로 반복했을 때 이음선(마지막 열과 첫 열의
RGB 거리)을 점수화했다. 폭을 넓히면 반복 주기가 길어져 이음선이 덜 보이지만 한계가 있다:

```
어두운 긴 풀  1타일:30  2타일:40  3타일:60  4타일:191
밝은 긴 풀    1타일:28  2타일:43  3타일:66  4타일:137
```

3타일이다. 유기적으로 보일 만큼 길고, 이음선이 안 보일 만큼 짧다. 4타일부터 3배로 튄다.

1KB 남짓은 Vite의 `assetsInlineLimit`(4096) 아래라 **data URI로 번들에 인라인된다.** 별도 파일이
없으니 패키지 앱의 `file://` 경로 문제가 원천적으로 생기지 않는다 —
`test/payload-shape.test.ts`가 모든 시트가 4096바이트를 넘지 않는지 지킨다.

이 타일셋만으로는 여정을 다 못 그린다. 저자가 못을 박아 뒀다 — *"we decided to only
focus on one biome, as such this doesn't contain any snow, mountains, deserts or beaches."*
그래서 한동안 달맞이산을 잔디밭 위에 그렸다. 지금은 팩이 넷이다.

**마을 시트 하나만 이 규칙의 예외다.** 여정이 시티를 지나게 되면서, 도시를 아무것도 안 지어진
돌길로 보여주는 것보다는 낫다고 판단해 두 번째 CC0 팩을 들였다 —
[RPG Town Pixel Art Assets](https://opengameart.org/content/rpg-town-pixel-art-assets),
저자 **Luis Zuno(@ansimuz)**, **CC0**(팩 안에 license.txt로 명시), 16×16으로 크기도 같다.
공개된 게 zip뿐이라 생성기가 직접 푼다 — PNG 코덱을 손으로 짠 것과 같은 이유다.

**섞는 범위를 먼 밴드 하나로 묶었다.** 마을 시트는 far(상점가)만 새 팩이고 near(풀)와
ground(돌길)는 기존 타일셋 그대로다. 팔레트 차이가 "거리감"으로 읽히는 줄에만 남고,
앞쪽 두 줄은 다른 지역과 같은 붓이다. 채택 전에 여섯 시트를 나란히 렌더해 눈으로 확인했고,
타일 선택도 이음선 점수로 골랐다 — 지붕이 단독으로는 더 예쁘지만 이음선이 118이라
상점가(23)에 밀렸고, 그림 같던 흰 울타리는 157~202라 탈락해 near가 기존 수풀로 남았다.

**바위와 물가 — 팩 두 개를 더 들였다.** 동굴 29곳 · 바닷가 22곳 · 유적 20곳 · 산길 14곳 ·
사막 2곳, 합쳐서 87곳이 잔디나 연못을 밟고 있었다.

- [Tiny RPG Mountain Tileset](https://opengameart.org/content/tiny-rpg-mountain-tileset) —
  저자 **Luis Zuno(@ansimuz)**, 16×16 탑다운. `cave` · `mountain` · `ruins` 셋이 여기서 나온다.
- [16x16 Overworld Tiles](https://opengameart.org/content/16x16-overworld-tiles-0) —
  저자 **ARoachIFoundOnMyPillow**, **CC0**. `seaside`와 `desert`. 바다와 마른 모래는 바위
  팩에 없다.

**산 팩이 또 ansimuz라는 게 채택 이유다.** 위의 팔레트 논거는 "붓을 섞지 말라"는 얘기인데,
마을 밴드가 이미 이 붓을 받아들였으므로 동굴·산길·유적은 새 붓을 하나도 안 늘린다. 게다가
이 팩 하나에 동굴 입구, 다듬은 석벽, 이끼 낀 절벽이 같은 팔레트로 들어 있어서 정확히 셋이다.

**라이선스에 각주가 하나 붙는다.** OpenGameArt는 ansimuz 팩 둘 다 **CC0**로 기록하고 있고
ansimuz가 저자이자 등록자이므로 그건 저자 본인의 선언이다. 다만 마을 팩과 달리 이 둘의
`public-license.txt`에는 CC0라는 말이 없다. 전문은 이렇다:

> "You may use these assets in personal or commercial projects. You can modify these assets
> to suit your needs. You can re-distribute the file. Credit no required but appreciated it."

생성기 주석에 **그대로** 적어 뒀다. 이 저장소가 실제로 기대는 성질은 둘뿐이고 두 선언이
모두 그 둘을 준다 — **재배포 가능**(그래서 커밋할 수 있다)이고 **크레딧 불필요**(그래서
아래 라이선스 절이 "화면에 크레딧이 없다"고 말할 수 있다). `test/payload-shape.test.ts`가
저 문구와, SOURCES의 모든 URL이 헤더에 적혀 있는지를 지킨다.

**보고 뺀 것들.** Kenney의 [Roguelike/RPG pack](https://kenney.nl/assets/roguelike-rpg-pack)은
CC0를 명시하고 모래와 눈까지 있는데, 평평하고 외곽선이 굵고 채도가 높아서 Beast·ansimuz
옆에 두면 다른 매체로 읽힌다 — Kenney Pixel UI Pack을 스타일 때문에 반려한 것과 같은
이유다(아래 "배틀 UI" 참고). Kenney 팩은 **눈이 있는 유일한 후보**였는데 그래서 탈락했고,
결국 **설원은 시트도 지형 이름도 없다** — 얼음길·프로스트케이브는 동굴 암반 위를 걷고
지평선이 얼음을 말한다. 사막도 같은 운명이 될 뻔하다가 물가 팩의 모래로 살아남았다.
ansimuz 자신의 Warped: Super Grotto Escape Pack은 동굴용 1순위였는데
열어 보니 파란 신전 정문과 밧줄다리·기둥 같은 장식물 모음이라 반복 가능한 암반 팔레트가
아니었다. TajamSoft의 (16x16) Cave tileset은 **OGA-BY 3.0**이라 귀속이 의무다 — 이 프로젝트가
지지 않기로 해 둔 바로 그 의무다.

**고르는 절차는 도구가 됐다.** 마을 팩 때 손으로 하던 전수 조사가 이제 생성기 안에 있다:

```
npm run gen:grass -- --survey mountain --run 3 --top 20 --out /tmp/m.png
   → 불투명한 후보를 전부 이음선·밝기로 채점해 표로 찍고, 후보를 4번 반복해 렌더
npm run gen:grass -- --preview /tmp/scenes.png
   → 완성된 시트 열 장을 나란히 렌더 (README가 적어 둔 "눈으로 확인" 단계)
```

밝기를 같이 찍는 이유는 밴드마다 역할이 있어서다 — 동굴 far는 어두우면서 이음선도 낮아야
하는데, 후보 87개를 눈으로 훑어 그 하나를 찾는 것보다 표에서 고르는 게 빠르다. 새 시트
다섯의 이음선은 far 0~26 · near 0~16 · ground 0~17로, 기존 시트들(61~67)보다 낮다.

**배틀 화면 — 커밋하지 않는다 (닌텐도 자산).**
5세대 배틀 배경 15종을 `play.pokemonshowdown.com/fx`에서 **런타임에 받아**
`~/.poketokenpet/sprites/`에 캐시한다. 스프라이트와 완전히 같은 규칙이고, 실제로 같은
`cacheAsset`(8초 타임아웃 · 10분 네거티브 캐시 · inflight 중복 제거 · temp+rename)을 그대로
쓴다. 같은 디렉터리에 넣으므로 `readSprite`·`cacheStats`·`pruneCache`·`petsprite://`가 배관을
하나도 안 늘리고 그대로 덮는다.

이걸 고른 이유는 **이미 쓰고 있는 BW 애니메이션 스프라이트와 같은 게임의 같은 세대 아트**라서다.
저 스프라이트들이 원래 저 배경 위에 서 있으라고 그려졌으니 색을 맞출 일이 없다. PokeAPI에는
배경이 없고, CC 대체재는 존재하지 않는다.

**어느 배경일지는 조우한 포켓몬의 타입이 정한다** (`server/biome.ts`). 이동 화면이 이미
"내가 어디 있나"에 답하므로, 배틀 화면은 "방금 뭘 만났나"에 답한다 — 매 조우마다 바뀌는 쪽이고,
화면을 볼 이유가 되는 쪽이다. 복합 타입은 **먼저 적힌 타입이 이긴다**: 풀이 독보다 앞이라
이상해씨는 동굴이 아니라 초원에 서고, 물이 얼음보다 앞이라 라프라스는 얼음동굴이 아니라 강에
선다. 그 순서가 설계 전부고, 바꾸는 방법도 그 배열을 바꾸는 것뿐이다.

**받지 못해도 깨지지 않는다.** `.scene-battle`의 기존 그라디언트가 그대로 아래에 남아 있고
배경은 그 위의 `::before` 레이어다. 다운로드가 실패하면 `--battle-bg`가 없어 아무것도 그리지
않으니, 화면은 이 기능이 생기기 전과 **정확히 똑같다**. 팬 운영 서버에 기대는 외부 의존이라
이 성질이 중요하다. 옮기고 싶으면 `server/sprites.ts`의 `BG_BASE` 한 줄이다.

`test/payload-shape.test.ts`가 `bg-*.png`가 저장소에 커밋되는 것을 막는다.

### 기술 이펙트

같은 디렉터리에서 **기술 이펙트 18종**도 받는다 (`ensureEffect`). 배경의 형제 파일들이라
호스트도 규칙도 늘지 않는다 — 런타임에 받아 `fx-*.png`로 캐시하고 커밋하지 않는다.
18개 합계 **97KB**, 첫 취득 234ms.

**PokeAPI에는 기술 아트가 없다.** 스프라이트 저장소가 badges·items·pokemon·types뿐이다.
3세대 애니메이션 팩이나 Essentials 라이브러리처럼 있는 것들은 전부 닌텐도 프레임 리핑본이고,
진짜 CC0인 선택지(OpenGameArt "Pixel Art Spells")는 일반 판타지 16×16이라 5세대 배틀과
전혀 안 붙는다. 그래서 배경과 같은 결론에 같은 방법으로 도달한다.

**무엇을 그릴지는 세 가지가 정한다** (`server/movefx.ts`, `server/biome.ts`의 형제):

| 정하는 것 | 어디서 | 결과 |
|---|---|---|
| 어떤 그림 | 기술 **타입** 18종 | 불꽃 `flareball` · 전기 `lightning` · 벌레 `web` … |
| 어떤 형태 | 기술 **분류** | 물리는 상대 위에서 터지고, 특수는 날아가고, 변화는 시전자에게 핀다 |
| 어느 쪽 | 연출 **위상** | `turn`이면 상대에게, `counter`면 나에게 |

빗나갔거나 상성이 0이면 **아무것도 안 띄운다.** 메시지 박스가 이미 "빗나갔다" · "효과가 없는
것 같다"를 말하고 있는데 그 위에 타격을 그리면 서로 모순된다.

**스프라이트는 건드리지 않는다.** 예전에 스프라이트를 돌진시키고 대상을 깜빡이게 했다가
"맞았다"가 아니라 "다시 나타났다"로 읽혀서 걷어낸 적이 있다. 이건 별도 레이어(z-8, 포켓몬
위 · 메시지 박스 아래)라 그 실패와 다르다. 둘 중 하나라도 다시 움직이면 그 문제가 그대로 돌아온다.

상자 크기는 **원본의 실제 그림 영역을 재서** 타입별로 보정했다. `rocks`는 100×100 캔버스
안에 조약돌이 59×40뿐이라 그대로 두면 얼룩이 되고, `lightning`은 62×226이라 정사각형에
넣으면 실오라기가 된다. 84% 이상 채우는 나머지는 손대지 않았다.

받지 못하면 그냥 안 나온다 — 배경과 같은 성질이다.

## 상태 화면

펫 탭이 원작 요약 화면 역할을 한다. 탭은 늘리지 않았다 — 420px 패널에 6개가 이미 빡빡하다.

```
[장면]
우리레오 ✏️              ← 연필을 누르면 인라인 편집, Enter 확정 / Esc 취소
화염레오 · Pyroar · 임금포켓몬
[불꽃] [노말]

[진행바] 졸업까지 ...

상태    단계 2/2 · 희귀도 · 성격 · 1.5m 81.5kg · 함께한 진행도 · 만난 야생 포켓몬
기술    누르기  노말 · 물리 · 위력 85 · PP 20      ← 읽기 전용
```

`server/moves.ts`가 종별 **타입·한글 분류·키·무게**를 함께 담는다(1025종 전부, +44KB).
PokeAPI는 키를 데시미터, 무게를 헥토그램으로 주므로 생성 시 각각 10으로 나눈다.

**타입 색은 원작 18색을 쓴다.** 다만 채운 색이 아니라 **틴트**다 — `color-mix`로 각 색을
패널 배경 쪽으로 대부분 되돌린다. 420px 패널에 채도 높은 블록 18개를 그대로 넣으면
협박 편지가 된다. 기술 목록의 각 행도 왼쪽 3px 테두리로 자기 타입 색을 갖는다.

이 때문에 **패널 팔레트를 손봤다.** 원래는 따뜻한 크림색에 `#d9773d` 강조색이었는데 두 가지
문제가 있었다: 따뜻한 캐스트가 모든 타입 색을 주황 쪽으로 물들이고, 그 강조색이 불꽃 타입의
`#EE8130`과 몇 도 차이라 **강조 버튼과 불꽃 배지가 같은 것으로 읽혔다.** 그래서 중성색은
따뜻함을 뺐고(약간 차가워져서 초록 풀숲이 붙여넣은 것처럼 보이지도 않는다) 강조색은 어떤
타입도 소유하지 않은 **틸**로 옮겼다. 틸은 원소가 아니라 인터페이스로 읽힌다.

**기술 4칸은 파트너 탭이 관리한다.** 기술 구성은 파트너의 것이니까 파트너 화면에 있어야 한다.
가방은 기술머신을 들고 있고, 슬롯이 꽉 찬 채로 기술머신을 쓰면 **가방 안에 간소한 선택기**가
잠깐 나타난다 — 슬롯 목록을 가방에 한 번 더 복사하지 않기 위해서다.

**사냥 기록은 기록 탭에 있다.** 파트너 탭에 8줄씩 깔면 파트너 자신의 정보가 묻히고, 위쪽 장면이
이미 가장 최근 조우를 실시간으로 재생한다. 파트너 탭에는 한 줄 요약과 기록 탭으로 가는 링크만
둔다. 기록 탭은 기본 5건이고, 펼치면 20건 전부와 함께 주운 기술머신·메가스톤까지 보여준다.

**줄마다 정지 스프라이트가 하나씩 붙는다.** 24px(= 96 × ¹⁄₄, `ZOOM_LADDER`의 가장 작은
눈금이자 `--ctl`)이고 `ensureStaticSprite`가 받는 96×96 PNG다. 애니메이션 GIF는 평균 49KB에
최대 565KB라 20줄이면 1MB짜리 페이로드가 20초마다 오가지만, 정지본은 **평균 1.7KB**라 20장을
다 받아도 34KB — 이미 34MB인 캐시 옆에서는 반올림 오차다. 그래서 `state.ts`의 "가장 최근
항목만" 규칙은 **애니메이션에만** 적용되고, 목록의 정지 썸네일은 전부 받는다. 두 규칙이
갈라진 자리라 주석에도 그렇게 적혀 있다.

`.hunts > li`가 9-slice 때문에 켜진 `image-rendering: pixelated`를 글자용으로 되돌리므로
아이콘 안에서 **다시 켜야** 하고, 행이 `align-items: baseline`이라 교체 요소를 그냥 넣으면
옆 글자가 12px 내려앉는다 — 아이콘만 `align-self: center`로 맞춘다.

**어떤 기술로 이겼는지는 더 이상 적지 않는다.** 그 줄을 만들려면 로그 항목마다 `battleAt`을
통째로 재생해야 했다 — 20건 × 매 페이로드 빌드. 이름 옆의 기술 이름 하나를 위해 치르기에는
비싼 값이고, 배틀 연출이 바로 위에서 같은 싸움을 이미 보여준다.

### 성격

부화할 때 **25종 중 하나**가 정해지고 그 뒤로 바뀌지 않습니다. 오래 12종만 들고 있었는데,
손으로 적힌 목록이라 절반이 빠져 있었습니다 — 지금은 `scripts/gen-species.ts`가 PokeAPI에서
**한글명까지 같이** 가져옵니다(`NATURES`·`NATURE_KO`). 한글명이 하나라도 없으면 생성이
throw합니다: 조용히 슬러그로 떨어지면 한국어 화면에 `sassy`가 새어 나오기 때문입니다.

**순수 장식입니다.** 배틀도 성장도 성격을 읽지 않습니다. 원작은 성격으로 능력치 두 개를
±10% 밀지만 이 앱에는 밀 능력치가 없어서, 옮겨오려면 없던 메커니즘을 새로 지어내야 합니다.
그건 성격이 하려는 일(개체마다 다르다는 표시)보다 큽니다.

한글 변환은 **서버에서** 합니다(`server/state.ts`). 렌더러는 생성 테이블을 import할 수 없고,
바로 옆 `speciesName`이 이미 같은 이유로 같은 자리에서 해석됩니다.

### 정렬 축은 하나다

"좋긴 한데 어수선하다"는 지적을 받고 세어보니 원인이 숫자로 나왔습니다 — **간격 19가지 값이 84개
선언에**, 패딩 좌우 5종·상하 5종, 컨트롤 높이 5종. 그리고 진짜 원인은 따로 있었습니다.

**`.app`이 가운데 정렬이 기본이고 여섯 곳이 좌측으로 되돌리고 있었습니다.** 그래서 눈이 따라갈
왼쪽 선이 하나도 없었습니다 — 상점을 내리면 선반 제목 `알`은 가운데, 그 아래 행은 왼쪽, 다음
제목은 다시 가운데로 튑니다. 지금은 **기본이 좌측**이고 가운데 정렬은 **정말 그림인 것 둘에만**
옵트인입니다: 파트너 초상(`.portrait`)과 도감 카드 격자.

`<button>`은 페이지의 `text-align`을 **상속하지 않는다**는 게 여기서 한 번 물었습니다. UA가
`center`를 걸어두기 때문에, 기본을 왼쪽으로 뒤집자 모든 행 라벨이 가운데로 갔습니다.
`.items .rowbtn`에 명시적으로 왼쪽을 다시 걸어야 했습니다.

### 토큰

```
--s1..--s6        2 · 4 · 8 · 12 · 20 · 32px   간격
--pad-box  8px    상자 안쪽 (3px 틀 + 8px = 글이 항상 11px에서 시작)
--pad-tight 4px   컨트롤 안쪽
--ctl      24px   칩 · 작은 버튼 · 배지
--ctl-lg   32px   탭 · 액션 버튼
```

**`--pad`가 아니라 `--pad-box`인 이유가 있습니다.** Scene.css도 `:root`에 쓰는데 거기 `--pad`는
**배틀 발판의 초록색**이고, Scene.css가 나중에 로드됩니다. 그래서 `--pad`로 두자 패널의 모든
`padding: var(--pad)`가 색으로 해석돼 통째로 무효가 됐습니다 — 에러가 아니라 "칩이 답답해 보인다"로
나타나는 종류의 사고입니다. `test/panel-css.test.ts`가 이제 **두 스타일시트가 토큰 이름을 공유하지
않는지** 검사합니다.

### 스크롤바가 오른쪽에서 10px을 먹고 있었다

왼쪽 선을 하나로 모으고 나니 이번엔 화면이 **왼쪽으로 치우쳐** 보였습니다. 착시가 아니라
산수였습니다.

`::-webkit-scrollbar`에 폭을 지정하는 순간 macOS의 오버레이 스크롤바가 아니라 **자리를
차지하는 고전 스크롤바**가 되고, 그 폭은 content box에서 빠집니다. 그래서 패널 내용은 왼쪽
12px, **오른쪽 12+10=22px**이었고, 스크롤하지 않는 탭 바는 12/12 그대로였습니다 — 탭 바의
오른쪽 끝과 그 아래 내용의 오른쪽 끝이 서로 다른 x에 있었습니다.

게다가 `overflow-y: auto`는 넘칠 때만 바를 그리므로 **짧은 탭은 12/12, 긴 탭은 12/22** —
탭을 바꿀 때마다 화면이 10px 옆으로 튀었습니다.

```css
.tabpanel {
  scrollbar-gutter: stable both-edges;   /* 항상 · 양쪽 다 */
  padding: var(--s4) var(--s2) var(--s6);
}
```

`stable`이 넘치든 안 넘치든 칸을 예약하고, `both-edges`가 반대쪽에도 같은 폭을 둡니다.
gutter는 *border 안쪽과 padding 바깥 사이*에 놓이므로 내용까지의 거리는 양쪽 다
`gutter + padding`입니다. 그래서 레일 폭에 이름을 붙이고 패딩을 그 보수로 잡았습니다:

> **`--s2`(4) + `--rail`(8) = `--s4`(12) = 탭 바의 좌우 패딩**

이 식이 정렬의 전부라서 `test/panel-css.test.ts`가 **값이 아니라 합**을 검사합니다. 레일을
10px으로 되돌리면 그 순간 빨간불이 켜집니다.

측정으로 확인한 결과 여섯 탭 전부 · 제목·카운터·대화창·칩·행 전부가 창 양 끝에서 12/12입니다.

> **헤드리스로 재현하려다 한 번 속았습니다.** `--hide-scrollbars=false`를 줬는데 Chrome은
> 이 스위치를 *있으면 켜짐*으로 읽어서 스크롤바를 숨겨버렸고, 고치기 전 CSS가 0px을 먹는
> 것으로 나왔습니다. 플래그를 아예 빼고 나서야 10px이 보였습니다.

### 그 김에 — 행도 진짜로 11px에서 시작하게

위의 `--pad-box` 절에 "모든 상자가 11px에서 시작한다(전에는 행이 15px)"고 써두었는데,
**행은 실제로 아직 15px이었습니다.** `.items li`에 `padding-left: var(--s4)`가 따로 남아
있었고, 주석은 "왼쪽 등급 띠 자리"라고 했지만 **띠는 `left:3px`에서 폭 3px이라 6px에서
끝납니다.** 8px 패딩이면 글이 11px에서 시작해 띠와 5px 떠 있어 충분합니다.

`.items li.row`의 20px은 그대로 뒀습니다 — 그건 여백이 아니라 `▶` 커서가 들어갈 칸이고,
게임 메뉴가 늘 그렇게 합니다. 다만 `--s5`(섹션 간격)로 적혀 있어서 여백처럼 보이던 것을
`--gutter-cursor`로 이름만 바꿨습니다.

### 폰트 — 갈무리

OFL은 CC0 풀숲 타일(`scripts/gen-grass.ts`)과 같은 등급입니다 — 저자가 재배포를 허락한 원작이라
**커밋합니다.** 런타임에 받아 캐시만 하는 포켓몬 스프라이트와는 다른 층위입니다.

**모노스페이스 쪽을 씁니다.** 이 패널이 찍는 것의 태반이 토큰 수·가격·퍼센트라, 글자폭이 고정되면

**556자 중 554자**를 덮고, 완성형 한글은 11,172자 전부입니다. 빠지는 하나는 ✏️ 이모지인데 그건

바꾸기 전에는 `font-size` 선언 35개에 값이 15가지(.46~1.7rem)였습니다. `rem`은 루트 크기에 따라
달라져서 비트맵에는 쓸 수 없으므로 전부 px입니다. 그리고 안티에일리어싱을 끕니다

8px이 있는 이유는 배틀 이름판이 152px 폭에 6px 게이지를 물고 있어서입니다. 그 안의 초소형 라벨
둘이 10px에서 안 들어가는데, 아무도 불평하지 않은 화면을 다시 짜는 것보다 309KB짜리 얼굴 하나를
더 싣는 편이 나은 거래였습니다.

### 크롬 — 여전히 직접 그립니다

**진짜 포켓몬 UI 스프라이트는 쓰지 않습니다.** spriters-resource·Pokémon Essentials·decomp
모드에 널려 있지만 전부 닌텐도 디자인의 rip이고, 런타임으로 받을 출처도 없습니다(PokeAPI와
Showdown은 UI를 서빙하지 않습니다). [Kenney Pixel UI Pack](https://kenney.nl/assets/pixel-ui-pack)은
CC0라 법적으로는 깨끗하지만 판타지 RPG 스타일이라 **쓰면 지금보다 덜 포켓몬 같아집니다.**

그래서 `scripts/gen-ui.ts`를 넓혔습니다. 기존 `frame()`이 메시지 창을 그렸다면, 새 `plain()`은
테두리 한 겹과 채움에 **빛 받는 쪽 하이라이트 한 줄**을 넣습니다 — 픽셀 버튼이 튀어나와 보이는
장치가 그것뿐입니다. 누르면 하이라이트가 반대편으로 가서, 아무것도 움직이지 않고 눌린 것처럼
보입니다.

메시지 창이 테두리를 두 겹으로 그리는 것과 대비됩니다: 26px 버튼이 그러면 대부분이 테두리입니다.

**둥근 모서리는 전부 없앴습니다** — App.css 17개, Scene.css 8개, PetApp.css 1개. 픽셀 격자에
가장 안 어울리는 것이고, 모서리는 9-slice가 대각선으로 깎아 표현합니다. 포커스 링도 각졌습니다.
`test/panel-css.test.ts`가 세 시트에서 `border-radius:`가 다시 나타나면 빌드를 떨어뜨립니다.

정말로 둥글어야 하는 것이 딱 하나 있습니다 — 배틀 발판입니다. 그건 `border-radius`가 아니라
**계단 타원 `clip-path`**로 그립니다. 위 "발판은 배경에 없다" 참고.

### 팔레트 — 바닥과 표면을 가른다

`--bg` 하나가 **페이지 바닥**이자 **타입 틴트가 섞여 들어가는 대상**이었습니다. DS 화면처럼 색
있는 바닥 위에 크림색 창이 올라가면 그 둘은 더 이상 같은 것이 아닙니다:

```
--ground    패널이 깔리는 색 바닥. 탭마다 다르다
--surface   창 내부. 내용이 실제로 얹히는 면
```

**모든 `color-mix`는 `--surface`를 향합니다.** 타입 배지는 창 *안에* 있으니까요. 그래서 README가
공들여 고른 18개 타입 색과 4개 등급 색의 관계는 **그대로 보존되고** 바닥만 바뀝니다. 강조색 틸도
유지했습니다 — "어떤 타입도 소유하지 않은 색"이라는 근거가 아직 맞고, 바꾸면 18색을 전부 다시
검증해야 합니다.

바닥은 탭마다 다릅니다(원작이 가방 주머니마다 색을 주는 것과 같은 생각). 채도는 낮게 잡았습니다 —
그 위에 18개 타입 색이 올라가야 하고, 팔레트 절 전체가 "크롬이 내용보다 소리치지 않게"에 관한
이야기입니다.

**여기서 두 번 걸렸습니다.** 하나, `--ground`를 `.app`에 걸고 배경은 `body`에 칠하고 있었는데
자식에 설정한 커스텀 속성은 부모에 닿지 않습니다 — 모든 탭이 자기 색을 가진 줄 알았지만 실제로는
`:root` 기본값만 칠하고 있었습니다. 둘, 다크 모드 크롬 오버라이드를 파일 앞쪽에 뒀는데
**미디어 쿼리는 명시도를 더하지 않아서** 뒤에 쓰인 같은 선택자에 집니다 — 다크 모드에서 행이
밝은 틀을 쓴 채 밝은 글자를 얹어 안 보였습니다. 지금은 파일 맨 끝에 있습니다.

### 목록은 창 하나, 카드는 각자 하나

`.items`의 행은 눌러서 고르는 카드라 각자 틀을 씁니다. `.bars`·`.hunts`는 읽는 것(사냥 기록,
토큰 내역)이라 **하나의 창 안에 줄을 그어** 넣습니다 — 원작이 그런 목록을 다루는 방식이고,
틀이 없으면 색 바닥 위에 글자만 떠 있어 미완성으로 읽힙니다.

## 스프라이트 캐시

배틀에 나온 야생 포켓몬이 쌓이므로 캐시가 결국 도감 전체(약 36MB)로 자란다. 설정 탭에
용량이 표시되고 정리 버튼이 있다. 정리는 **지금 화면이 참조하는 파일만 남긴다** — 전부 지우면
다음 갱신까지 화면이 비어서 고장으로 보인다. 남길 목록은 페이로드에서 파생시키므로
스프라이트 종류가 늘어도 어긋나지 않는다.

### 트레이너

조우 25번에 한 번(약 2시간) 트레이너가 승부를 걸어온다. 클래스가 팀 크기·강함·**선호 타입**을
정한다 — 낚시꾼은 물, 벌레잡이 소년은 벌레. 타입 상성이 이미 있으므로 이게 배틀을 실제로 바꾼다.

PokeAPI에 트레이너 데이터가 없어서 **클래스 20종과 이름 풀은 직접 썼다.** 한국어 클래스명도
공식 로컬라이즈명이 아니라 우리가 붙인 것이다 — `부자 아저씨`가 원래 그랬듯이.

**아트는 직접 쓰지 않았다.** 각 클래스는 Showdown 트레이너 슬러그를 들고 있고
`ensureNpcSprite`가 그걸 받아온다 — 상점 점원·배틀 배경·기술 이펙트와 **같은 호스트, 같은
런타임 페치+캐시 규칙**이다. 이 파일에는 오래도록 "스프라이트 저장소에 트레이너 아트가
없다"고 적혀 있었는데, 사실 `server/sprites.ts`가 카운터를 위해 이미 찾아 두었고 배틀 쪽이
묻지 않고 있었을 뿐이다. 이 앱이 요청할 수 있는 24장 전부 **80×80, 평균 762바이트**라
`Scene.tsx`가 상수 하나(`TRAINER_TARGET = 80`)로 1배 확대해 도트를 그대로 찍는다.

**성별은 스프라이트가 정한다.** 클래스는 `{ m?, f? }` 슬러그를 갖고, 한쪽만 있으면 그 성별로
고정되고 둘 다 있으면 굴린다 — 성별을 따로 든 필드가 없으니 나중에 한쪽만 고치다 어긋날
수가 없다. 남성 전용 10종, 여성 전용 5종, 양성 5종으로 여성이 약 37%다. 이름 풀도 남/여로
갈랐다. 예전에는 한 풀이라 `미니스커트 도현`이 나왔다.

이름은 **전부 2음절**인데 취향이 아니라 레이아웃 규칙이다. 보상 문구가 "가장 긴 트레이너
이름은 11자"에 기대 있고 가장 긴 클래스명 `엘리트 트레이너`가 8자다 — 8 + 공백 + 2 = 정확히
11. 3음절을 하나라도 넣으면 보상 줄이 두 줄로 접히고, `test/trainer.test.ts`가 그걸 막는다.

**여기서는 질 수 있다.** 야생 사냥은 지는 법이 없고 내 HP 바에 바닥값이 있는 것도 그 때문인데,
트레이너 배틀에서만 그 바닥을 푼다. 실측 승률:

```
             1마리    2마리    3마리
기술 없음     100%     93%     33%
강한 4개      100%     99%     95%
```

상대가 자기 기술로 답하게 되면서 2마리 구간이 100%에서 내려왔다. 기대 데미지는
그대로고(가중 추첨 평균 배수 1.006) 분산과 상성만 생긴 결과다.

클래스를 8종에서 20종으로 늘리고 **이 표는 그대로 뒀다.** 같은 조건으로 늘리기 전후를 나란히
돌려 보면 승률이 사실상 안 움직인다(3마리 구간 기술 없음 27%→26%, 강한 4개 99%→99%). 2마리
클래스가 넷에서 열다섯이 되면서 평균 강함이 1.088에서 1.027로 내려간 만큼 보상도 같이
내려가서(트레이너 한 명당 평균 배수 6.93→6.52, 사냥 수입 전체로는 2% 미만) 난이도와 벌이가
같은 방향으로 움직였다.

기술머신을 모을 이유가 여기서 생긴다. 지면 보상이 없을 뿐 진행도를 빼앗지는 않는다.

**`battleAt`은 팀용으로 늘리지 않았다.** 그러면 야생이 보장하는 세 가지가 동시에 깨진다 —
마지막 턴이 반드시 상대를 쓰러뜨린다는 것, 전체가 `MAX_TURNS` 안에 든다는 것, 마무리 타격이
전역 턴 인덱스에 묶여 있다는 것. 대신 팀 크기만큼 **합성**하고 내 HP만 라운드를 넘어 잇는다.
옵션을 안 주면 야생 동작이 **바이트 단위로 동일**하다 — 6000줄을 대조해 확인했다.

**보상**은 진행도(보통 조우의 3배 × 팀 크기 × 강함)와, 35% 확률로 반짝반짝부적이나
변함없는돌이다. **이상한사탕은 절대 안 준다** — 그건 `bonusTokens`로 들어가는데 `huntCap`은
`huntTokens`만 캡하므로 사냥 상한을 통째로 우회한다. 지갑도 건드리지 않는다.
전체적으로 사냥 수입이 약 27% 늘어 야생이 여전히 주역이다.

**RNG 스트림은 건드리지 않았다.** `encounterAt` 안에서 뽑기를 하나만 추가해도 이후 모든 뽑기가
밀려서 과거 조우가 전부 달라진다. 트레이너 판정은 네 번째 솔트를 쓰는 독립 함수다 —
20000개 조우가 트레이너 도입 전후로 동일한지 테스트가 지킨다.

**대신 트레이너 재현은 바뀐다.** `trainerAt`은 `seq`뿐 아니라 클래스·이름 표에 대해서도
순수해서, 클래스를 늘리면 과거 `seq`에 서 있던 사람이 다시 굴려진다. 야생 쪽은 위의 이유로
멀쩡하다. 걸리는 건 딱 하나 — `state.ts`가 **가장 최근 로그 한 건만** 다시 연출하는데, 그
엔트리에 기록된 이름이 지금 함수가 내놓는 이름과 다를 수 있다. `trainerFor`가 그걸 대조해서
어긋나면 `null`을 준다. 일어나지 않은 배틀을 연출하느니 그 한 건의 연출을 접는 편이 정직하고,
기록 탭은 저장된 이름과 승패를 그대로 보여준다. 업데이트 직후 최대 한 번이다.

### 기술머신

조우 4%의 확률로 기술머신이 떨어집니다. **지금 포켓몬이 실제로 배울 수 있는 기술만**
나옵니다 — PokeAPI의 `move_learn_method = machine`을 전 세대에 걸쳐 합집합한 **340개**가
후보이고, 1025종 중 **1016종**이 뭔가는 배웁니다.

| 못 배우는 9종 | 뀨뀨 · 단데기 · 메타몽 · 루브도 · 개무소 · 실쿤 · 카스쿤 · 코스모그 · 애글 |
|---|---|

원작 그대로입니다. 이 포켓몬을 키우는 동안에는 가방이 그 사실을 알려줍니다.

기술 슬롯은 **4칸**. 다섯 번째를 배우려면 하나를 잊어야 하고, 팝오버가 어느 칸을 비울지
물어봅니다. 배운 기술의 위력 합이 사냥 속도를 올립니다 — 최대 2배까지.

#### 기술머신 주머니는 스크롤이 아니라 쪽으로 넘깁니다

주머니 중에서 유일하게 진짜로 길어지는 목록입니다. 실제 세이브 하나를 재보니 **47개를 갖고
있고 그중 지금 파트너가 배울 수 있는 19개**가 뜹니다 — 한 줄이 약 50px이니 950px짜리
칼럼인데, 팝오버는 가장 클 때 760px, 작을 때 420px입니다. 그리고 도감이 찰수록 늘어납니다.

그래서 **한 쪽에 8개**씩 끊고 `◀ 1 / 3 ▶`로 넘깁니다. 8 × 50 = 400px이고, 탭바·주머니 칩·
설명창이 첫 줄 앞에서 약 220px을 쓰므로 760px 창에 **스크롤 없이** 들어갑니다
(실측: 어느 쪽에서든 `scrollHeight === clientHeight`).

주머니가 애초에 존재하는 이유(`기술머신 14개에 도구와 스톤까지 한 칼럼에 쌓이면 가방 하나가
화면 여섯 장`)와 같은 논리를 주머니 하나 안에서 한 번 더 적용한 것입니다. 스크롤 대신 쪽인
이유는 **설명창과 주머니 칩이 계속 화면에 남기 때문**입니다 — 길게 스크롤하면 지금 무슨
주머니를 보고 있는지와 가리킨 것의 설명이 위로 사라집니다.

**쪽이 하나뿐이면 페이저를 그리지 않습니다.** `1 / 1`은 아무 말도 하지 않는 컨트롤이고,
그건 `폼이 없는 종은 줄 자체가 없습니다`와 같은 규칙입니다.

**쪽 번호는 렌더에서 한 번 더 조입니다.** 기술머신은 배우면 **없어지므로**(`teach`가
개수를 깎고 0이면 지웁니다) 서 있던 마지막 쪽이 그 순간 사라질 수 있습니다. 이펙트로
고치면 빈 쪽을 한 프레임 그리고 나서 고쳐지므로, 파생값에서 바로 잘라둡니다.
파트너가 바뀌어 `teachableNow`가 목록을 통째로 다시 짤 때도 같은 자름이 받아냅니다.

**슬롯 선택기가 떠 있는 동안에는 페이저를 감춥니다.** 그때 화면에 목록이 둘이 되는데
하나는 질문입니다. 페이저는 훑어보는 도구이고, 무엇을 잊을지 고르는 중은 훑어보는 중이
아닙니다. 그 김에 **탭이나 주머니를 옮기면 그 질문도 버립니다** — 메가스톤 주머니 위에
"무엇을 잊을까요"가 떠 있으면 답할 수 없는 화면에 질문만 남습니다.

**모든 포켓몬은 공격 기술을 최소 하나 갖습니다.** 알에서 나올 때 **자기 타입 공격 기술 중
가장 약한 것**을 하나 알고 나오고(이상해씨 → 씨기관총, 파이리 → 회오리불꽃), 그 하나뿐인
공격 기술은 잊을 수도 변화 기술로 덮을 수도 없습니다. 안 그러면 변화 기술만 배운 포켓몬이
상대를 때리지 못하는데, **변화 기술 하나만 배운 개체가 아무것도 안 배운 개체보다 나빠지는**
상황이 실제로 나왔습니다.

기술머신으로 공격 기술을 하나도 못 배우는 종이 **13종** 있습니다 — 학습셋이 아예 없는 9종과,
학습셋은 있는데 전부 변화 기술인 늠비름·마자·해무기·코스모움. 이 넷은 규칙을 만족시킬 방법이
없으므로 **배틀 쪽에 안전망**을 둡니다: 공격 기술이 하나도 없으면 몸통박치기가 추첨에 다시 낍니다.
(무학습 구성은 지금처럼 추첨을 아예 안 뽑습니다 — 여기서 뽑기 시작하면 과거 배틀이 전부 어긋납니다.)
**상태 기술은 위력이 0이지만 여기서는 35로 셉니다.** 데미지는 안 주더라도 상대의 한 턴을
쓰게 만드는 건 사실이고, 이 숫자가 재는 건 데미지가 아니라 압박이기 때문입니다
(`STATUS_SWING`). 같은 값이 상대 HP 풀 사이징에도 쓰여서, 전부 상태 기술인 구성이
풀을 0으로 만들어 배틀이 0턴에 끝나는 일도 막습니다.

```
사냥 배수 = min(2.0, 1 + 배운 기술 위력 합 / 600)
```

**세대마다 번호가 바뀌므로 TM 번호는 쓰지 않습니다.** 기술 자체가 곧 기술머신이고,
아이콘은 기술의 타입에서 옵니다 (`sprites/items/tm-{type}.png`, 18타입 전부 존재).

### 왜 경과시간을 누적하지 않는가

`electron:dev`는 Vite와 Electron을 **동시에** 띄웁니다. 브라우저로 localhost:5173을 열어두면
같은 `state.json`에 두 개의 20초 파이프라인이 붙습니다. 지금 이게 안전한 이유는
`buildState`가 **멱등**이기 때문입니다 — `accrue`는 저장된 앵커에서 델타를 구하고
`advance`는 순수 함수라, 두 프로세스가 같은 바이트를 씁니다.

`huntTokens += f(경과시간)`은 이 성질을 깹니다. 그래서 사냥은 **조우 번호 구간의 재생**입니다.
같은 저장 상태에서 출발한 두 프로세스는 같은 토큰·같은 기술머신·같은 기록을 계산하므로,
경쟁에서 진 쓰기는 다음 틱이 그대로 다시 만들어냅니다.

시계가 뒤로 갈 때(NTP 보정·시간대 변경·VM 스냅샷 복원) 음수 경과를 `Math.floor` 하면
카운터가 **뒤로 갑니다.** 그럴 땐 빼지 않고 앞으로만 재앵커합니다.

## 도감

떠나보낸 포켓몬이 **스프라이트와 함께** 카드 격자로 쌓인다. 이로치는 이로치 스프라이트로,
테두리도 강조된다.

**진화체를 졸업시키면 지나온 형태가 전부 등록된다.** 리자몽을 키웠다는 것은 파이리를
키웠다는 뜻이니까. `Companion.pathIds`가 부화 때 확정된 경로 전체라
`pathIds.slice(0, stageIndex + 1)`이면 끝난다. 닉네임은 **실제로 떠난 형태에만** 붙는다 —
앞 단계는 "지나갔다"는 기록이지 그 이름으로 떠난 개체가 아니다.

졸업과 알 구매 두 경로가 `retireInto()` 하나를 공유한다. 예전에는 각자 복사본을 갖고 있었고,
그게 두 경로가 어긋나는 방법이다.

옛 저장본은 `migrate`에서 한 번 소급 등록된다. 분기 라인에서도 안전한데,
**541개 라인 전수에서 선행 단계가 모호한 종이 0개**이기 때문이다 — 라플레시아와 아르코는
둘 다 뚜벅쵸 → 냄새꼬를 거치고, 뷰티플라이와 독케일은 실쿤/카스쿤에서 갈리지만 서로의
경로에 나타나지 않는다.

### 필터

등급 · 세대 · 타입, 그리고 '미수집 포함'. 기본은 접혀 있다 — 타입 18칩을 항상 펼쳐두면
포켓몬 한 마리 보이기 전에 화면이 다 찬다.

**세대는 데이터를 굽지 않는다.** 9세대 전부 연속 id 구간임을 PokeAPI로 확인했으므로
경계 숫자 9개면 된다 (151/251/386/493/649/721/809/905/1025). 과거 경계는 바뀌지 않는다.

**도감 색인은 페이로드가 아니다.** 미수집 칸을 보여주려면 1025종의 이름·등급·세대·타입이
필요한데 그게 **116KB**다. 상태 페이로드는 20초마다 오가므로, 정적인 이 데이터는
`/api/dex`(브라우저) · `pet:dexIndex`(Electron)로 빼서 토글을 처음 켤 때 한 번만 받는다.
미수집 칸은 스프라이트를 받지 않으므로 토글을 켜도 다운로드가 늘지 않는다.

### 상세 화면

카드를 누르면 **그 자리에서 격자가 엔트리 화면으로 바뀐다.** 원작이 하는 일이 그거다 —
책장에서 한 권을 고르고 B로 돌아온다. 그리고 420px 팝오버에 정보가 다 들어가는 방법이
그것뿐이다: 이 패널은 이미 떠 있는 창이라, 모달을 띄우면 창 안의 창이 되고 스크림이 덮을
"바깥"이 없다. 앱에 `position: fixed`는 여전히 `.flash` 하나뿐이다.

가방의 기술머신 슬롯 선택기가 이미 같은 일을 작은 규모로 한다 — 목록을 제자리에서 선택기로
바꾼다. 이건 그걸 화면 크기로 한 것이지 새 장치가 아니다.

**머리 부분은 격자가 들고 있던 것으로 즉시 그린다.** 열어 둔 카드를 id 쌍이 아니라 **행 통째로**
들고 있기 때문이다 — 번호·이름·그림·이로치·타입이 곧 엔트리 화면의 머리다. 네트워크를 기다리는
것은 그 아래 절들뿐이라 돌릴 스피너가 없다.

**미수집 칸은 누를 수 없다.** `mine`이 정의상 비어 있고, 스프라이트를 받지 않는다는 위의 약속을
깨지 않으려면 그림 없는 화면을 열게 되기 때문이다. 원작도 등록되지 않은 번호는 열어주지 않는다.

**초점은 키로 되돌린다.** 상세가 열린 동안 격자는 언마운트되므로, 들어갈 때 잡아둔 노드는
돌아왔을 때 detached다 — detached 노드의 `.focus()`는 **아무 일도 조용히 일어나지 않는다.**
카드마다 `data-key`를 달고 키로 다시 찾으면, 덤으로 그 카드가 화면 안으로 스크롤된다.

**상세도 페이로드가 아니다.** 색인과 같은 이유이면서 반대 방향이다: 색인은 정적이라 한 시간
캐시하지만, 상세는 절반이 플레이어 자신의 기록이라 `no-store`다. 졸업이 한 시간 뒤에 반영되면
고장으로 읽힌다. `/api/dex/:id`(브라우저) · `pet:dexEntry`(Electron)로 **누른 종 하나만** 받는다.

라우트 순서가 조용한 함정이었다. 색인이 `startsWith('/api/dex')`인데 **`/api/dex/25`도 이 조건을
만족한다** — 순서를 뒤집으면 모든 상세 요청이 **아무 에러 없이** 116KB짜리 색인을 돌려받는다.
상세를 앞에 두고, 색인 조건은 정확 일치로 좁혔다. 순서 하나가 정확성을 떠받치지 않도록.
테스트 목에도 같은 함정이 있어서 같이 고쳤다 — 안 고쳤으면 새 테스트가 **틀린 이유로 통과했다.**

#### 무엇을 굽고 무엇을 안 굽나

`server/dexdata.ts`(생성물, 183KB)에 **도감 설명 · 종족값 · 특성** 셋만 굽는다.
`server/moves.ts`에 합치지 않았다 — `server/hunt.ts`가 그걸 매 배틀 틱마다 import하는데
이 중 한 글자도 읽지 않는다.

| 테이블 | 크기 | |
|---|---|---|
| 도감 설명 | 108.7KB | 898/1025종 |
| 종족값 | 29.0KB | 1025종 |
| 특성 표 | 23.5KB | 284종류, 한글명 전부 · 한글설명 248개 |
| 종→특성 | 20.3KB | 숨겨진 특성은 부호를 뒤집어 표시 |

**포획률은 넣지 않았다.** 인포박스에는 있고 7KB뿐이지만, 여기서는 **화면에 보이는 모순**이 된다.
`rarityOfSpecies`는 종 자신이 아니라 **라인 뿌리**의 포획률을 읽는다 — 그래야 한 라인이 등급
하나를 공유하고 등급 필터가 말이 된다. 버터플 자신의 포획률은 45(귀함급)인데 라인 뿌리인
캐터피가 255라 카드의 배지는 **흔함**이다. 두 숫자를 나란히 찍으면 누군가 "버그"라고 읽고
필터를 종별로 고치려 들 텐데, 그건 도감 설계가 통째로 피하려던 변경이다.

**알 그룹 · 성비 · 부화 걸음수**도 뺐다. 교배도 두 번째 부모도 걸음도 없고 `Companion`에는
성별 필드가 없다. 앱이 영영 쓸 수 없는 통계다 — 성격에 대해 이미 한 이야기와 같은 문단이다.

#### 굽지 않아도 나오는 것들

절반은 이미 저장소 안에 있었다. **방어 상성**이 특히 그렇다 — `effectiveness`를 공격 타입 쪽으로
열여덟 번 돌리면 끝이고, 추가 데이터가 0이다. 그리고 이건 위키에서 베껴온 정보가 아니라
**이 앱의 배틀이 실제로 곱하는 표다**: `server/hunt.ts`가 매 스윙에 이 함수를 곱하고
`src/Scene.tsx`가 같은 숫자로 `효과가 굉장했다!`를 찍는다. 종족값과 정반대 성격의 절이다.

1배는 아예 담지 않는다. 열여덟 칸 중 열 개가 "보통"이면 4배가 어디 있는지 안 보인다 —
**폼이 없는 종은 줄 자체가 없습니다**와 같은 규칙이다.

**진화 라인은 경로가 아니라 단계로 접는다.** `lineOf(133).paths`는 **여덟 개**다. 경로마다 한 줄씩
그리면 420px에 첫 칸이 전부 이브이인 여덟 줄이 된다. 단계마다 한 칸이 원작이 트리를 그리는
방식이고, 갈래가 없는 라인은 이 함수를 지나도 그대로다.

**폼은 `formsFrom`이 아니라 `f.base === speciesId`로 찾는다.** `formsFrom(800)`은
울트라네크로즈마를 빠뜨린다 — 이미 합체한 네크로즈마에서만 도달하므로 `from`이
`[10155, 10156]`이라 800에서 안 잡힌다. `formsFrom`은 "지금 이 모습에서 어디로"라는
**배틀의 질문**이고, 도감은 "이 종에 무엇이 있나"를 묻는다.

#### 도감 설명이 없는 127종

`#899` 이상은 PokeAPI에 **한국어 행이 아예 없다.** 요청이 실패한 게 아니라 번역이 없다.

집안 규칙(한글이 없으면 throw)의 기존 대응은 셋이었다 — 성격은 **throw**, 메가 이름은 **합성**,
여행지는 **생략**. 여기엔 셋 다 안 맞는다: #900도 도감에 있고 카드도 받는다.
그래서 네 번째 답이다 — **없는 대로 두고, 화면이 설명 상자를 아예 그리지 않는다.**
빈 상자도 "설명 없음"도 아니다.

생성기는 개수가 아니라 **경계**를 못박는다. `KO_FLAVOR_THROUGH = 898`. 127이라는 숫자는 오늘의
사실이고, "898까지 전부 있고 그 위로는 없다"가 주장이다 — 이렇게 써야 요청 한 덩어리가 조용히
빈손으로 돌아왔을 때 경계가 끌려 내려가고 생성이 멈춘다. 위쪽이 채워지는 건 좋은 소식이라
로그만 남긴다. `NO_MACHINE_MOVES`와 같은 본능이다.

특성은 반대다 — **이름은 284개 전부 한글이 있어서 하나라도 없으면 throw**하고, 설명만
248/284라 없는 줄은 이름으로 끝난다.

#### 종족값을 넣은 대가

**넣기로 했고, 화면이 스스로 그 값을 부인한다.** 종족값 막대 아래에
`원작 수치입니다. 이 앱의 배틀은 종족값을 읽지 않고 기술 위력과 타입 상성으로만 계산합니다.`가
붙는다. 없는 메커니즘이 있는 것처럼 읽히면 그게 `### 전투 보정을 지어내지 않았습니다`가
막으려는 바로 그 일이기 때문이다.

그리고 **테스트가 자물쇠를 건다** — `server/hunt.ts` · `server/game.ts` · `server/state.ts`가
`dexdata.ts`를 import하면 실패한다. 화면용으로 굽는 것과 "배틀도 이걸 쓰면 되지 않나" 사이는
한 걸음이고, 그 한 걸음이 GOLDEN 표의 모든 숫자를 움직인다.

막대 분모는 **255가 아니라 180**이다. 255에 닿는 종이 거의 없어서 255로 나누면 여섯 막대가
전부 절반도 안 차고, 그러면 종끼리 비교가 안 된다 — 막대가 하는 유일한 일이 그건데.

#### 조판은 파트너 탭에서 빌려온다

`.portrait` · `.bars.info` · `.types` · `.chain`을 그대로 쓴다. 두 화면이 갈라지지 않게 하는 게
재사용의 목적이다. **종족값 막대에는 새 CSS가 한 줄도 필요 없었다** — `.bars li`가 이미
라벨·막대·숫자 3열이고, 토큰 탭의 `어디서 썼나`가 쓰는 마크업 그대로다.

새로 쓴 건 셋뿐이다. `.dex .card`는 상자를 칸에서 **카드로 옮긴다** — 누르는 것이 곧 상자여야
한다(`.items .rowbtn`이 이미 정리한 논쟁). `.dexart`는 카드의 48px 박스의 정확히 두 배다.
`.bars.matchups`는 배수 라벨 열이다.

**도감 설명 상자는 `.uiwin`을 입되 `.saywin`은 아니다.** 점원의 상자가 92px 고정인 이유는 그
아래에 누를 목록이 붙어 있어서인데, 여기는 아래에 누를 게 하나도 없고 상자가 열릴 때 한 번
쓰이고 상태가 바뀌지 않는다. 반면 비용은 진짜다 — 92px는 약 3.6줄이라 네 줄짜리 설명은
**마지막 문장을 잃는다.** 아무도 없어진 걸 알 수 없는 그 문장을. 그래서 같은 숫자를
천장이 아니라 **바닥**(`min-height`)으로 쓴다.

## 전설과 환상 — 조건을 갖춰야 만난다

전설 71종 + 환상 23종, **94종은 그냥 나오지 않습니다.** 조건을 갖춰야 야생에 나타나고,
만나면 **질 수 있는 배틀**이 벌어지고, 이기면 **그 포켓몬의 알**이 남습니다.

```
조건 달성 → 야생 조우 가능 → 배틀에서 승리 → 알 획득 → 알을 품어 키움 → 도감 등록
                    ↑
          전용 도구를 쓰면 다음 조우를 확정 예약
```

**도감 규칙은 안 바뀝니다.** 잡았다고 등록되지 않습니다. 알을 품어 키우고 졸업시켜야
들어갑니다 — 도감의 뜻("떠나보낸 포켓몬")을 지키려고 일부러 이렇게 했고, 전설도 예외가
아닙니다.

### `rarityOfSpecies`는 전설 분류기가 아니었습니다

먼저 고쳐야 했던 것입니다. capture_rate 규칙은 양쪽으로 틀립니다:

```
전설인데 안 걸림   뮤 45 · 세레비 45 · 쉐이미 45 · 코스모그 45 → 귀함
                  네크로즈마 255 · 테라파고스 255 → 흔함
전설 아닌데 걸림   메타몽 35 · 에어아머 25 · 메탕 3 · 패러독스 16종 → 전설
```

그래서 `scripts/gen-legends.ts`가 PokeAPI의 **`is_legendary` / `is_mythical`**을 실제로
가져옵니다. 같은 생성기가 전용 도구 38종의 한글명도 가져오고, 아이콘이 있는지 **HEAD로 직접
확인**합니다 — 스프라이트 저장소는 7세대쯤에서 얇아져서 녹슨검·가면들은 아이콘이 없습니다.
27/38에 아이콘이 있고, 나머지는 다이맥스밴드처럼 글리프를 그립니다.

### 조우 스트림은 한 글자도 안 건드렸습니다

`encounterAt`은 `(k, speciesId, threshold)`에 순수해야 합니다. 두 가지가 거기 매달려 있습니다:
두 프로세스가 같은 구간을 재생해 같은 바이트를 내는 멱등성, 그리고 패널이 옛 로그를 다시 그리는
재생. 드로우 하나만 늘어도 앱이 만든 **모든 조우가 다시 굴려집니다.**

그래서 게이트는 `encounterAt`의 **출력에** 얹습니다 — `stoneAt`이 사는 그 자리입니다.

```ts
const open = openLegends(state);            // 루프 밖에서 한 번
...
const locked = !!legendOf(rolled) && !open.has(rolled);
const wildId = locked ? substituteAt(seq) : rolled;   // 여섯 번째 솔트
```

`substituteAt`은 **전설이 없는 라인에서만** 뽑으므로 재시도 루프가 필요 없습니다. 결과는
`HuntEntry.wildId`에 기록되므로 재생은 계산이 아니라 기록을 읽습니다. 그 김에 `state.ts`가
옛 로그의 등급을 `encounterAt`으로 다시 굴리던 것도 저장된 종에서 읽게 고쳤습니다 — 치환이
과거 로그를 거짓말로 만들 수 없게.

**루트 트레이너는 전설을 안 들고 다닙니다.** 등산가가 아르세우스를 꺼내면 게이트가 한 줄로
무의미해집니다. `rollSpecies`의 `exclude`로 전설 라인을 빼는데, 이건 **드로우를 하나도 더
쓰지 않습니다** — 풀만 좁아지고 뽑기 횟수는 그대로입니다.

등급 3% 안에서 뽑히니 여전히 귀합니다. 전용 도구를 쓰면 기다림을 건너뛰고 **다음 조우를 확정
예약**합니다.

### 예약은 절대 인덱스로 못박습니다

```ts
forcedNext: { seq: state.huntCount, speciesId }
```

"다음 조우"는 두 writer가 합의할 수 있는 사실이 아닙니다. `hunt()`는 커서 구간을 재생하고,
어느 조우가 예약된 것인지 둘이 같은 답을 내야 합니다 — 절대 인덱스는 그 답이 되고 "다음"은
안 됩니다.

**도구는 이길 때가 아니라 쓸 때 소모됩니다.** 지면 손해가 있어야 배틀이 긴장을 갖습니다.
다만 조건 자체는 남으므로, 돌아가는 길은 도구를 다시 구하는 것이지 전부 다시가 아닙니다.

### 배틀과 알

트레이너전과 같은 구조입니다 — `battleAt`에 `floor: false`를 줘서 **질 수 있게** 하고,
등급에 따라 상대가 단단해집니다(준전설 1.6× · 박스 2.0× · 환상 2.4×). 이기면
`legendEggs[speciesId]`가 오르고, 가방 '전설' 주머니에서 품으면 `forcedSpecies`가 서서
그 종이 확정으로 부화합니다 — `forcedRarity`·`shinyCharmActive`와 **완전히 같은 수명**입니다.

부화 분기는 강제 종이 있어도 **주사위는 그대로 굴립니다.** 건너뛰면 그 뒤의 샤이니·성격
뽑기가 전부 밀리기 때문입니다.

### 화면

조건을 보는 길은 **두 개**이고 둘 다 도감 탭 안입니다. 420px 한 줄에 여덟 번째 탭은
안 들어가고, 전설도 결국 모으는 화면이라 도감 뒤가 제자리입니다.

**격자의 `?` 칸이 첫 번째 길입니다.** 아직 못 만난 전설 94종은 `미수집 포함` 토글과 무관하게
항상 격자에 있습니다 — 볼 수 없으면 목표가 아니고, 목표로 만드는 것이 이 기능의 전부입니다.
누르면 도감 상세 화면의 한 갈래로 조건이 열립니다(등급·세대, 게이지 또는 `조우 가능`, 전용
도구와 그것을 얻는 길, 그리고 알 설명). 이름은 끝까지 `???`입니다 — 무엇을 위한 조건인지는
만나면 알게 됩니다.

미수집 칸이 원래 안 눌리는 이유는 코드에 적혀 있습니다 — *"`mine`은 정의상 비어 있고, 그 칸의
상세 화면은 비어 있거나 '다운로드 없음'이라는 약속을 어긴다."* **잠긴 전설은 정확히 그
예외입니다**: 할 말이 있고(조건은 이미 페이로드의 `legends.gates`에 다 있습니다), 스프라이트를
받을 필요도 없습니다.

**격자에서는 수집한 칸이 먼저, 잠긴 칸이 뒤입니다.** 번호순으로 한데 섞으면 9종짜리 도감이
94개의 `?` 아래로 묻힙니다(첫 실물이 6번째 줄). `미수집 포함`을 켠 화면은 어차피 1025칸이
번호순이라 그 갈래는 그대로 둡니다.

**두 번째 길은 94행 목록**입니다. `[도감] [전설 목록]` 칩 한 줄로 꺼내는데, 가방의 주머니 칩과
같은 어휘입니다. 예전에는 헤더 구석의 밑줄 링크였고 바로 옆 `필터`와 한 덩어리로 읽혀서
아무도 못 찾았습니다. 칩 이름을 `전설`로 줄이면 **도감 필터의 등급 칩 `전설`과 부딪칩니다.**
94행은 **세대별로 묶고** 헤딩이 `N / M`을 말합니다 — 업적 보드와 같은 방식입니다.

가방에는 '전설' 주머니가 생겨 전용 도구 · 조각 · 알 셋을 만나는 순서대로 놓습니다. 비어 있을
때의 안내가 "조건을 채우면"이라고 말하면서 조건을 볼 길이 없었으므로, 그 문장에서 목록으로
가는 링크가 나갑니다. 그리고 가방 탭의 점(`bagCount`)은 `inventory`만 세고 있어서 **첫 금강옥이
떨어져도 안 켜졌습니다** — 전용 도구 · 알 · 합성 가능한 조각을 함께 셉니다.

### 새 필드 다섯 개

`legendItems` · `shards` · `legendEggs` · `forcedSpecies` · `forcedNext`. 전부 optional이라
스키마 번호는 그대로지만, **`migrate`에 이름을 적어야 합니다** — 그 함수는 spread가 아니라
allow-list라서, 안 적으면 20초마다 지워지고 열어둔 게이트가 조용히 다시 잠깁니다.

전용 도구는 `ItemId` 유니온에 넣지 **않았습니다.** 그 유니온은 `shop.ts`와 `game.ts`에 손으로
두 번 적혀 있어서 38개를 더하면 함정이 됩니다. 메가스톤이 폼 id로 키를 잡듯 슬러그로 키를
잡고, 사는 선반이 아니라 확인하는 수집품으로 둡니다.

## 업적

아홉 분야 50개. 달성하면 **소지금**과, 어떤 것은 **아이템**이 들어옵니다.

```
성장    임계값 10 · 100 · 1000배                        🔁 250배마다
여행    성도 · 호연 · 신오 · 칼로스 · 알로라, 세계일주      🔁 1,000조우마다
도감    10 · 50 · 150 · 500 · 완성, 아홉 세대            🔁 25종마다
희귀    전설 1 · 10종, 이로치 1 · 3 · 10종, 합체 등록
트레이너  1 · 10 · 50 · 100승                            🔁 25승마다
배틀    기술 네 칸, 기술머신 30 · 60종 보유
수집    메가스톤 1 · 3 · 10 · 30종, 기술머신 1 · 50 · 200개  🔁 100개마다
육성    졸업 1 · 10 · 50 · 100마리, 이름을 지어줬다        🔁 10마리마다
상점    첫 구매, 임계값 10 · 100 · 500배 소비              🔁 150배 소비마다
```

**새 카운터는 하나도 안 늘렸습니다.** 쉰 개가 전부 이미 저장돼 있던 값에서 나옵니다 —
`spentTokens`, `dex`의 세대·등급·이로치·별명, `active.moves.length`, 보유 기술머신 종류 수.

### 🔁 반복 업적

여섯 개는 **끝나지 않습니다.** "25승마다", "1,000조우마다" 식으로 계속 반복되고 달성 횟수가
쌓입니다. 사다리 꼭대기를 본 뒤에도 그 분야에 볼 것이 남습니다.

**상점 사다리는 값을 올린 만큼 위로 늘렸습니다.** 10배·100배는 옛 가격에서 "상점 전체를 다섯
번"이었지만 이제는 전설의 알 하나쯤이라 초반 이정표가 됐고, 그 위에 `shop-500`과 반복
`shop-repeat`을 **더했습니다** — 옛 계단의 번호를 고쳐 달지 않은 이유는, 이미 `shop-10`을
달성해 둔 저장본이 가리킬 곳을 잃기 때문입니다. 표에 없는 id를 가리키는 달성 기록은 번
것을 조용히 잃는 것입니다.

**상한을 두지 않았습니다.** 보상이 지갑행이라 성장을 못 건드리고, 간격이 실제 진행(사냥·졸업·
도감)에 묶여 있어 놀고 있는 기계가 캘 수 있는 것이 아닙니다. 다만 **전부 그 분야 일회성
꼭대기보다 쌉니다** — 반복이 유한한 것보다 더 주면 사다리가 무의미해집니다. 테스트가 그걸
지킵니다.

계단 수는 `floor(have / step)`을 **매번 새로 계산**합니다. `+= 1`이 아니라서 두 번 돌려도,
두 프로세스가 같이 돌려도 두 번 지급되지 않습니다 — `settleAchievements`의 멱등성이 여기에도
그대로 적용됩니다. 앱을 껐던 동안 세 계단을 넘었으면 한 번에 세 번 치릅니다. 오프라인 사냥
백로그가 정산되는 방식과 같습니다.

상태는 `repeats`(id → 지급 횟수)에 따로 둡니다. `achievements`(id → 달성 시각)와 한 칸에
넣지 않은 이유는, 일회성의 뜻이 "언제 열렸나"이고 반복의 뜻은 "몇 번 받았나"라서입니다.
**`migrate`에 이름을 적는 것은 여기서도 필수**입니다.

### 화면 — 분야로 묶어서 봅니다

'전체'일 때는 **분야별로 묶고 헤딩이 `3 / 5`를 말합니다.** 상점의 선반과 똑같은 방식입니다 —
행이 아니라 분야 목록을 필터하고, 칩으로 하나를 고르면 헤딩이 사라집니다. 숫자를 칩에 넣으면
칩 열 개가 세 줄이 되므로 헤딩이 가져갑니다.

**「달성 숨기기」**는 도감의 필터 토글과 같은 자리, 같은 `.linky`입니다. **반복 업적은 숨기지
않습니다** — 끝난 적이 없으니까요. 같은 이유로 반복 행은 흐려지지도 않습니다. 잠긴 것도
끝난 것도 아니라 **언제나 다음 계단으로 가는 중**입니다.

게이지 비율(`ratio`)은 **서버가 계산합니다.** 반복 행의 막대는 전체가 아니라 계단 안에서의
진행도라, 렌더러가 `have / need`로 다시 계산하면 87승이 다음 목표 100 대비 87%로 보입니다 —
실제로는 75에서 100까지 중 48%입니다. 숫자와 막대가 어긋날 수 없게 한 곳에서 냅니다.

**보상은 지갑으로만 갑니다.** `awardTokens`는 `lifetimeOf`에 들어가지 않습니다 — 거기 넣으면
도감을 채우는 것으로 포켓몬이 부화합니다. `bonusTokens`(이상한사탕이 쓰는 칸)도 안 됩니다.
그건 `huntCap`이 재는 대상 밖이라, 공짜로 거기 넣으면 사냥 상한을 통째로 우회합니다 —
`server/trainer.ts`가 트레이너 보상에서 이상한사탕을 뺀 것과 같은 이유입니다.
금액은 상점 가격과 같이 **부화 임계값의 배수**라 헤비 유저든 라이트 유저든 체감이 같습니다.

### 키스톤·다이맥스밴드·반짝반짝부적은 이제 팔지 않습니다

셋 다 **업적 보상으로 옮겼습니다.** 원작에서도 반짝반짝부적은 도감을 채운 대가이고 키스톤은
사람이 주는 물건이지, 돈으로 사는 물건이 아니었습니다. 그래서 반짝반짝부적은 도감 네 계단에
걸려 있고(부화 때 소비되는 일회용이라 한 번으로는 모자랍니다), 키스톤은 **메가스톤 3종**에
붙어 있습니다 — 짝이 될 돌이 하나도 없을 때 주는 키스톤은 빈 물건이니까요.

**상품 목록에서 행을 지우지는 않았습니다.** 가방이 이름·설명·아이콘을 `state.shop.products`에서
찾기 때문에(`product()`·`itemIcon()`), 지우면 이미 가진 사람의 가방에 **이름 없는 칸**이
남습니다. 대신 `award` 플래그를 달아 선반에 안 오르고 `buy()`가 거절합니다. 거절 문구도
"토큰이 부족합니다"가 아니라 "파는 물건이 아닙니다"입니다 — 값을 더 모으면 살 수 있다는
거짓말을 하지 않으려고 지갑 검사보다 **먼저** 봅니다.

### 소급 달성

첫 실행에 이미 넘긴 것이 전부 열리고 보상도 들어옵니다. 따로 짠 코드가 아니라, 판정이
"델타"가 아니라 **지금 상태와 임계값의 비교**라서 저절로 그렇게 됩니다. 그리고 그 비교 방식이
`settleAchievements`를 **멱등**하게 만듭니다 — `electron:dev`에서 Vite와 Electron이 같은
`state.json`에 각자 파이프라인을 돌리는데, 안전이 "둘이 같은 바이트를 계산한다"에만 기대고
있기 때문에 이건 선택이 아니라 요구사항입니다.

**트레이너 승수만 0부터 셉니다.** 승패는 롤링 20칸 로그에만 있었고(약 100분), 재현도 안
됩니다 — `trainerBattleAt`은 그때의 기술과 폼을 받는데 그 둘이 기록돼 있지 않습니다.
화면이 그 사실을 그대로 적습니다.

### 새 필드는 `migrate`에 반드시 적습니다

`achievements` · `awardTokens` · `trainerWins` · `tmsFound` 넷은 전부 optional이라 스키마 번호를
올리지 않지만, **`server/store.ts`의 `migrate`에 이름을 적어야 합니다.** 그 함수는 spread가
아니라 **allow-list**라서, 적지 않은 필드는 다음 로드에서 버려집니다. 업적 표가 20초마다
비워지면 **매 틱마다 보상을 다시 지급**합니다. (개발 중에 실제로 봤습니다 — 새 필드를 모르는
이전 빌드가 아직 떠 있는 채로 새 코드가 상태를 쓰자, 이전 빌드가 종료하면서 넷을 전부
지웠습니다.)

`tmsFound`는 지금 든 기술머신 수를 **바닥값**으로 깔고 시작합니다. `tms`는 배우면 줄어들어
기록이 못 되기 때문인데, 이건 `retiredCount`가 `departedCount(dex)`로 바닥을 까는 것과 같은
수법입니다.

### 업적은 시스템과 함께 갑니다

**id는 영구 키이고 분야는 표현입니다.** 행은 자유롭게 다시 묶어도 되고 실제로 그렇게 했습니다 —
`raise-shiny`·`raise-fusion`은 희귀로 옮겼지만 **id는 그대로**입니다. id를 바꾸면 그걸로 달성해
둔 기록이 조용히 사라집니다.

**시스템을 더하거나 바꾸면 이 표도 같이 고칩니다.** 새 기능이 들어왔는데 업적판이 그대로면
업적판은 그 순간부터 거짓말을 시작합니다. 새 기능이 durable 카운터를 만들었으면 `ACHIEVEMENTS`에
행을 더하거나, 안 더하는 이유를 적습니다. 임계값을 바꿔도 **이미 달성한 것은 회수되지
않습니다** — `state.achievements`는 id로 키를 잡고, 이미 있는 id는 건너뜁니다.

`test/achievements.test.ts`가 기계로 지킬 수 있는 만큼을 지킵니다: 분야마다 최소 하나,
사다리는 오름차순, 상점에서 뺀 셋은 반드시 어떤 업적이 준다(이게 없으면 키스톤을 영영 못 얻는
빌드가 나갑니다), 그리고 두 번 돌려도 보상이 두 번 들어오지 않는다.

## 상점과 가방 — 프렌들리숍 카운터

지갑 = **번 토큰 − 쓴 토큰**. 성장과는 분리되어 있어 **아이템을 사도 진화가 되돌아가지 않습니다.**
가격은 부화 임계값(HT)에 비례하므로 헤비 유저든 라이트 유저든 체감이 같습니다.

**HT를 날로 읽는 법.** `hatchThreshold = 최근 7일 일평균 × 0.15`이므로 (`game.ts:675`)
**코딩 하루 = 6.67 HT**입니다. 이 환산이 없으면 `80×`가 얼마나 비싼 건지 아무도 모릅니다:
전설의 알 80 HT는 **열이틀치 코딩**이고, 흔한 알 5 HT는 **네 시간**입니다.

지갑에 들어오는 것은 딱 둘입니다 — `lifetimeEarned`와 업적 보상(`awardTokens`). **사냥과
이상한사탕은 진행도만 올리고 지갑은 건드리지 않습니다.** 그래서 수입은 6.67 HT/일에 업적
일회성 365.5 HT(≈ 55일치를 한 뭉치로)와 반복 업적 ~1.5 HT/일이 얹히는 모양입니다.

상점 탭은 **카운터**입니다. 선반 앞에 점원이 서 있고, 배틀 화면과 같은 9-slice 메시지 상자로
말을 겁니다. 나머지 화면이 전부 원작의 언어로 말하는데 상점만 설정 화면처럼 생겼던 것을 고쳤습니다.

```
┌ 선반 · 점원 · 카운터 상판 ────┐   ← CSS로 그림, 점원만 런타임 스프라이트
│                소지금 2.47B │   ← 카운터 안에 얹음
└─────────────────────────────┘
╔═════════════════════════════╗
║ 전설의 알               2.14B ║   ← 가리키면 점원이 설명한다
║ "전설"이 보장된 알. …          ║
╚═════════════════════════════╝
[전체][알][성장][진화]
 ▶ 🥚 전설의 알           2.14B     ← 한 항목에 한 줄
```

**설명은 목록 위, 움직이지 않는 자리에 있습니다.** 4·5세대 가방과 구매 화면은 DS 윗화면에
설명·소지금을 두고 아랫화면에 목록을 둡니다 — 설명은 가만히 있고 목록이 그 아래에서 움직입니다.
처음에는 반대로 만들었다가(설명을 화면 하단에 붙임) 목록 위에 얹혀 떠다니는 것처럼 보여서
원작 쪽으로 고쳤습니다. 그 김에 **설명창과 점원 대사창을 하나로 합쳤습니다**: 창 하나에 상태
넷 — 인사, 가리킨 물건, 질문, 감사 인사. 상점에서 실제로 일어나는 일이기도 합니다.

**가리키는 것은 공짜입니다.** 호버와 포커스가 설명을 띄우고(원작에서 커서를 옮기는 것과 같음),
클릭이 질문으로 넘어갑니다. 포커스도 거는 이유는 키보드로도 설명을 읽을 수 있어야 하기 때문입니다.

**창은 상태가 바뀌어도 높이가 변하지 않습니다.** 가장 큰 상태에 맞춘 고정 높이입니다 — 늘어나면
바로 아래 목록이 통째로 밀려서, 누르려던 줄이 커서 밑에서 도망갑니다.

**한 번에 사지지 않습니다.** 줄을 고르면 점원이 값을 부르고 되묻습니다 — 원작의 절차 그대로인데,
여기서는 그게 연출만이 아닙니다. **알을 사면 지금 파트너가 도감으로 떠나는데** 그동안 클릭 한 번에
경고 없이 그렇게 됐습니다. 이제 알을 고르면 파트너 이름이 확인 대사에 들어갑니다:

```
전설의 알 2.14B입니다.
지금 코코리는 도감으로 떠납니다. 괜찮으시겠습니까?   [예] [아니오]
```

구매 결과도 화면 위 토스트가 아니라 **점원의 상자**에 들어갑니다. 3초 뒤 인사로 돌아갑니다.

**점원은 Showdown의 트레이너 스프라이트**(`waitress`, 80×80, 789바이트)입니다. 여기 쓰려고
들여온 `ensureNpcSprite`를 지금은 **트레이너 배틀의 등장 컷도 같이 씁니다**. 배틀 배경·기술
이펙트와 **같은 호스트에서 런타임에 받아 캐시**하며, 다른 자산과 똑같이 **커밋하지 않습니다** —
직접 그리거나 CC0여야 한다는 규칙은 저장소에 담기는 픽셀에 대한 것입니다. 못 받아오면 점원만
없고 카운터·대사·가격은 그대로입니다(`test/ui/tabs.test.tsx`가 그걸 지킵니다).

참고로 BW의 `clerk`는 상점 점원이 아니라 **회사원 트레이너 클래스**입니다. 실제로 카운터 사람처럼
읽히는 건 `waitress`와 `waiter`뿐이라 넷을 받아 눈으로 보고 골랐습니다.

**마트 내부 배경은 받지 않고 그립니다.** Showdown에는 실내 배경이 없습니다(`bg-indoor`·
`bg-pokecenter`·`bg-building` 전부 404). 벽·선반·상판은 그라디언트 몇 줄이라 받아올 것도,
실패할 것도 없습니다. 그리고 그 밝은 카운터가 **다크 모드에서 대사 상자가 놓일 바닥**이 되어
줍니다 — 배틀 화면이 쓰는 것과 같은 해법입니다.

**한 항목에 한 줄입니다.** 원작이 그러듯 아이콘이 왼쪽, 숫자가 오른쪽입니다. 처음에는 가격을
이름 밑에 쌓아서 한 줄이 60px이었는데, 그러면 상품 열 개가 화면 대부분이었습니다.

**커서 자리는 항상 비워둡니다.** 원작이 그러듯 `▶` 칸을 상시 확보합니다. 선택할 때만 자리를
만들면 선택이 옮겨갈 때마다 모든 줄이 옆으로 흔들립니다.

**가리킨 줄은 은은한 면으로만 표시합니다.** 행 전체를 버튼으로 만들면서 `배우기`·`사용` 같은
**알약 버튼**의 채우기 스타일이 행에도 걸린 적이 있습니다 — 60×28 알약을 위해 그린 색이
400×44 행에 칠해지니 바가 물든 것처럼 보였습니다. 지금은 알약 규칙이 `:not(.rowbtn)`으로
좁혀져 있고, `test/panel-css.test.ts`가 그 형태가 돌아오지 못하게 붙잡습니다.

가방도 같은 창을 같은 자리에 씁니다 — 점원만 없습니다(원작에서도 가방은 혼자 여는 화면입니다).

그리고 **주머니로 나눕니다** — 도구 · 중요한 물건 · 기술머신 · 메가스톤. 5세대 가방이
주머니(Case) 다섯 개로 나뉘는 그 구조이고, 여기서는 그게 실제 문제를 풉니다: 기술머신 14개에
도구와 스톤까지 한 칼럼에 쌓이면 가방 하나가 화면 여섯 장이었습니다. 지금은 한 장에 들어갑니다 —
다만 **기술머신 주머니만은 그 약속을 한 번 깼다가 되찾았습니다.** 모으다 보면 한 주머니 안에서
다시 길어지기 때문인데, 거기는 쪽으로 넘깁니다(`### 기술머신` 참고).

### 빈 설명창이 지금 걸린 효과를 말합니다

설명창에는 상태가 셋 있습니다. 무언가를 가리키면 그 이름과 설명, 아무것도 안 가리켰는데
**지금 걸려 있는 효과가 있으면 그 효과**, 둘 다 아니면 `고르면 여기에 설명이 나옵니다.`입니다.

가운데 것이 이번에 생겼습니다. 그전까지 `진화 정지 중` · `다음 부화 샤이니 확률 8배` 같은 줄은
**아이템 목록 맨 아래 회색 한 줄**에 있었습니다 — 화면에서 가장 눈에 안 띄는 자리인데, 내용은
*지금 이 순간 규칙이 다르게 돌고 있다*는 사실입니다. 그동안 화면에서 가장 큰 요소(92px 창)는
누가 마우스를 올려주기를 기다리며 비어 있었습니다. 둘을 바꿨습니다.

**그 김에 버그 하나가 딸려 나갔습니다.** 옛 줄은 조각 셋에 구분자를 각각 붙여 이어서,
마지막 조각이 없으면 `다음 부화 샤이니 확률 8배 · `처럼 **가운데점으로 끝났습니다.**
`filter(Boolean).join(' · ')`이면 그 실패 방식 자체가 없습니다.

### 중요한 물건은 주머니가 따로입니다

키스톤과 다이맥스밴드는 **갖고 있는 것 자체가 효과**라 누를 것이 없습니다(바로 아래
`### 키스톤과 다이맥스밴드는 패시브다` 참고). 그런데 이상한사탕·변함없는돌과 한 목록에 있으면서
혼자 버튼 대신 `보유 중` 배지를 달고 있었습니다 — 한 목록에 성격이 두 가지였다는 뜻입니다.

원작에 이미 이름이 있어서 그대로 씁니다. 이제 **도구 주머니에는 누를 것만** 있고,
**중요한 물건 주머니에는 누를 것이 하나도 없습니다.** 가리키면 설명은 나옵니다 —
이 주머니를 여는 유일한 이유가 그것입니다.

### 자동사냥·사냥 상한은 설정 탭으로 갔습니다

둘은 **아이템이 아니라 설정**입니다. 전에는 그 사실을 인정하면서도 가방 주머니 밖 맨 아래에
뒀는데, 이 앱이 실제로 따르는 규칙은 따로 있습니다 — **컨트롤은 그 주제가 있는 곳에 둔다.**
기술 4칸이 파트너 탭에 있는 이유(`## 상태 화면`)도, 배틀 모습 토글이 설정이 아니라 파트너에
있는 이유(`### 배틀 모습 표시 토글`)도 그겁니다. 사냥의 주제는 가방이 아닙니다.

**설정 탭 맨 위에, `PetSettings` 바깥에 둡니다.** 생김새가 같아서 합치고 싶어지지만 두 줄은
`/api/shop` → `state.json`으로 가고 **웹 빌드에서도 동작**하는 반면, 데스크탑 펫 설정 여섯 줄은
`prefs.json`으로 가고 **Electron에서만** 그려집니다. 안에 넣으면 브라우저에서 통째로 사라집니다.
`server/game.ts`의 `setShowBattleForm` 주석이 왜 `huntEnabled`가 Prefs가 아니라 GameState에
사는지를 이미 적어뒀습니다 — `buildState`는 Prefs를 못 보고, 웹 빌드에는 Prefs가 없습니다.

설명을 제자리에 두는 구분은 그대로입니다: 설정은 제자리에서 설명하고, 아이템 설명은 찾아보는
것입니다. 이제 **설정은 전부 설정 탭에서** 그렇게 합니다.

상점은 **알 · 성장 · 진화** 세 선반으로 나뉘고, 위쪽 칩으로 하나만 볼 수 있습니다.
5세대 프렌들리숍이 계산대 둘로 **공통 상품과 지역 한정 상품**을 나눠 파는 것과 같은 구조입니다.
칩은 도감 필터가 이미 쓰는 언어이고, 다만 **접히지 않습니다**: 10줄뿐인데 클릭 한 번을 더
요구할 이유가 없습니다.

| 선반 | 상품 | 가격 | 하루치 | 효과 |
|---|---|---|---|---|
| 성장 | 이상한사탕 | **요구량의 0.3×** | 아래 절 | 지금 단계 진행도 +25% |
| 진화 | 변함없는돌 | 8× | 1.2일 | 진화·졸업 정지 (토글, 해제는 무료) |
| 진화 | DNA쐐기 | 35× | 5.2일 | 도감에 있는 상대와 합체 (분리는 무료) |
| 알 | 흔한 알 | 5× | 0.75일 | 보장 없음 — 그냥 새로 시작 |
| 알 | 조금 귀한 알 | 12× | 1.8일 | "조금 귀함" 이상 보장 |
| 알 | 귀한 알 | 25× | 3.7일 | "귀함" 이상 보장 |
| 알 | 전설의 알 | 80× | 12일 | "전설" 보장 |
| — | 반짝반짝부적 · 키스톤 · 다이맥스밴드 | **안 팜** | — | 업적 보상 (위 절) |

알을 사면 지금 포켓몬은 도감에 등록되고 떠납니다.

### 값이 여덟 배가 된 이유

**돈이 뜻을 잃었기 때문입니다.** 옛 값으로는 사는 물건 일곱 개를 전부 하나씩 사도 22.2 HT,
**사흘 반치**였습니다. 그런데 업적 하나만 해도 일회성 365.5 HT를 줍니다 — **상점 전체를
열여섯 번** 살 돈입니다. 실제 저장본에서 지갑에 24억(92 HT)이 잠들었고, 가방에는 아무
쓸모도 없는 변함없는돌이 열다섯 개 쌓였습니다.

새 값으로 전부 하나씩은 **165 HT ≈ 25일치**입니다. 지갑이 다시 "무엇을 살까"를 묻습니다.

**알 사다리는 원래 원칙으로 돌아갔습니다.** 이 문서가 줄곧 *"자연 확률(60/25/12/3)에 대략
반비례"*라고 적어놨는데 실제 비율은 1 : 1.9 : 3.75 : 12.5로 어긋나 있었습니다. 5 / 12 / 25 / 80은
**1 : 2.4 : 5 : 16**으로, 진짜 역수(1 : 2.4 : 5 : 20)에 훨씬 가깝습니다.

**메가스톤은 팔지 않습니다** — 사냥으로만 나옵니다. 아래 "특별 진화" 절 참고.

### 한 개만 파는 물건 — `PASSIVE`가 아니라 `UNIQUE`

키스톤·다이맥스밴드는 이제 아예 안 팔지만(업적 보상), **변함없는돌은 팔되 하나만 팝니다.**
`consumeItem`을 보면 그 돌은 **켤 때도 끌 때도 개수를 줄이지 않습니다** — 하나 가지면
영구히 토글이고 두 개째는 정확히 아무 일도 안 합니다. 1.5×일 때는 조용한 낭비였지만 8×는
하루치를 버리는 함정이라, 값을 올리는 변경이 곧 이걸 고쳐야 하는 이유가 됐습니다.

그래서 집합을 둘로 갈랐습니다. `PASSIVE`는 **가방에 누를 것이 없는** 물건이고(키스톤·
다이맥스밴드), `UNIQUE`는 **상점이 두 개째를 안 파는** 물건입니다(`PASSIVE` + 변함없는돌).
변함없는돌은 토글이라 가방 버튼이 있어야 하므로, 둘을 한 집합으로 뭉치면 그 버튼이
조용히 사라집니다. 테스트가 그 구분을 지킵니다.

이미 가지고 있으면 그 줄이 가격 대신 **보유중**을 띄우고 점원이 "이미 가지고 계십니다"라고
답합니다. 판단은 서버가 합니다(`UNIQUE` · `owns`) — 화면이 규칙을 다시 유도하면 두 벌이
되고, 그러면 상점이 `buy`가 거절할 물건을 파는 날이 옵니다. 페이로드의 `owned`도 같은
집합을 봐야 하고, 그게 이 주석이 경고하던 바로 그 어긋남입니다.

**알은 네 등급이 다 있고, 보장은 "정확히"가 아니라 "바닥"입니다.** 산 등급보다 잘 나온
굴림은 그대로 둡니다 — 귀한 알에서 전설이 나올 수 있습니다. 그래서 바닥이 `common`인
흔한 알은 아무것도 보장하지 않고, 그 사실이 곧 그 상품의 정체입니다: 등급을 사는 게 아니라
**교체를 사는** 가장 싼 방법이고, 흔한 포켓몬일수록 성장 배율이 낮아(`RARITY_MULT` 1.0)
가장 빨리 자랍니다.

가격은 자연 확률(60/25/12/3)에 대략 반비례합니다. 사다리는 `RARITY_ORDER` 하나에서 나오고
`Rarity` 유니온 자체가 그 배열에서 파생되므로, 등급을 추가하면 보장 비교가 자동으로 따라옵니다.
`test/shop.test.ts`가 "등급마다 알이 정확히 하나", "비쌀수록 바닥이 낮아지지 않음",
"어떤 알도 바닥 아래로는 절대 안 나옴"을 지킵니다.
이상한사탕이 주는 진행도는 지갑에 들어가지 않으므로 **사탕으로 사탕을 살 수는 없습니다.**

### 이상한사탕은 자기가 주는 만큼 받는다

**가격표에서 유일하게 임계값의 배수가 아닌 줄입니다.** 사탕의 효과는 처음부터
`지금 단계 요구량의 25%`였는데(`shop.ts`가 그래야 하는 이유까지 적어뒀습니다 — 고정 배수는
전설이나 늦은 단계에서 광고한 25%가 아니라 1.7%를 주게 됩니다) **값만 임계값 고정**이었습니다.
요구량은 `4×`에서 `100×`까지 움직이므로, 같은 버튼의 수익률이 이렇게 갈렸습니다:

| 언제 사느냐 | 낸 값 | 받은 진행도 | 배율 |
|---|---|---|---|
| 알 단계 | 0.4 HT | 0.25 HT | **0.6배** — 살 이유가 없음 |
| 흔함 · 1단계 | 0.4 HT | 3 HT | 7.5배 |
| 전설 · 졸업 직전 | 0.4 HT | 25 HT | **62.5배** |

62.5배짜리 버튼은 가격이 아니라 구멍입니다. 24억이면 사탕 230개, 진행도 920억 — 게임을
통째로 건너뜁니다.

그래서 **값의 기준을 효과와 같은 것으로 맞췄습니다.** `Listing.basis`가 `'requirement'`이면
`priceOf`가 임계값 대신 `currentRequirement(state)`를 씁니다:

```
값   = 0.3 × currentRequirement(state)
효과 = 0.25 × currentRequirement(state)
```

어느 상황에 사도 **0.83배**입니다 — 시간을 앞당기는 값으로 20%를 얹어 내는 것이고, 그래서
"돈을 진행도로 바꾸는 것이 최적"인 상태가 생기지 않습니다. 테스트가 *어떤 등급·어떤 단계에서도
받는 것이 낸 것보다 적다*를 전수로 지킵니다.

**표시 가격이 파트너에 따라 움직입니다.** 이건 버그가 아니라 그 물건의 정체입니다 —
페이로드가 20초마다 다시 오므로 자동으로 따라가고, 알 단계에는 `currentRequirement`가
임계값을 돌려주므로 자연스럽게 이어집니다. `priceOf`가 `hatchThreshold` 대신 `state`를
받게 된 이유가 이것 하나입니다.

## 특별 진화 — 메가진화 · 거다이맥스 · 합체

진화에 **두 번째 축**이 생겼습니다. 첫 번째 축은 `stageIndex`가 `pathIds`를 따라 걷는 것이고,
그건 1~1025 기본 종을 절대 벗어나지 않습니다. 폼은 그 옆에 나란히 놓입니다 — **그려지는 것과
불리는 것만** 바꾸고, 도감·희귀도·학습기·진화 라인이 보는 종은 그대로 둡니다.

`server/forms.ts`가 그 테이블입니다(`npm run gen:forms`로 생성, 직접 수정 금지).
**메가 100 · 거다이맥스 34 · 합체 6**, 총 140개.

| | 지속 | 조건 | 저장 |
|---|---|---|---|
| **합체** | 영구 (분리 가능) | 도감에 파트너 + DNA쐐기 | `Companion.formId` |
| **메가진화** | 배틀 한 번 | 키스톤 소지 + 그 종의 메가스톤(사냥) | 저장 안 함 |
| **거다이맥스** | 배틀 3턴 | 다이맥스밴드 소지 | 저장 안 함 |

### 키스톤과 다이맥스밴드는 패시브다

처음에는 변함없는돌을 따라 **착용 토글**로 만들었는데 그게 틀렸습니다. 변함없는돌은 실제로 껐다
켜는 물건이고, 이 둘은 그냥 **가지고 있는** 팔찌와 밴드입니다. 지금은 소지 여부가 조건 전부이고,
가방에서 누를 것이 없습니다 — 눌러도 아무 상태도 안 바뀌는 버튼이 있는 것보다, 버튼을 두지 않고
`보유 중`이라고 적는 편이 정직합니다. 개수(`×1`)도 안 붙입니다: 장신구는 스택이 아닙니다.

그래서 `GameState.keyStone`·`dynamaxBand` 두 필드가 사라졌습니다. 마이그레이션은 필요 없습니다 —
토글은 물건을 가진 사람만 켤 수 있었고 소지는 `inventory`에 남아 있습니다.

**그 대신 우선순위가 뒤집혔습니다.** 둘 다 패시브면 하나를 벗어서 다른 쪽을 고를 수 없으므로,
지는 쪽은 영영 못 보게 됩니다. 둘 다 되는 종은 실측 **4종**입니다(이상해꽃·리자몽·거북왕·팬텀).
그래서 **스톤이 있으면 메가, 없으면 거다이맥스**로 정했습니다. 거다이맥스는 한 번 사면 끝이고
메가는 **그 종의 스톤이 풀숲에서 나와야** 하니, 공들인 쪽이 이깁니다. 그 4종도 스톤을 줍기
전까지는 거다이맥스를 그대로 봅니다.

### 무엇이 모자란지 화면이 말한다

파트너 탭의 "배틀에서" 줄은 조건이 **전부** 충족됐을 때만 나타났습니다 — 도움이 될 수 있는 유일한
순간에 아무 말도 안 했다는 뜻입니다. 지금은 그 종에 폼이 있으면 항상 뜨고, 안 되는 이유를 댑니다:

```
배틀에서   메가저리더프                        ← 준비됨
배틀에서   메가저리더프 · 저리더프나이트 필요      ← 스톤이 없다
배틀에서   메가저리더프 · 키스톤 필요             ← 아이템이 없다
배틀에서   메가저리더프 · 변함없는돌을 빼면 가능    ← 막혀 있다
```

폼이 없는 종은 줄 자체가 없습니다. 천 종에 "없음"을 적는 것은 정보가 아닙니다.

### 스프라이트는 한 줄도 안 고쳤습니다

폼의 PokeAPI **pokemon id가 곧 스프라이트 id**이기 때문입니다. `ensureSprite`는 원래 아무 숫자나
받고, `id <= BW_MAX_ID ? 0 : 1`이 폼 id를 자동으로 Showdown 계층부터 시작시킵니다.
메가이상해꽃(10033)은 앞·뒤·샤이니·뒤샤이니가 전부 있고, 거다이맥스(10195)는 Showdown 뒷모습이
없지만 **기존 폴백이 정적 PNG로 떨어집니다** — 원래 하던 동작 그대로입니다.

### 전투 보정을 지어내지 않았습니다

종족값을 재보면 답이 나와 있습니다:

- **메가는 일괄 +100** (이상해꽃 525→625, 리자몽 534→634, 거북왕 530→630) → 비율 약 **1.19**.
  그래서 스윙에 `form.power`를 곱하고, 야생 조우 토큰도 같은 배수를 받습니다.
- **거다이맥스는 종족값이 base와 완전히 같습니다** (525→525). 원작에서 다이맥스는 능력치가 아니라
  **HP 2배**이므로, HP가 100점 막대로 고정된 이 앱에서는 "**3턴 동안 받는 피해 절반**"이 같은 산수입니다.
  야생 배틀은 HP 하한이 있어 질 수 없으니 이건 사실상 **트레이너전용 능력**입니다 — 원작에서도 그렇습니다.

폼 옵션은 전부 **이미 뽑힌 값에 곱하기만** 합니다. 새 난수 draw가 하나도 없고 기본값이 전부
항등원이라, 폼 없이 싸운 배틀은 이 기능이 생기기 전과 **비트 단위로 같습니다** —
`test/hunt.test.ts`의 GOLDEN 표가 그걸 증명합니다.

**도감이 종족값을 굽게 된 뒤에도 이 문단은 그대로입니다.** `server/dexdata.ts`는 도감 상세
화면만 읽고, 배틀은 여전히 기술 위력과 타입 상성만 씁니다 — `hunt.ts`·`game.ts`·`state.ts`가
그 파일을 import하면 테스트가 실패합니다. 위의 1.19가 종족값이 이 앱에서 하는 유일한 일이고,
그것도 **생성 시점에 측정된 상수**입니다.

### 메가스톤은 사냥으로 줍습니다

**만난 야생 포켓몬이 메가진화할 수 있는 종이면, 낮은 확률로 그 종의 메가스톤을 떨굽니다.**
가중치 표가 없습니다 — 희소성이 데이터에서 저절로 나옵니다. 메가는 대부분 최종진화체인데
`encounterAt`이 제곱 굴림으로 미진화체 쪽으로 기울어 있어서, **조우의 약 5%만** 메가 가능한
종입니다. 실측하면 스톤 1개당 약 82조우 = **6.8시간** 사냥입니다(`test/stone.test.ts`).

스톤은 **기술머신처럼 파트너보다 오래 삽니다**. 상한(`huntCap`) 바깥이라 진행도가 상한에
붙어도 계속 모입니다.

`stoneAt`은 **다섯 번째 솔트**를 씁니다. `encounterAt`의 스트림에 draw를 하나만 끼워도
지금까지의 모든 조우가 다시 써지기 때문입니다 — `trainerAt`이 같은 문제를 같은 방법으로 풉니다.

### 합체는 도감이 박스입니다

파트너는 한 마리뿐이라 "둘 다 가지고 있어야 한다"를 옮길 데가 없습니다. 이 앱에서 소유의 유일한
의미는 **키워봤다**이고, 그게 정확히 도감이 기록하는 것입니다. 그래서 지금 파트너가 큐레무이고
도감에 제크로무가 있으면 합체할 수 있습니다.

| base | partner | → |
|---|---|---|
| 큐레무 | 제크로무 / 레시라무 | 블랙큐레무 / 화이트큐레무 |
| 네크로즈마 | 솔가레오 / 루나아라 | 황혼의 갈기 / 새벽의 날개 |
| 버드렉스 | 블리자포스 / 레이스포스 | 백마 탄 모습 / 흑마 탄 모습 |

**파트너를 도감에서 지우지 않습니다.** 도감은 무엇을 키웠는지의 기록이고, 아이템 값을 역사에서
받아내면 그 약속이 깨집니다. 대신 분리가 무료입니다.

**울트라네크로즈마는 합체가 아니라 2단계입니다.** 먼저 솔가레오/루나아라와 합체(영구)하고,
그 다음 배틀에서 울트라버스트(일시)입니다. `Form.from`이 배열인 이유가 이것 하나이고
(`[10155, 10156]`), 이게 원작 규칙을 그대로 옮깁니다. 스톤도 없습니다 — 스톤은 그걸 쓰는 야생
포켓몬이 떨구는데 합체한 네크로즈마는 풀숲에 나오지 않고, 여기까지 온 것 자체가 이미 대가입니다.

합체하면 **타입도 폼을 따릅니다** — 배틀의 타입 상성까지. 패널에는 프시케/강철로 보이는데
싸울 때는 그냥 프시케이면 그건 타입표가 하는 거짓말입니다.

### 도감에는 base 종으로 등록되고, 카드만 떠난 모습을 보여준다

합체한 채로 졸업하면 도감 항목은 **큐레무**로 들어가고, 카드의 **그림과 이름만** 블랙큐레무가
됩니다. 등급·세대·타입 필터·수집률은 전부 base 종 기준입니다 — `generationOf`·`rarityOfSpecies`·
`preEvolutionsOf`·`dexTotal`이 하나같이 1..1025를 전제하고, 그 전제를 깨는 것이 이 설계에서
가장 비싼 일입니다. 닉네임이 "실제로 떠난 형태에만" 붙는 기존 규칙과 같은 생각입니다.

**메가·거다이맥스는 도감에 안 남습니다.** 배틀 한정이라 어디에도 저장되지 않습니다. 도감에
폼으로 남을 수 있는 것은 합체뿐입니다.

**여기 버그가 하나 있었습니다.** `record()`가 `(종, 이로치)`로만 중복을 걸러서, **평범한 큐레무를
먼저 졸업시킨 적이 있으면** 나중에 블랙큐레무로 졸업해도 이미 있다고 보고 빠져나갔습니다 —
`formId`도 닉네임도 **저장조차 안 됐습니다.** 어느 쪽을 먼저 키웠는지가 세이브에 남는 내용을
바꾸는, 가장 조용한 종류의 버그입니다. 지금은 이미 있는 항목이라도 새로 온 쪽에 정보가 더 많으면
채워 넣습니다(덮어쓰지는 않습니다 — 먼저 떠난 개체가 이름을 지킵니다).

그리고 페이로드가 그 `formId`를 **실제로 읽습니다.** 저장은 되는데 아무도 안 읽어서 카드에는
평범한 큐레무가 뜨던 기간이 있었습니다.

### 한글 이름이 없는 49종

메가 97종 중 **49종은 PokeAPI에 한글명이 없습니다**(id 10278 이상, Legends Z-A 신규).
메가스톤 아이콘도 전부 404이고, 거다이맥스는 34종 전부 한글명이 없습니다.

다만 이름 규칙이 **예외 0건으로 규칙적**입니다 — 기존 48종이 전부 `메가`+한글종명(+X/Y/Z),
메가스톤 47개가 전부 한글종명+`나이트`. 그래서 생성기가 **공식 이름이 있으면 쓰고 없으면 합성**합니다.
한 종에 메가가 둘 이상이면 수식어를 붙이는데, 그 한글도 대개 PokeAPI가 다른 폼에 이미 갖고
있습니다(`로우한 모습`, `500년 전의 색` 등 85개). 어써러셔 셋만 어디에도 없어 손으로 적었습니다.

**한글명이 겹치면 생성이 throw합니다.** 수식어를 몰라 조용히 빠뜨리는 것이 유일한 실패 방식인데,
그러면 같은 이름 두 개가 나오므로 충돌 검사 하나가 그걸 전부 잡습니다.

스프라이트는 대응이 필요 없습니다 — 97종 전부 정적 PNG가 있어서 폴백 체인이 그대로 씁니다.
신규 일부가 애니메이션 대신 정지 이미지인데, #650 이상 종에 이미 하던 것과 같은 성질입니다.

**한글 도감 설명이 없는 127종은 답이 다릅니다.** 메가 이름은 규칙이 예외 0건이라 합성할 수
있었지만, 도감 설명은 지어낼 수 없습니다. 그래서 **없는 대로 두고 화면이 상자를 안 그립니다** —
자세한 건 `## 도감`의 `### 상세 화면`에 있습니다.

### 배틀 모습 표시 토글

메가는 5분에 한 번 도는 배틀에서 10초 나타났다 사라집니다. 그런데 이 앱에서 실제로 보는 것은
**떠 있는 펫**입니다. 그래서 파트너 탭에 토글이 하나 있습니다 — 켜면 떠 있는 펫과 패널이 그
모습으로 보입니다. **순수 장식이고 규칙은 아무것도 안 읽습니다**(성격이 이미 같은 자리에 있습니다).
배틀이 정산될 때는 `battleFormOf`를 다시, 정직하게 봅니다.

### 저장 형식

`Companion.formId`, `GameState.stones` / `keyStone` / `dynamaxBand` / `showBattleForm`,
`HuntEntry.stoneId` / `form` — **전부 선택 필드라 `schemaVersion`은 4 그대로**입니다.

다만 `migrate()`는 **화이트리스트**입니다. 필드를 하나씩 적어서 새 객체를 만들기 때문에,
거기 안 적힌 것은 다음 로드에 조용히 사라집니다. 실제로 그랬습니다 — 당시 착용 토글이던 키스톤이 20초마다
스스로 벗겨지고 스톤 수집이 비워졌는데 화면에는 아무 설명이 없었습니다.
`test/shop.test.ts`가 이제 **전부 채운 세이브를 왕복시켜 필드가 하나도 안 없어지는지** 봅니다.
다음에 추가될 필드까지 잡는 모양입니다.

## 스프라이트

전부 PokeAPI 원본 자산이며, 런타임에 받아 `~/.poketokenpet/sprites/`에 캐시합니다.
받기는 8초 타임아웃이 걸려 있고 실패는 10분간 기억합니다 — 없는 스프라이트를 매 갱신마다
다시 요청하면 GitHub에 차단당하고, 타임아웃이 없으면 멈춘 연결 하나가 갱신 루프 전체를
영구 정지시킵니다.
종마다 아래 순서로 시도해 **1024종 전부 애니메이션**이 나옵니다.

```
1. sprites/pokemon/versions/generation-v/black-white/animated/{id}.gif   #1-649, 레트로 픽셀
2. sprites/pokemon/other/showdown/{id}.gif                              #650+ 포함 전 세대
3. sprites/pokemon/{id}.png                                             최후 폴백
   알   sprites/pokemon/egg.png        아이템 sprites/items/{slug}.png
   점원 play.pokemonshowdown.com/sprites/trainers/{slug}.png  → npc-{slug}.png
```

캐시는 평평한 폴더 하나라서 접두사가 이름공간입니다 — `item-` · `bg-` · `fx-` · `npc-` ·
`{id}-{kind}`. 새 종류를 더할 때는 겹치지 않는 접두사를 고르고 `cacheAsset`을 타면
타임아웃·네거티브 캐시·중복 제거·원자적 쓰기가 전부 따라옵니다.
샤이니가 없는 종은 일반 스프라이트로 떨어집니다.

**정수배로만 확대합니다** (`src/pixelScale.ts`). 원본 캔버스 크기가 43×43부터 96×96까지
제각각이라 한 크기로 강제하면 픽셀 격자가 어그러집니다. 알은 96×96 캔버스 안에 실제
그림이 **28×30뿐**이라 포켓몬(3배)보다 더 크게(4배) 확대해야 같은 크기로 보입니다.

| | 원본 | 배율 | 표시 |
|---|---|---|---|
| 알 | 96×96 | 4× | 내용 112×120 |
| 꼬렛 | 43×43 | 3× | 129×129 |
| 피카츄 | 50×46 | 3× | 150×138 |
| 잠만보 | 74×75 | 2× | 148×150 |

## 배포

### 릴리스 내는 법

태그 하나면 끝입니다. `.github/workflows/release.yml`이 mac과 Windows 러너에서
각각 빌드해 **네 개**(mac x64/arm64, win x64/arm64)를 만들고, `SHA256SUMS.txt`와
함께 **초안** Release에 붙입니다. 초안인 건 의도적입니다 — 사람이 파일 목록을 한 번
보고 publish 하라고.

```bash
npm version patch      # package.json 버전 올리고 태그 생성
git push --follow-tags
```

태그 없이 빌드만 확인하려면 Actions 탭에서 **Run workflow**(`workflow_dispatch`).
결과물은 Release 대신 실행 페이지의 artifact로 떨어집니다.

`arch`를 mac·win **양쪽 다** 명시한 것이 이 파이프라인의 핵심입니다. 안 적으면
electron-builder가 호스트 아키텍처만 만들어서, Apple Silicon에서 릴리스를 내면
Intel Mac 사용자가 받을 게 아무것도 없는 채로 조용히 성공합니다.

### 코드 서명

지금은 **서명하지 않습니다**. macOS Developer ID는 연 $99, Windows EV 인증서는 연 $300~400이고
개인용이라 값어치가 없습니다. 직접 빌드해 실행하면 Gatekeeper는 다운로드받은 파일만
격리하므로 문제없습니다.

받는 사람이 겪는 것은 문서로 대신합니다 — mac은 [docs/MACOS.md](docs/MACOS.md),
Windows는 [docs/WINDOWS.md](docs/WINDOWS.md). **macOS Sequoia(15)부터는 우클릭 → 열기가
막혔다**는 게 여기서 제일 중요한 사실입니다. 오래된 안내를 따라 우클릭을 반복하는
사람은 영영 못 엽니다. 시스템 설정 → 개인정보 보호 및 보안의 **그래도 열기**이거나
`xattr -dr com.apple.quarantine` 둘 중 하나여야 합니다.

Windows는 NSIS 설치본보다 **portable zip**이 SmartScreen 경고가 덜해서 zip만 냅니다.
